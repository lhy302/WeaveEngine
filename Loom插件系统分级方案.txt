====================================================================
Loom 插件系统分级方案 (2026-08-27 定稿, 用户拍板)
====================================================================
背景: 原插件系统 (test_plugin_loader L1, 2026-08-20) 只有"一切皆插件 +
坏插件回退官方", 插件与引擎同权无分级。本方案按用户要求重设计:
核心插件 / 普通扩展插件 / 游戏脚本 三种来源、三种处理,
并接入"编辑器层 + 播放器层"两层模型与游戏封装链路。

====================================================================
一、角色模型
====================================================================
  三类东西, 三种处理:
    1. 核心插件   —— 替换引擎核心部件 (界面/渲染/物理/输入), 全权, 人工信任闸
    2. 普通扩展插件 —— 向引擎增加功能 (脚本/按钮……), 受限环境
    3. 游戏脚本   —— 单个游戏的逻辑 (物体运动等), 进游戏包.lsc (现机制不变)

  Loom 本体两层:
    编辑器层   开发者编辑场景/调试游戏 (editor.py + Qt 界面 / 可换 GUI)
    播放器层   播放游戏 (runtime.PlayerApp, 不 import 编辑器; 脚本注入此层)
    封装 = 砍掉编辑器层, 只保留播放器层给玩家。

  单插件必须声明注入哪一层 (注入主体层), 不允许一个插件两处注入逻辑;
  唯一的跨层是"界面补充": player 插件可在编辑器侧注册操作按钮 (路 A,
  见第八节), 按钮只是逻辑的入口, 不算跨层注入。

====================================================================
二、目录结构
====================================================================
  程序目录/ (源码=Loom\ / 编译版=exe 目录)
    plugins/                    普通插件 (受限, 防投放误用)
      editor/                   只注入编辑器层 (开发者工具, 封装不带)
      player/                   只注入播放器层 (游戏刚需, 封装打包带走)
    core_plugins/               核心插件 (全权, 信任闸)
      <功能类别>/<插件>/        按可替换功能分 (render/ physics/ input/ ...,
                                 类别可扩展; 未来 GUI 新插件按本系列定义)
    plugins/README.txt          信任边界警告 (更新为新结构)
    core_plugins/README.txt     核心插件信任须知
    插件信任.json               核心插件信任记录 {id: {path, files:{sha256}, time}}
    设置.json                   gui 选择等 (不变)

  目录即声明: plugins/editor|player 子目录决定普通插件注入层;
  核心插件由 plugin.json 的 "layer": "editor"|"player" 显式声明 (缺失=报错
  拒绝加载, 防止按功能类别臆断).

====================================================================
三、普通插件 (标准) —— 受限执行环境
====================================================================
  定位: 防误用/防低级恶意 (投放式安装, 谁都能往 plugins/ 放文件),
  不是安全沙箱 —— 元编程绕道 (挖 __class__ __base__ 等) 防不住, 文档明示.

  受限环境 (加载 entry.py 时注入):
    1. 受限 builtins: 无 open / eval / exec / compile / __import__(换受限
       白名单版) / input / memoryview / help ... 保留: 纯数据与常用安全
       函数 (len/range/enumerate/zip/map/round/abs/min/max/sum/sorted/
       reversed/isinstance/issubclass/iter/next/hash/str/int/float/list/
       dict/tuple/set/bool/print) + 语言机制 (object/type/super/getattr/
       setattr/globals/locals/__build_class__/__debug__ ...).
       原则: 受限=挡"伸手抓系统" (文件/网络/进程/动态代码/原生接口),
       不砍语言机制 (否则写不出正常插件; 元编程绕道本就防不住,
       诚实档位见本节约尾).
    2. import 白名单: math / re / collections / itertools / functools /
       dataclasses / typing / random / copy / json(纯数据) + 引擎 SDK:
       scripts / engine / matlib  —— 其余一律拒绝 (os/sys/subprocess/
       socket/ctypes/threading/multiprocessing/importlib/shutil/pathlib/
       tempfile/urllib/http.client/ftplib/webbrowser/winreg/pickle 等).
    3. 文件: 全局禁; 插件自己的资源走 api.read_asset(name) (限插件目录,
       只读, 包内文件).
    4. 动态代码: 无 exec/eval/__import__ (其实 __import__ 换受限版放行
       白名单, 动态拼接名字拒绝).

  SDK 边界说明: 普通插件可 import 引擎 SDK 模块 (scripts/engine/matlib),
  引擎自身暴露的能力由其 API 负责; 受限拦的是"插件直接伸手抓系统".

  **★ 2026-08-28 修订 (渗透靶场实测, 见《Loom安全扫描报告.txt》第六章)**:
    上文 SDK 白名单 (scripts/engine/matlib) 已**废除并移出白名单** ——
    它们的命名空间真实含 os/sys/np/pygame (`import engine` 后 `engine.os.
    open` 直接写任意文件, 靶场实锤; 连"投影只暴露公开名"都救不了: 暴露
    名函数的 `__globals__` 同样泄)。现在的白名单 = 纯标准库计算/数据结构
    模块 + 入口源码 **AST 门禁** (元编程黑面属性名与 vars/globals/getattr
    等检索器调用直写拒载) + **plugin_sandbox.py** (受限 __import__ 检查
    函数之"家": 零模块 import, 加载时剥离其 __builtins__ —— 攻击者即便
    拿到 `__import__.__globals__` 也榨无可榨)。
    靶场 13 个向量 (直写 9 + 混淆 4, 含异常回溯框架面) **全部被拦**。
    诚实档位不变且更精确: **门禁档** —— 拦截"书写形态"直写与常见混淆,
    不承诺防刻意深层元编程新技巧 (解释器内无进程内可信沙箱); 真隔离方案
    = 插件子进程最小权限 + 只读 IPC API, 列为本方案 L2 设计项 (待投入)。

  生效 API: register_script / register_editor_button (见 八) / read_asset;
  其余注册点记 pending (L2+ 开放, 每个扩展点开放 前过权限评审).

====================================================================
四、核心插件 —— 信任闸 + 哈希 + 重启生效
====================================================================
  权限: 全权 (等同引擎本体), 所以安全代码更严格:
    1. 安装 = 放置到 core_plugins/ 后, 启动引擎弹信任确认框:
       红字警告: "核心插件拥有引擎全部权限, 插件来源必须可信。
       建议安装前阅读插件源码" 列出 id/name/来源目录/用途.
       用户确认 → 写 插件信任.json (全文件 SHA256) → 提示重启 →
       重启后生效. 拒绝 → 永不加载.
    2. 每次启动校验: 文件指纹与信任记录一致 → 加载; 不一致 (被改动过)
       → 拒绝加载 + 重新弹确认框.
    3. 清单校验更严: 必填 layer / capability (如 gui/render/physics/
       input) / desc 非空; 缺失任何一项 = broken.
    4. 加载失败/损坏 → 回退官方 (原隔离机制).
    5. 无头/测试环境: 未信任插件只记录不加载 (不偷偷跑).
  信任文件: 插件信任.json 原子写, 与设置.json 同机制.

====================================================================
五、GUI 体系 (保持独立) 与"GUI 插件并入核心"的定义
====================================================================
  【现有 GUI 体系 = 独立, 不改】guiloader + GUI/ 目录 + 文件后缀/头部标识
  机制 (scan_guis/load_gui/resolve_gui 回退官方) 保持原样, 仍可替换。
  LoomHub 的 HubGUI 机制同样不变 (LoomHub 不做插件化, 已拍板)。

  【"GUI 插件并入核心" = 分类归属核心插件系列 (用户 2026-08-27 再澄清)】
  今后新增 GUI 插件在**分类上划入核心插件系列**: plugin.json 按核心清单
  (capability: "gui" + layer + desc), 享受核心插件全部待遇 (全权 /
  信任确认 / 重启生效 / SHA256 校验); 但**装载机制与 GUI 组件本体保持
  独立** (guiloader 的 GUI/ 文件+头部标识+build_gui 工厂, 可整体替换) ——
  GUI 组件独立出来就是为了方便替换, 不与其它组件合体; 分类归入核心
  系列只影响"信任与权限等级", 不改变"可整体替换"的独立机制。
  (未来 GUI 插件落地时: 核心清单定义 + guiloader 承载装载, 接缝按此执行)

====================================================================
六、封装链路 (build_game / game_pack / game_player)
====================================================================
  收集: build_game 扫描 <引擎目录>/plugins/player/* + core_plugins/** 中
  layer=player 的插件 (封装智能判断 = 声明驱动: 只带播放器层).
  产出 (secure 模式): 插件包.lpc (fmt 'loom-plugins-1': 插件清单+文件字节
  +entry 源码, LOOMSC1 混淆) + 整体 SHA256 写入 游戏包.lsc config.
  发布夹: MyGame.exe + 游戏包.lsc + 插件包.lpc  三者同夹不可分离.
  玩家运行时: 启动读 .lsc (校验插件哈希) → .lpc 解密 → 内存加载插件
  (不落盘, 与 register_sources 同机制) → 再注册脚本 → 加载场景.
  缺/改任一 → 立即报错 (目前"缺游戏包"同款).

  build_game 新参数:
    --protection secure|open   默认 secure. secure=插件加密+哈希+互验.
       open=插件明文 (发布夹 plugins/player/), 允许玩家放非原版插件
       (MOD), 运行时加载该目录, 不做哈希校验.
    --no-encrypt-content      仅 open 模式下有效: 场景+脚本也不混淆
       (纯 MOD 友好; 单机游戏允许玩家随便改). secure 下强制加密.
  语义: 竞技/多人 → secure (给开挂者添堵: 混淆 + 哈希 + 互验);
  单机/MOD → open (+ 可选不混淆内容, 方便 MOD 注入). 单机允许
  玩家随便改自己游戏, 不影响别人.

====================================================================
七、玩家进程加载语义
====================================================================
  mode: editor | player (加载器全局, 入口设置):
    editor 进程 (Loom.exe 编辑器): 加载 editor+player 普通插件 (受限) +
      核心插件 (信任闸) —— 编辑器里试玩必须跑 player 插件.
    player 进程 (--run / 游戏配置双启 / MyGame.exe): 全权, 不设受限
      (secure 包内容已由开发者确认+哈希, open 则玩家自负), ~核心/普通
      玩家端无差别.
  受限只拦"开发机投放的普通插件", 这是唯一需要拦的陌生人入口.

====================================================================
八、跨层按钮 (路 A: 界面补充)
====================================================================
  player 层插件 (普通或核心) 可调 api.register_editor_button(text, cb):
    - cb 在编辑器进程调用 (受限环境回调, 与插件同环境)
    - 编辑器默认 GUI (qt_view) 工具栏「插件」菜单/区域 收集展示
    - 封装时逻辑层进游戏 (按 layer), 按钮只是开发入口, 不带
  后续扩展: register_editor_panel (L5).

====================================================================
九、与旧机制的兼容关系
====================================================================
  - plugins/ 旧平面结构 (无 editor/player 子目录) 作废, 无存量插件
    (示例插件 2026-08-21 已删), 直接切换; README 写明.
  - script 注册表 SCRIPTS 不变: 插件注册脚本与游戏包脚本同池; 插件
    卸载清理只删自己注册的 (官方/游戏包不受影响).
  - 元数据合同 (解释器.json) 不变; min_engine/beta 支持不变.
  - LoomHub 一切不变.

十、测试台账铁律 (已定档, 台账条目见《未测试功能测试方向指南.txt》
    2026-08-27 条)
====================================================================
  a. 普通插件受限: 拦 import 黑名单模块 / 无 open·exec·eval / 引擎 SDK
     放行 / 误报错不崩 / 白名单正常.
  b. 核心插件: 未信任不加载 / 确认后重启生效 / 哈希被改→拒载+重确认 /
     缺 layer→broken / 回退官方.
  c. 目录分层: editor/player 插件各进各层 / 封装只带 player 层.
  d. 跨层按钮: player 插件注册按钮出现在编辑器插件菜单 / 回调可调用.
  e. 封装: secure .lpc 加密+哈希+缺包报错 / open 明文+外插件执行 /
     --no-encrypt-content 场景明文.
  f. 现有 GUI 体系: 保持独立不动 (回归 guiloader 原测试可见); 未来核心 GUI
     插件定义 (capability gui) 走信任闸 —— 挂载结构验证, 不改现有机制.
