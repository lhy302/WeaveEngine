关键分层原则:
  * engine 不 import editor / runtime —— 保证打包版能只带 engine。
  * editor 继承 GLEngine 并覆写 render()(编辑器专属画面)。
  * runtime 继承 GLEngine, 不改渲染, 只跑场景 + 脚本 (GL 播放器)。
  * Vk 播放器不依赖 GLEngine: scene_driver (数据+步进) 与 vk_renderer (绘制)
    分离, 脚本 API 与 engine 保持同语义 (scene_driver 头注释有同步契约)。
  * physics_bridge / audio_backend 零 GL: 缺库 (culverin/game-audio) 自动禁用
    回退, 引擎其余部分行为不变。
  * fastpath 被 engine 顶层 import, numba 未装自动降级纯 Python (数值同源)。
   * scripts.py 由引擎初始化时加载注册表；内置脚本与 scripts/ 下游戏脚本均通过 @register
     登记，挂载脚本在逻辑帧中执行。
  * LoomHub 与解释器解耦: hub_config/hub_install 不 import 解释器模块;
    启动解释器靠 subprocess 调 `python Loom\Loom.py --open <场景>`.

一·补 LoomHub 项目管理器 (LoomHub\ 目录, 2026-08-11)
====================================================================
角色: Unity Hub —— 项目管理 + 项目启动 + 解释器(编辑器)多版本管理。

软件命名:
  解释器名   = Loom          (解释器默认安装根 C:\Program Files\Loom\<版本>)
  项目管理器 = LoomHub       (解释器名 + "Hub")

解释器元数据 (每个版本目录内 解释器.json):
  { name, version, python_version, main: "Loom.py", main_exe: "Loom.exe" }
  - main/main_exe 分开记录 => .py 源码 / .exe 封装 双兼容; 封装后改 exe 名
    只需更新 main_exe, LoomHub 靠它定位主程序。
  - 多版本共存: 按版本号子目录安装, 类似 Python 的 python3.x 目录。

hub_config.py (纯逻辑, 无 GUI 依赖, 可无头测试):
  - discover_interpreter(dir)  读 解释器.json 分析版本/主程序, .exe 优先判 kind
  - scan_install_root(root)    扫描 C:\Program Files\Loom 下版本子目录
  - load/save/add/set_default/remove_interpreter   配置 interpreters.json
  - load/save/add/remove_project                    配置 projects.json
  - default_python()/python_version()   系统默认 python 检测 (PATH)
  - build_launch_command(info, scene, mode) 启动命令构造:
      .py  -> [python, 主程序, --open/--run, 场景];  .exe -> [exe, --open, 场景]
  - 配置原子写 (save_json_atomic), 坏配置容错返回空。

hub_install.py:
  - install_from_zip(zip, version, root)  解压到 <root>/<version>/, 校验元数据,
      登记配置; 防 Zip Slip; 支持 zip 顶层包一层目录(自动提升).
  - RemoteDownloader.download(url, dir)  远程下载接口 (预留, NotImplementedError).

UI 模块化 (2026-08-13): 业务动作全抽到 hub_controller.py 的 HubController
  (命令层, 不 import pygame/tkinter, 可无头测试). 消息用 msg + msg_level
  ('ok'/'err'/'dim'), UI 自行映射颜色. 文件对话框用系统原生 filedialog (跨 UI).
  UI 只通过 HubController 公开 API 读写 (见 hub_controller.py 的 IHubView 契约).

LoomHub.py 主 GUI 类 = LoomHubGUI (IHubView 默认实现, 2026-08-13 改名):
  pygame 自绘 (不依赖 moderngl), 复用 Loom\filedialog.py 系统原生文件对话框.
  界面: 左=解释器面板(扫描/导入/.zip
  安装/远程[灰]/设默认/移除), 右=项目面板(新建/导入/打开/移除). 状态栏显示
  默认 python 版本并提醒. 打开项目 = 用默认解释器 --open 启动编辑器.
hub_view_tk.py (IHubView 第二实现): 极简 tkinter 视图, 同一 HubController
  跑通全部动作 —— 证明"换 UI 只换实现类、业务零改动".

启动:
  py -3.12 LoomHub.py            (pygame 视图, 默认)
  py -3.12 LoomHub.py --ui tk    (tkinter 视图)

LoomHub 空闲 CPU 优化 (2026-08-15, 用户实测单开烧 60% 单核):
  根因: ①_text 每帧对每条文字 font.render 重栅格化 (SDL_ttf, 60FPS×几十条 = 大头);
       ②default_interpreter 每帧读磁盘 interpreters.json; ③主循环每帧全量重绘。
  修 (LoomHubGUI.py + hub_controller.py):
   - _text_cache: (text,color,font)->Surface 只栅格化一次 (blit 便宜), 上限 2000 防膨胀.
   - run() 脏驱动重绘: 无事件且未强制时跳过整帧 draw+flip (启动器空闲近似 0 CPU);
     事件帧后 _force_redraw=had_event 强制再绘一帧 —— 补"绘制顺序先于动作生效"的
     侧效应 (底部按钮改列表/默认, 滚轮改 scroll, 选行改选中). _force_redraw 初始 True.
   - HubController 缓存 default_interpreter (__init__ 取, _refresh 刷), 不每帧读磁盘.
   - 设置面板 _gui_list_cache: scan_guis 开面板时扫一次目录 (每帧扫是磁盘 I/O).
  实测 (tests/_tmp/hub_cpu_probe.py + 子进程采样): 空闲 CPU 60% -> 0.0%;
  每帧事件全量重绘 ~6% (文字缓存代价). test_hub_gui 扩文字缓存/强制重绘断言.

二、数据模型 (engine.py)
====================================================================
【GameObject】场景物体 (≈ Unity 的 GameObject 合并版; 旧文档称 ModelState,
  2026-08-30 类名已正式改 GameObject —— 组件化正名, 序列化/测试全量跟进)
  - name / guid / visible            身份与可见性
  - position / rotation / scale      Point3D (欧拉角, 度转弧度存内部)
  - color / saturation               颜色与饱和度 (Material 持有时走 Material)
  - parent / children                父引用 + 子列表 (M14 层次;
                                    2026-08-16: set_parent 默认保世界挂父——换父后按新父空间
                                    换算局部位置/旋转/缩放, 世界不变; 复制/播放还原走
                                    preserve_world=False 局部原样)
  - script_id / script_vars          M27 脚本挂载 (脚本id + 参数字典)
  - scripts (list)                   M25 组件化: 多脚本组件数组 (含 script_id)
  - renderer.material                M23 材质组件: 引用材质库共享资产 (Material)
  - collider (ColliderComponent)     M28 碰撞体组件 (shape/enabled)
  - rigidbody / audio_source / animator   M31/M34/M35 组件
  - _script / _script_broken         运行时脚本实例缓存 / 坏脚本标记
  - vbo / vao / _shadow_vao / _shadow_vbo  GPU 几何资源句柄 (首次渲染/建模时构建)
  ★ 组1 缓存 (2026-08-30, 性能):
  - _bucket_key (None|tuple)         桶键惰性缓存 (GL 3元/Vk 2元键形);
                                    mesh/normal_mode/primitive/params 四 setter
                                    置脏; params 原地 mutate 不置脏 = 引擎契约外
                                    操作 (无库内用法, 注释备案)

【Material】材质资产 (M23; 组1 加缓存)

矩阵约定 (matlib.py, 行向量, OpenGL 习惯):
  - model 矩阵 = S @ R @ T   (先缩放→绕自身旋转→再平移到世界)
  - view 矩阵  = 相机逆向 (camera 位置/旋转构成的 view)
  - projection = perspective (视场角/FOV, 近远裁剪)
  - 世界坐标 = local @ model;  裁剪坐标 = world @ view @ projection
  - 顶点在 CPU 端 numpy 批量算好, 上传 GL_POINTS/GL_TRIANGLES。

坐标系: OpenGL 右手系, +Y 向上, 相机默认朝 -Z。
        (游戏物理里曾用 -Z 为上, 引擎渲染统一 +Y 为上)

着色器: _FRAG_SRC 硬编码在 engine.py (GLSL), 关键常量:
  - MAX_LIGHTS = 8
  - 无光源时 u_ambient_scale = 0.2 (压暗, 提醒手动加光)
  - gamma 校正 1/2.2 在片元末尾
  - A2 实例化 (2026-08-29): 顶点着色器 per-instance 属性 a_w0..a_w3 (世界矩阵行,
    GLSL mat4(列收) = M^T, 与旧 u_model 逐位一致) + a_sat.x (饱和度) +
    a_col (rgb + w>0.5 材质色覆盖); /i 格式串 = 整串生效尾部单 /i
  - M29 阴影: sampler2DShadow u_shadow_maps[16] 平铺 (平行光1张/点光6面),
    u_shadow_slot 每光源起始槽位, u_light_ortho 平行光 view-proj,
    u_light_mode/shape 光束截面掩码; PCF 3x3 软阴影;
    ★ 深度方案 (2026-08-12 修正后为准): 阴影贴图存**真实深度** (近=小),
    本驱动 (1050Ti) 实测做 stored>=ref 比较 (忽略 compare_func),
    传 ref = depth - bias (stored>=depth-bias <=> 片元不被挡=照亮).
    关键坑: moderngl VAO 与创建程序绑定, 阴影 pass 须用独立 _shadow_vao (positions-only);
    gl_FragDepth 须无条件写 (分支不取时值未定义 -> 全变近面).

====================================================================
五、脚本系统 (scripts.py + engine.update_scripts) (M27)
====================================================================
设计: 类 MonoBehaviour 的轻量版 —— 一个物体挂一个脚本。

注册与查表:
  SCRIPTS = {}                    id -> 类
  @register                       装饰器, cls.script_id 为注册键
  get_script(id) / script_options()

脚本基类 (Script):
  script_id / name / params       元信息; params = (key,label,默认值,min,max,fmt)
  on_start()                      进入/挂载时调用一次
  update(dt)                      每帧调用

挂载数据流:
  ModelState.script_id + script_vars   (可序列化, 在 sceneio 存成
                                        {"script":{"id","vars"}})
  update_scripts(dt) 每帧:
    - 无 script_id      -> 清实例缓存
    - 坏脚本(_script_broken) -> 跳过
    - 实例未构建         -> 查注册表建实例, 套用 script_vars,
                            调 on_start() (失败 -> broken)
    - 每帧调 update(dt)  (抛异常 -> 打印 + broken, 不崩引擎)
  _run_scripts(dt)  分发器 (2026-08-14 多核): 有 _script_runner 则交脚本专用线程
    (ScriptRunner.run_frame 同步等待, 线程绑预留大核), 否则/线程异常回退内联
    update_scripts —— 测试直调 update_scripts 行为零变化。
    同步模型线程安全: 主线程阻塞等脚本跑完才进 physics/render -> 一帧内无并发写;
    脚本实例由同一 worker 线程连续持有 (on_start/update 同线程)。

输入 (供脚本读):
  engine.is_key(name)  <->  pygame.key.get_pressed() 刷新到 script_keys
  键名用 _KEYMAP 里的名字: 'w'/'a'/'s'/'d'/'space'/'Left'/'Right'/...
  注: WASD 移动是"世界轴"移动 (相机朝向无关)。

内置脚本 (11 个，注册表当前实现；另可从 scripts/ 动态加载自定义脚本；实际由逻辑帧驱动):
  rotate          自转 (sx/sy/sz 度/秒)
  orbit           公转 (绕中心点, 半径/高度/角度在 on_start 捕获)
  bob             浮动 (y 正弦, on_start 捕获 base_y)
  wasd_move       WASD 移动 (世界轴, speed)
  camera_follow   相机跟随 (把 camera_target 设为 物体世界位置+偏移)
   first_person    第一人称移动/鼠标视角/跳跃
   third_person    第三人称移动/鼠标视角/角色朝向
   jump            刚体跳跃
  fall            重力落地 (g 重力加速度; 每帧 move_with_collision 向下移,
                  被挡停 = 落地)
  bounce          弹跳 (g 重力 + rest 弹性 0~1; 触地且速度向下 -> 反转速度)
  count_touch     触碰计数彩球 + RuntimeUI 教学示例

====================================================================
五·补 物理碰撞 (M28) —— engine.py 纯数学, 不碰 GPU
====================================================================
设计: AABB 级"够用"物理 —— 不是刚体系统, 是"碰撞查询 + 推出"。
  - 碰撞体自动派生: 球体网格 -> sphere, 其他 -> box (平面 -> box 零厚度)。
  - 同一棵父子树的物体之间永不碰撞 (防止零件互撞/自撞)。
  - 用"严格 <"判定相交: 恰好贴边不算碰撞, 静止物体不会被反复推。

数据结构 (engine.py):
  ColliderComponent(Component): ctype='collider',
    shape = 'box'|'sphere'|'none', enabled = bool
  GameObject.collider             每个物体必有一个 (add_model 时自动派生)

关键方法 (全部在 GLEngine 上, 世界空间):
  collider_bounds(m, M=None) -> ('box',(mn,mx)) | ('sphere',(center,r))
    盒 = AABB; 球 = AABB 中心 + 最大半长 (对球体网格正好=真实半径)。
    M 可选: 传入批量世界矩阵避免重算 (多核优化)。
  _pair_overlap(ba,bb) 静态纯几何相交: 盒-盒 严格< / 球-球 距<和 / 盒-球
    球心到盒最近点距离<半径 (球在盒内也算)。
  _pair_overlap_vec(ai,bj,bmn,bmx,scn,rad,kind)  向量化版 (多核 2026-08-14):
    一次 numpy 算 K 对相交, 与 _pair_overlap 逐位等价 (test_parallel 随机等价回归)。
  _related(a,b)   a/b 是否同树 (祖先/后代/同一对象) -> 是则不算碰撞。
  collider_hit(a,b)   单对判定 (同树/禁用/none 一律 False)。
  get_collisions(m)   查询 m 当前和谁相交 (脚本里拿它做"碰到就..."事件)。
  _push_out(a,b)      把 a 推出 b (只改 a.position):
    盒-盒走"最小穿透轴"(每轴算把 a 沿 +/- 推到刚分开的最小位移, 取最小;
    相等朝远离对方中心) —— 这样零厚度平面也能得到真实穿透量, 且滑墙自然。
    含球沿两中心连线推出 (need = ra+rb-距离)。
  resolve_collisions(m, max_iter=4)   迭代把 m 推干净, 返回是否被挡。
  move_with_collision(m, dx,dy,dz)    带碰撞的位移, 返回是否被挡:
    ★ 子步防穿透: 把位移拆成 <= 碰撞体特征尺寸 (盒=最小半边长, 球=半径,
      下限 0.02) 的 N 步, 每步移动 + resolve —— 大位移不会跳过薄地面。
    脚本里禁止直接改 position 做"带碰撞"移动 —— 那是瞬移, 会穿透。

多核碰撞并行 (2026-08-14, _COLLISION_PAR_THRESHOLD=32 模型数以下走内联零线程开销):
  _update_collision_events(dt)  有池且 >=阈值 -> _collision_events_parallel, 否则内联
  _collision_events_parallel    一次算全部碰撞对 -> 建邻接集 -> 串行派发 start/end 事件
                                (事件改脚本状态必须串行; current 集与内联逐位一致)
  _collision_pairs_parallel     只读检测: 候选对过滤(enabled/shape≠none/非同树/i<j) ->
                                碰撞体数组(用 compute_world_matrices 现算) ->
                                np.array_split 切 chunk -> 线程池 map 向量化判定 -> 合并
  _ensure_collision_pool        ThreadPoolExecutor(initializer= 设 pool_mask 亲和, Py3.9+)
  ★ 碰撞体数组必须"现算当帧矩阵", 不能复用 self._frame_world (它在渲染前算、事件在
    update_physics 内部跑, 物理已移动物体 -> 复用会用到过期位形)。内联 get_bounding_box
    每帧现算, 二者必须一致 (test_parallel 含物体移动后等价回归)。

序列化: sceneio v6 每个对象加 "collider": {"shape", "enabled"};
  旧场景 (v5) 无该字段 -> 加载时按网格类型自动派生, 无需迁移改写。
撤销: snapshot 含 'collider' -> 检查器切换碰撞体可 Ctrl+Z 撤销。

====================================================================
十一、踩过的坑 (重要, 改代码前必读)
====================================================================
□ 矩阵顺序: model = S @ R @ T, 写成 T@R@S 会让物体绕世界原点而非
  自身中心旋转 (旋转"绕自身"bug 的根源)。
□ 行向量 vs 列向量: matlib 是行向量(向量在矩阵左边, v @ M), 别混入
  列向量写法的 M * v。
□ gamma: 片元末尾 pow(col, 1/2.2), 测试断言亮度要按 gamma 后取值。
□ 饱和度: 在 shader 里做 (顶点色 -> 灰阶混合), 别在 CPU 端改色。
□ 光源实体: 加光源不要加进 self.models —— 那会变成可见网格、被拾取。
  光源单独 lights 列表, 单独 uniform 上传 (定长 numpy 数组整块写)。
□ 播放模式: 退出播放必须恢复 物体+光源+父链+顺序, 少恢复一样下次
  播放就会叠加脏状态。脚本实例(_script)必须清空, 否则复跑 on_start
  不会重新执行。
□ update_scripts 容错: 单个坏脚本抛异常不能崩掉整帧, 标记 broken
  并打印, 同帧其他脚本继续。
□ scripts.py 懒加载: engine 内 `from scripts import get_script` 放在
  方法内部, 避免无脚本场景也 import 脚本模块。
□ 碰撞用"严格 <"判相交: 恰好贴边(touching)不算碰撞 —— 这是"静止后
  不再被推"的正确行为, 别改成 <=。
□ 碰撞必须走 move_with_collision / resolve_collisions: 直接改 position
  是瞬移, 会穿透薄物体。move_with_collision 内部有子步拆分防穿透
  (盒=最小半边长/球=半径), 大位移也不会跳过薄地面。
□ 同树物体不互相碰撞: _related 排除祖先/后代 —— 挂到同一父物体下的
  零件互相重叠也不会被推开。想互撞就把它们挂到不同的根。
□ 球体碰撞体取 AABB 中心+最大半长: 对球体网格正好=真实半径; 但
  collider.shape='sphere' 的盒形网格(立方体改球形碰撞体)只是近似, 别
  拿它当精确盒-盒用。
□ undo 快照含脚本/collider/material 字段: 改了而不进快照, 撤销会丢。
□ GUI 无保留状态: 拖拽值中途不能依赖控件"记住" —— 用 _insp_undo_start
  模式(开始记快照, 结束时压命令)提交给撤销。
□ 资源面板扫描用 os.listdir 列文件名 (惰性加载 JSON): 逐帧读文件又慢又抖。
□ 资源面板拖放照搬层级拖拽模式 (按下武装 _res_drag / 松开解析), 但材质
  拖放分支不需要 _mouse_to_ground —— gpos 只在 mesh/prefab 分支算 (无头测试
  桩没有 width/height)。
□ 材质资产"再存=覆盖更新"靠 _asset_file_by_guid 按 guid 找同文件; 无匹配
  才 unique_default_name 新建, 绝不覆盖陌生文件。
□ 资源面板与层级面板的点击归属: 两个面板 rect 不重叠, 各自 _register 按下
  已设 click_captured, 互不误触发。
□ Windows 路径: 测试用完整路径 `py -3.12 "...\tests\test_xxx.py"`,
  PowerShell cwd 默认在 D:\my-project, 相对路径会解析到错误目录。
□ .bat 文件必须 CRLF 换行 (LF 会让 cmd 解析错乱)。

(多核/无限网格, 2026-08-14)
□ 无限网格别用"视锥足迹"定范围/做 step 分级 (2026-08-14 两轮返工): ①足迹按相机俯仰
  变化 -> 抬头时足迹退化兜底网格消失; ②足迹定范围+step 分级 -> 抬头/缩放时间距肉眼可见
  变化 (1→2→5→10)。正确 = 相机 XZ 为中心 (吸附整数格) + **恒定 step=1** + 范围只随
  相机距离 + 远处淡出盖住边界。网格环绕相机, 前方一半在视野内, 抬头 (相机绕到目标下方
  eye.y<0) 网格在头顶照常渲染, 无需任何射线求交。
□ CPU set 亲和位 = LogicalProcessorIndex, 不是 Id: GetSystemCpuSetInformation 的
  Id 是 CPU set 标识 (本机实测 256+), 直接当掩码位会得到 0 或错位; 用组内
  LogicalProcessorIndex。Group!=0 (>=64 核多组) 掩码表达不了 -> 放弃绑定。
□ E 核判定 = EfficiencyClass 高于全场最小 (数据驱动): 不能硬编码 ">0" (P 核
  EfficiencyClass 可能不是 0), 也不能看 AllFlags (那只是 Parked/Allocated 位)。
□ 防锁死铁律: 亲和掩码永不空、至少留 1 个大核给主线程 (混合: min(script_cores,
  len(P)-1)); 任一逻辑核 id>=64 -> mask 归 0 整体放弃绑定。
□ 脚本线程 affinity 必须在**线程函数体内**调 pin_current_thread (线程亲和是线程
  局部的), 不能在创建线程的线程里调。
□ ScriptRunner._done.set() 必须放 finally: 脚本抛不抛异常都要唤醒主线程, 否则
  一帧脚本炸了整帧卡死。
□ 碰撞事件检测必须"现算当帧矩阵": _collision_pairs_parallel 内部
  compute_world_matrices(models) 现算, 不能复用 self._frame_world (它在渲染前算、
  事件在 update_physics 内部跑, 物理已移动物体 -> 复用会用到过期位形)。
□ 矩阵批量 compute_world_matrices 与逐模型 model_world_matrix 必须数值等价 (含父链),
  改旋转顺序/矩阵布局前先跑 test_parallel 等价回归。
□ _upload_lights 缓冲复用后, 每帧开头必须把 slots 清零成 -1 再填 (不复位会残留
  上一帧槽位); sampler_units 也须整表复位。
□ moderngl scope enable_only 位或有效 (DEPTH_TEST | BLEND), 元组写法报错
  "invalid enable_flags"。
□ 测试环境变量 LOOM_NO_PARALLEL=1 守卫: 不加的话集成测试会建脚本线程/设进程亲和,
  影响确定性与子进程调度。

(异步GUI, 2026-08-15)
□ 不能多线程 GL (上下文非线程安全) —— "异步GUI"= 离屏 FBO 合成, 不是开线程。
□ 输入正确性铁律: pressed/released 每帧清空 (engine._handle_events), GUI _register
  会消费 —— 任何离散事件(按键/点击/滚轮/resize)必须**当帧**跑面板 pass, 否则丢输入。
  判定 need = gui_dirty or had_input or _gui_fbo is None or 心跳;
  had_input=bool(ctl.pressed or ctl.released or ctl.mouse_wheel) 兜底测试直改字段。
□ MOUSEMOTION 仅无按键按下才置脏 (not any(pygame.mouse.get_pressed()))——轨道/拖动期
  不置脏 GUI 保持省钱; 空闲悬停仍更新。
□ gui.active_id/_focus 拖动每帧重渲: 顶部 draw 检查置脏 (gui.py 拖拽代码只能在自己
  pass 里跑、无法调度下一帧, 这是唯一正确挂点)。
□ had_input 后保持 gui_dirty 再渲一帧: 反映点击后的状态翻转(设置面板/播放切换/高亮)。
□ moderngl 5.12: ctx.scope(framebuffer=None) 绑屏幕非当前 FBO, 处处显式传 FBO。
□ GUI FBO 必须 = engine.width/height (scissor y-flip 用 engine.height), 渲前
  fbo.clear(0,0,0,0) 透明底(面板不透明、视口透出场景); 尺寸驱动重建覆盖 resize/F11。

[多核并行优化] (parallel.py + engine.py, 2026-08-14; 详见记忆 parallel-cpu-affinity-multicore)
  parallel.py (零依赖 ctypes, 重点 Intel 12 代+ P/E 大小核调度):
    - GetSystemCpuSetInformation 真实结构体 (本机 SDK 10.0.22621.0 核对): _CPU_SET 24
      字节 / _SYSTEM_CPU_SET_INFORMATION 32 字节。★逻辑核号 = LogicalProcessorIndex

      EfficiencyClass > 全场最小 (Intel 12代 P=0/E=1), 数据驱动不靠厂商字符串。

      均质(AMD/Xeon) -> 进程全核、n>=8 才预留最高 2 逻辑核; 任一 id>=64 -> 放弃绑定。

    - apply_process_policy / pin_current_thread (SetProcessAffinityMask /

    - ScriptRunner: 脚本专用线程, 同步模型 (run_frame: submit -> Event.wait(释放 GIL)

[8核并行流水线] (parallel.py + engine.py, 2026-08-15; 详见记忆 loom-multicore-optimization-direction)
  CPython GIL 现实: 纯 Python 线程串行, 真并行只在释放 GIL 的 numpy/GL 调用.
    所以"8 核均摊"的落点 = 把每帧 numpy 重活分块丢预计算池; 脚本留专用线程(1 核);
    GL/事件留主线程; 物理步进/事件派发等纯 Python 属"拆不动的任务", 允许个别核偏高.
  parallel.py:
    - FramePool(n_workers, mask): 每帧预计算线程池 (ThreadPoolExecutor + initializer 绑
      pool_mask). run_parallel(jobs) 并行执行独立任务; map_indexed(n_items, func,
      batches_per_thread) 把下标空间分块并行 (executor.map chunksize=1 = 工作窃取),
      结果按序拼接 (确定性). frame_workers(policy, target=8) = min(8, 逻辑核-脚本核-主).
  engine.py:
    - self._frame_pool 预计算池 (8 worker 目标); _stop_parallel 关闭。
     - M3 另有 scheduler.NgilPool 常驻 nogil 分块池；它与 FramePool 是两套不同机制。
    - get_bounding_box: 顶点->齐次数组按 id(mesh) 缓存 (_bb_cache, _homogeneous_vertices,
      网格不可变; 高面数球省每帧重复 asarray) + 只算 3 列 vh@M[:,:3] + 转置连续归约
      (ascontiguousarray((vh@M[:,:3]).T).min/max(axis=1), 微基准比 strided axis=0 快 4 倍).
    - _model_aabbs_par(models, fw, visible_only=True): 模型世界 AABB, 模型数>=
      _AABB_POOL_THRESHOLD(64) 才池上分块 (实测 51 模型池 5.4ms > 串行 2.3ms, 池开销>收益),
      结果与逐模型一致; visible_only=False 返回全量对齐 (阴影与碰撞共享那份).
    - _scene_light_bounds_par(view, aabbs): 全部 AABB 8 角拼 (n*8,4) 一次批量 matmul.
    - _compute_light_vps(aabbs=None): 每帧一次算全部阴影光源 view-proj 缓存 self._light_vps,
      _render_shadow_maps 与 _upload_lights 复用 (旧代码每帧对同一光源算两遍包围盒);
      传入全量 aabbs 时过滤可见再算平行光包围.
    - _collision_pairs_parallel: 碰撞对 < _COLLISION_POOL_PAIRS(10万) 单次向量化
      _pair_overlap_vec (实测线程池分块比单次慢 300 倍), 超大才分块.
    - **阴影与碰撞共享一次全量 AABB** (2026-08-15): `_parallel_shadow_and_collision`
      用 `_model_aabbs_par(visible_only=False)` 一次算好全部模型包围盒 (池上分块并行),
      阴影 `_compute_light_vps(aabbs)` 过滤可见, 碰撞 `_collision_pairs_parallel(aabbs)`
      从 AABB 派生碰撞体数据 (`_collider_from_aabb`) —— 消除"阴影+碰撞各算一遍包围盒"
      的重复顶点变换 (50 高面数球曾 ~7ms 重复). `_collision_pairs_parallel` 加
      **根-根对 `_related` 快路径** (双方 parent=None 恒不相关, 直接加入候选对, 免祖先
      遍历). 真实循环复测: 播放 72.6 -> 110.7 FPS (不再下跌).
    - _collision_events_inline (小场景<32): **每物体只算一次碰撞体包围盒** (传当帧
      _frame_world), 逐对用缓存走纯几何 _pair_overlap —— 播放期碰撞事件曾 53ms/帧
      (逐对重算 model_world_matrix + 变换全部顶点), 修后 19->342FPS. collider_hit/
      get_collisions 加可选 fw 矩阵 (默认 None=旧行为).
    - _parallel_shadow_and_collision(dt, with_events): 阴影 VP(只读) ‖ 碰撞检测(只读)
      池上并行重叠 (独立任务并行), 事件派发 _dispatch_collision_events 回主线程串行;
      update_physics(dt, events=) 加参数 (渲染路径 events=False, 直调默认 True 不变).
    - 压测: tests/_tmp/stress_scene.py (50 高面数球 36x54) + real_loop_probe.py
      (真实运行循环 编辑/播放 FPS + 阶段耗时; vsync-off 不限帧用 stress_probe.py).
      **最终实测 (真实循环, 压测50球): 编辑 109.6 / 播放 110.7 FPS, 播放不再下跌
      (修前 72.6); 50 高面数球场景主线程 ~9ms/帧 (GL+GUI+阴影AABB, 接近 120 上限).**
    - LOOM_PROFILE=1: render 内 _profile(name, fn) 累计 self._stage_times (诊断用).

[主线程核心调度] (parallel.py, 2026-08-15)
  问题: 重负载主线程 (GL/事件/调度) 随机落核, 常撞上系统静态负载最高的核 (如 CPU1) ->
  单核瓶颈. 修: 启动时测每核 busy%, 把主线程锁到**负载最低的大核 (P核)**.
  - measure_core_busy(count, window=0.15): NtQuerySystemInformation
    (SystemProcessorPerformanceInformation=8) 两次采样算每核 busy% = (kernel+user-idle)/
    (kernel+user), 系统级含其他进程; _SPPI 结构 x64 48 字节. 单组系统 (<=64 核) SPPI
    下标 = 亲和位; 多组系统不映射 (安全跳过).
  - MainThreadCoreScheduler(topology, interval=20, margin=15, window=0.15,
    exclude_bits, busy_probe, disable_pin): 启动同步 _rebalance 选 P 核中 busy 最低者
    SetThreadAffinityMask 锁主线程 (threading.get_ident 记主线程 tid, OpenThread
    SET|QUERY 权限改亲和). EfficiencyClass 判 P/E, E 核绝不选 (12 代+ 大小核); exclude_bits
    排除脚本预留核. disable_pin 测试模式 (只算不绑).
  - **interval**: >0 启 watchdog 每 interval 秒重测, 当前核差最佳 < margin(15%) 不迁移
    (防抖), >= margin 迁移; **interval=0 只启动锁一次, 不周期重选**.
  - 接入差异: **Loom (engine.GLEngine.__init__, 排除 script_mask) interval=0 —— 引擎负载
    高, 周期跳核=周期性卡顿, 只锁一次保稳定; LoomHub (LoomHubGUI.__init__) interval=20 ——
    本身负载低, 周期重选不受影响**. 均打印锁定核号.
  - 探针: tests/_tmp/main_core_probe.py (打印各 P 核负载排序 + 真锁核验证).

十四、插件加载器 (L1, 2026-08-20; 承接《Loom模块化插件化分析.txt》五/八节)
====================================================================
设计: "一切皆插件" —— 核心部件 = 官方实现全内置, 插件 = 外部挂载替换/扩展;
  坏插件自动回退官方 (同 guiloader 机制: 扫描验明正身 → 加载失败禁用 → 其余照常)。
  管理 (2026-08-20): 设置对话框"插件"挂载区 —— 每插件行状态 (●已加载/○未加载/
  ×有问题+原因) + [加载][卸载] 两按钮 (卸载=会话禁用 _DISABLED, 重启恢复;
  加载=取消禁用重新加载) + [重新扫描] (差量: 新增加载/已删目录清理卸载, 不动

[插件目录结构]  <程序目录>\plugins\<任意目录名>\
    plugin.json   {"id","name","version","entry","min_engine"?, "deps"?}
      id = 反向域名风格 (^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$), version = x.y.z,
      entry = 仅合法 .py 文件名 (防路径穿越), min_engine = x.y (超当前跳过)
    entry.py     模块级 def register(api): ... (必需钩子, 缺失/抛异常 → 插件禁用)
  <程序目录>: 源码 = plugin_loader.py 所在目录 (不随 cwd, 2026-08-20 修: 曾用
    sys.argv[0] 目录, 从别的目录启动 Loom.py 会找错) / 编译版 = exe 目录 (sys.frozen)。
  当前引擎版本 CURRENT_VERSION = '1.0.0' (与 解释器.json version 同步)。

[加载流程]  plugin_loader.load_plugins(base=None)  (入口 Loom.py / build_entry.py
  启动时调用; base 仅供测试覆盖):
    _parse_manifest (清单 JSON/必填字段/格式/入口存在/min_engine)
    → _load_one (importlib 动态 import entry.py, 模块名 loom_plugin_<id 消毒>,
      调 register(api)) → 成功记 _LOADED, 失败记 broken + 打印, 不中断其余。

[PluginAPI 注册表]  register(kind, item) 通用入口:
    kind='script' → register_script(cls) → scripts.SCRIPTS[sid]=cls (检查器可挂);
    其余扩展点 (menu/panel/importer/shader/postprocess/inspector/tool) → 记
    api.pending, L2+ 开放 (调用不崩, 插件照常加载)。
  约束: register_script 的类必须 script_id 非空字符串, 否则抛 ValueError →
    该插件 broken (坏插件回退语义)。

[测试]  tests/test_plugin_loader.py (临时 base 目录, 全无头):
  合法加载进 SCRIPTS / 坏清单各形态 / 坏入口各形态 / 重复 id / min_engine /

十四·A、插件 L1 分级重设计 (2026-08-27; 详见《Loom插件系统分级方案.txt》)
====================================================================
用户方向: 核心插件与普通插件不同权 —— 普通插件限制危险权限; 替换核心 = 重启
安装 + 信任提醒 (未来 L2-L6 扩展点注册表); 只改插件挂载结构, 引擎本体零改动
(engine/editor/sceneio 未动)。现有 GUI 体系保持独立 (guiloader 不动)。

[目录分层]  <程序目录>\plugins\{editor,player}\<插件> (普通插件 = 目录即声明注入层)
       <程序目录>\core_plugins\<类别>\<插件>    (核心插件)
  core_plugins 清单必填: layer(core 不得写 editor/player)/capability/desc;
  信任闸三分: untrusted(未在信任表)/modified(文件被改)/trusted ——
  _confirm_core_trust 全文件 SHA256 写入 插件信任.json (atomic);
  未信任/被改 = 不加载记 untrusted → UI 弹窗红字警告 (全权限/来源可信/先读源码,
