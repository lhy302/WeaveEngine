二、扫描结果总览
- High: 0     Medium: 0     Low: 52
- 52 个 Low 全部高置信度, 构成:
  * B110/B112 try/except/pass|continue (~47 处): 防御性容错 (GL 资源释放/
    窗口操作/音频/可选功能失败不崩), 属设计选择, 非漏洞。
  * B101 assert_used (5 处, 全在 mesh.py): -O 优化编译下 assert 会被移除。
    已加 #nosec B101 注释说明 (开发期一致性校验, Loom 运行/打包不启用 -O)。

三、攻击面逐项分析 (手动审查)
| 攻击面 | 结论 |
|---|---|
| subprocess (hub_config:266 / hub_controller:245) | 安全: 全部列表参数, 无 shell=True, 无字符串拼接注入 |
| .zip 解释器安装 (hub_install) | 安全: _safe_extract 防 Zip Slip (normpath+前缀校验), 有测试覆盖 (H03) |
| .obj/.mtl 导入路径 (mesh.py load_obj) | 安全: mtllib 引用路径用 os.path.basename 取基名再拼同目录, 防目录穿越 |
| 场景文件 (sceneio) | json.load 无代码执行; 加密场景是"压缩+XOR+base64"混淆 (M38), 防篡改门槛非密码学安全, 已文档化 |

【实测结果: 修复后 13/13 向量全部被拦截】
  v01 直接 open()                          -> 拦 (受限 builtins 无 open)
  v02 受限 builtins 检索 open/eval/exec    -> 拦 (确认全部移除)
  v03 import 黑名单/拼接名/变体参数         -> 拦 (受限 __import__ 只认白名单)

【残余边界 (诚实档位, 写进文档而非假装堵死)】
  - 当前防护 = "门禁"档: 拦截全部直写/常见混淆形态 (上述 13 向量);
  - AST 是静态检查, 刻意深层混淆 (动态合成属性名、更冷门的对象图路径) 在
    理论上仍可构造绕过 —— Python 解释器内**不存在**可信的进程内沙箱

  - 判定 (用户规则): 靶场渗透路径全部失败 → 本漏洞面按"不生效"记录;
