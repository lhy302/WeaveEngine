## 1 一句话结论

之前所有「VK 一致」的结论都建立在**离屏渲染**上（`test_ab_gl_vk` 用 `rgba8unorm` 离屏纹理）。
一旦换成**真窗口**（本机 NVIDIA GTX 1050 Ti，交换链格式 `bgra8unorm`），VK 播放器**直接崩**。
实机点验一共抓到 3 个缺陷，其中 2 个是「真机必崩」，第 3 个是「按 F11 没反应」。

## 2 抓到的缺陷与处置

| # | 缺陷 | 证据 | 处置 |
|---|---|---|---|
| **A** | **SCREEN 目标格式写死 `rgba8unorm`**，与真窗口交换链 `bgra8unorm` 不符 → wgpu 校验失败，渲染循环异常退出 | `GPUValidationError: Render pipeline targets are incompatible with render pass ... RenderPass [Bgra8Unorm] vs RenderPipeline [Rgba8Unorm]` | ✅ **已修**：`loom_pass.frame_plan(screen_format=...)` 参数化，VK 传 `self.format`（真实表面格式）；GL 默认值不变 → GL 零改动 |
| **B** | **`_tps_sample` 用 `deque.pop(0)`**（deque.pop 不接受参数）→ 窗口跑满 2 秒后抛 `TypeError`，整个渲染循环被打挂 | `TypeError: deque.pop() takes no arguments (1 given)`（`engine_core.py:624`） | ✅ **已修**：deque 用 `popleft`、list 用 `pop(0)` 双兼容 |
| **C** | **`host_key_forward` 先喂 UI 再进内核** → 引擎键（F9/F10/F11）在到达内核前被 UI 吞掉 | 真窗口按 F9 无反应；把 `host_key_forward` 直接调（ui=None）则暂停生效 | ❌ **已回退（经审核证伪：UI 机制上吞不到 F9/F10/F11，详见更正横幅）** |
| **D** | **F11 全屏在 VK 上不存在**：`allow_fullscreen` 属性缺失 → 内核第①步直接跳过，按键被静默忽略 | 真窗口按 F11：`glfw.get_window_monitor` 前后都是 True（无变化），`allow_fullscreen='<缺失>'` | ❌ **未修**（见 §5） |

## 4 探针自身踩的 4 个坑（留痕，免得下一个人重踩）

| 坑 | 现象 | 原因 |
|---|---|---|
| 1 | 注入的键完全没反应 | `vk_player` 模块级没有 `_GLFW_TO_PG`（它在函数里 `from loom_glfw_window import`），映射取到空 dict |
| 2 | 抓到的是 rendercanvas 的回调而不是 vk_player 的 | `set_key_callback` 被注册 3 次；应改捕获 `_chain_callback` 的 `our_cb` |
| 3 | 探针跑到一半就没有后续结果 | 序列要 6 秒，但 `frames_n=560` 只有 2.1 秒就退出了 → 改成 `frames_n=3000` |
| 4 | Tab 解锁测不出来 | `press+release` 同一帧发出，而解锁键是**帧首轮询采样**，边沿被吃掉 → 改成「按住 0.35 秒再松」 |

## 5 未修 / 未核

| 项 | 状态 | 理由 |
|---|---|---|
| **F11 全屏（缺陷 D）** | **未修，登记待裁决** | VK 的窗口由 rendercanvas 管理，切换 monitor 会重建 surface/交换链，风险高（可能把刚修好的 VK 播放器再次打挂）。需要单独立项：`EngineCore.allow_fullscreen` 默认值 + VK 侧 `_toggle_fullscreen` 的窗口实现 + 回归 |
| 真机手按键盘（OS `SendInput`） | **未核** | 本次是「直接调真窗口已注册的回调」，等价于 OS 送来该键；OS 级焦点/输入法链路未验 |
| 打包游戏（`game_player`）真窗口 | **未核** | 只验了 `vk_player`；打包产物同一套渲染器，但启动链不同 |
| 长时间稳定性（>10 分钟） | **未核** | 本次 290 帧 / ~11 秒 |

## 6 顺手发现的**性能门禁假红**

`run_all` 里 `test_aabb_simd.py` 报 `性能门禁: 入口级 AVX2 <= 0.90x 标量 ratio=0.92` 失败，
但**单独连跑 3 次全过、ratio 稳定 0.80**。原因是我刚跑完 3000 帧 Vulkan 渲染，机器还在负载上。

**这是门的缺陷，不是代码回归**：性能门禁没有「先让机器静下来 / 取 N 次中位数」的机制，
负载下必然假红。建议（未做）：性能门禁改为「预热 + 取 5 次中位数 + 与同机基线比」。
