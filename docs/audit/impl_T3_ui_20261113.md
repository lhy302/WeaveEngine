## 1. GL 侧的 UI 着色器是什么、在哪（任务强制项）

`loom_ui` 元素树 + `loom_render.py:369-390` 的 `TRIANGLE_STRIP` 只是**绘制/三角化**；
真正的 GLSL 程序在 `Loom/loom_shaders.py`，一共**两对**（对应 VK 的两块手写 WGSL）：

| GL 程序 | HEAD 位置 | 谁编译 / 谁用 | 与 VK 的对应 |
|---|---|---|---|
| **屏幕 HUD** `_HUD_VERT` / `_HUD_FRAG` | `loom_shaders.py:20-38` | `engine.py:313` `hud_prog`；绘制入口 `loom_hud.py:108 draw_text_quad` / `:214 draw_screen_rect` / `:233 blit_texture` | `vk_ui.py` 的 `_UI_WGSL`（31 行，屏幕 UI 管线） |
| **World Space UI** `_WORLD_UI_VERT` / `_WORLD_UI_FRAG` | `loom_shaders.py:43-59` | `loom_render.py:258-273` 建 `_world_ui_prog`；`loom_render.py:369-390` 画 TRIANGLE_STRIP | `vk_ui.py` 的 `_WORLD_UI_WGSL`（24 行，world Canvas 管线） |

**结论：GL 有对应物，而且是两对**（不是「UI 由别的程序代画」）。因此做**真统一**：
两对 GL 程序都改为读同一份 `Loom/shaders/ui.vert` + `ui.frag`。

## 2. 单源设计（一条 pair 服务两条 UI 管线）

任务点名的 `ui.vert` + `ui.frag` 同时服务「屏幕 UI」与「world Canvas」两条管线，
差异全部由 compat 宏 + 一个模式位吸收（不写第二份源）：

* **模式位**：VK 走 `UIC.ui_screen.z`（`>0.5` = world）；GL 走显式 `uniform int u_mode`
  （`_world_ui_prog` 创建时置 1，HUD program 保持默认 0）。
* **VK 顶点布局统一 36B**：`pos3 + uv2 + color4`（屏幕 UI 的 z 恒 0、world 的 color 恒白），
  两条管线共用同一对 shader module、同一个 80B `UIC` UBO（`vec4 ui_screen + mat4 ui_vp`）。
* **GL 接口零改动**：`u_origin/u_size/u_color/u_view_proj/in_pos/in_world_pos/in_uv`
  全部保留原名字与原算式（`loom_hud.py` / `engine.py` 一行未改）；只在 `loom_render.py`
  的世界程序创建处补一行 `u_mode=1`。
* **片段**：`texture * tint`。屏幕 UI 的 tint = GL `u_color` / VK 逐顶点色；
  world Canvas 的 tint 恒白（浮点 `x*1.0 == x`，逐位不变）。

## 9. 兼容层新增宏（GL / VK 两套分支）

| 宏 | VK | GL |
|---|---|---|
| `SB_UI_UBO/TEX/SAMP` | 0 / 1 / 2 | 0 / 0 / 0 |

## 10. 遗留不确定点（宁多列）

1. **.spv 数量 13 ≠ 任务写的 12**：基线实测 11 + 新增 2 = 13（§3 已解释；任务里的「12」按真实输出订正）。
2. **world Canvas 不在 23 场景门内**：`EditorApp.render` 的 FramePlan 只含 shadow/main/sky/post
   （`editor.py:2490-2492` 未开 `include_world_canvas`），且 `SceneDriver.load_from_data` 不调
   `_link_ui_targets`（VK 侧靠 `render_world_canvases` 懒绑）——这是**预存在**的夹具覆盖缺口，
   不是本次改动引入。因此对 world 管线补了 §8.2 的直接 old-vs-new 对拍（0 差异）。
3. **world quad 在真实夹具里被深度测试全遮挡**（开深度 0 px、关深度 658 px）：帧状态/场景构图所致，
   预存在；本次改动前后真实帧 PNG 仍逐字节相同，说明未改变该行为。若要让 world Canvas 进入像素门，
   需要另开一个「正对告示牌、无遮挡」的 `ab_*` 场景（本轮未做，避免改测试/基线）。
4. **GL 侧为「一条 pair 服务两个 program」保留了不使用的输入/uniform**：HUD program 声明了
   `in_world_pos`、`u_view_proj`（runtime 分支不取）；world program 声明了 `in_pos/u_origin/u_size/u_color`。
   实测 moderngl 正常、像素 0 差异；调试时看到这些「未绑定属性/未设置 uniform」属预期。
5. **`vk_renderer.py:1227` 有一句注释仍写 `_WORLD_UI_WGSL`**（指向已删常量，仅注释）；按纪律未改
   `vk_renderer.py`，留给下一次维护顺手订正。
6. **没有做窗口人工目视比对**（无头环境），像素门 + 直接对拍 + PNG 哈希是本次唯一视觉证据。
7. 发布包未重跑（`os.walk` 会收 `.spv`/shader 源，但未实际出包，不在验收门内）。
