# Loom 后续可选计划（Backlog，非当前承诺）

> 记录"值得做但当前不做"的想法，避免丢失。每条含：动机 / 方案 / 代价 / 前置条件。
> 状态标记：`待评估` / `已设计` / `暂缓` / `已实现`。

## 1. Agent 操作回放面板（替代已移除的"步进模式"）

- **状态**：待评估（2026-11-07 记录）
- **动机**：用户希望"人能看到 AI 每一步在做什么"。原"步进模式"要求人点下一步才执行，
  与 MCP 同步工具调用模型冲突（工具调用会超时，放宽超时又导致 Agent 重试重复提交），已移除。
  正确形态是**事后回放**：不阻塞工具调用，把每一步记录下来供人回看。
- **方案**：
  1. `AgentService` 每执行一条命令，追加一条结构化记录到环形缓冲：
     `{ts, cmd, args, ok, ms, done, total, before_snapshot?, after_snapshot?}`；
  2. 新增工具栏「AI 操作历史」面板：列表显示每条命令，点击某条 → 把场景恢复到该条**之前**的状态并高亮受影响对象；
  3. 提供「回放」按钮：按原节奏（120ms/条）重放一轮，人可随时暂停/单步（**本地播放**，不涉及 MCP 调用）；
  4. 与批次撤销联动：一轮 AI 操作对应一个 `BatchCommand`，面板里按"轮"分组。
- **代价**：需要命令级场景快照（复用 `undo.snapshot`），内存随轮次增长 → 环形上限（如最近 200 条/20 轮）。
- **前置**：A~D（逐条执行/状态栏/聚焦/批次撤销）已实现。

## 2. 场景快照 diff 可视化
- **状态**：待评估
- **动机**：回放面板需要"这条命令改了什么"的直观展示。
- **方案**：对前后快照做字段级 diff（位置/旋转/缩放/颜色/可见性/父子关系），面板里以 `旧 → 新` 展示。

## 3. VK 阴影容量扩展
- **状态**：暂缓（已文档化已知限制）
- **动机**：当前 VK 平行光阴影最多 2 张、点光阴影仅 1 套；第 3 盏起打印一次警告。
- **方案**：阴影图池化（按需分配/回收），bind group 按槽位动态重建（注意本项目驱动的多 bind group 死锁史）。

## 4. Shape 描边逐像素等价
- **状态**：暂缓（图元级差异，已契约化 `STROKE_PIXEL_EQUIVALENT=False`）
- **动机**：GL `GL_LINES` 与 VK 三角带覆盖规则不同；实测 line-list 也无改善（WebGPU 线宽恒 1px）。
- **方案**：若必须逐像素，需要在 GL 侧也改成三角带（改变参考基线），或引入几何着色器式扩边 + 半像素偏移。

## 5. 离屏 RenderTexture 型 Canvas
- **状态**：待评估（引擎本无此功能，非 VK 缺口）
- **动机**：当前 `loom_ui` 只有 `screen` / `world` 两种 Canvas。
- **方案**：新增 `canvas_type="offscreen"` + `target` 材质槽，渲染到纹理再作为贴图使用（两后端都要做）。

## 5. LoomHub 自更新（排入 LoomHub 0.1.3）
- **状态**：待评估（2026-11-08 记录；本轮只做 0.1.2 的覆盖安装能力验证，不做自更新）
- **动机**：现在 LoomHub **没有任何自更新能力**（全仓库无 `self_update`/`check_update` 之类代码；
  `test_hub` 里"远程下载接口"仍是 `NotImplementedError`）。用户想升级只能自己去 GitHub 找新版
  Setup 手动下载 —— 而我们每轮都可能改 Hub 自身（本轮就因配置落点重构从 0.1.1 升到 0.1.2），
  手动升级路径迟早会变成"用户跑着旧 Hub、行为与文档不符"的故障源。
- **方案（分三步，先做前两步即可）**：
  1. **检查更新（只读、零风险）**：启动后延迟 N 秒、每 24h 最多一次，GET
     `https://api.github.com/repos/lhy302/WeaveEngine/releases`，筛 `hub-v*` tag，
     与本地 `版本.json` 做语义版本比较；只有"远端更新"才提示。失败/无网静默（不打扰）。
     设置项：`check_update_enabled`（默认 true）、`last_check_ts`。
  2. **下载（可校验）**：取 release 里 `LoomHub-<ver>-Setup.exe` 资产 → 落到
     `%LOCALAPPDATA%\Loom\updates\`；比对 asset 的 `size` 与发布侧提供的 SHA256 清单
     （发布链路已有"版本单一事实源"基础，可顺带产出哈希清单）；非 https 一律拒绝。
  3. **安装（最后做）**：程序退出后静默执行 `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART`；
     Program Files 安装需提权 → 由安装器自己弹 UAC，或提示"以管理员身份运行"。
     **必须**：先退出 LoomHub 再装（否则 exe 被占用）；保留上一版安装器以便回滚；记录升级历史。
- **前置**：①覆盖安装已被验证可行（同 AppId 原地升级；本轮已给 `installer.iss` 补
  `[InstallDelete] _internal` 防 PyInstaller 残留）②`hub_github.py` 已有 releases API 访问能力与 token 链路。
- **代价**：约 1~2 天；主要风险在"自更新把用户弄成半个安装"——所以默认**只检查、只提示**，
  自动安装作为可选开关，且失败必须能回滚。
- **不做的事**：不自动提权、不静默重启、不在用户游戏运行中替换文件。
