# pygame 窗口 IME 污染实测报告（2026-10-18）

> 性质：物理证据记录。供后续"玩家运行时换 Qt"决策引用。
> 触发原因：Canvas UI 阶段3 实现 InputField 前，用户要求验证 pygame 窗口的输入法污染问题是否仍存在。

---

## 一、背景

编辑器在 2026-08-17 全面弃用 pygame 窗口改用 Qt，原因记录在 `gui.py:5`：

> pygame(SDL) 窗口会进程级污染中文输入法(IME)候选框 —— tkinter 子窗口、系统文件对话框全中招，补丁无解。

但**玩家运行时（PlayerApp / game_player.py）一直仍是 pygame 窗口**。
本次实测验证：该污染问题在玩家运行时是否仍然存在。

---

## 二、实测方法

脚本：`Loom/tests/_tmp/probe_pygame_ime.py`

1. 打开 pygame 窗口（800x400），调 `pygame.key.start_text_input()`
2. `set_text_input_rect` 指定候选框位置到窗口下方输入区
3. 用户手动用中文输入法打字，观察候选框与字符提交
4. 事件全量写入 `_ime_test.log`

---

## 三、实测结果（2026-10-18 19:19）

| 观测项 | 结果 |
|---|---|
| `start_text_input()` 调用 | ✅ 成功（无异常） |
| `TEXTEDITING` 事件 | 74 次（拼音逐字符输入被正确接收） |
| `TEXTINPUT` 事件 | 2 次，内容为 `我就和u覅回去无IE合法` / `人哈王企鹅UI回复i` |
| **候选框是否弹出** | ❌ **不弹出** |
| **是否影响其他程序输入法** | ❌ **影响（关掉测试窗口后其他程序输入法失灵）** |

### TEXTINPUT 内容异常分析

输入拼音序列为 `wjheufihqwuiehfrwqeuihfui`（从 TEXTEDITING 可见完整过程），
正常输入法应弹出候选框供选择后提交一句通顺中文。实际提交结果混杂：
- 部分中文（`我就和`、`回去`、`合法`）
- 拼音字母（`u`、`IE`）
- 生僻字（`覅`）

**结论**：候选框未显示导致用户"盲选"，最终提交内容是乱按结果。
这不是输入法正常工作，而是**半失灵状态**。

---

## 四、结论

**污染问题仍然存在，且性质与 2026-08-17 记录一致**：
- 本窗口的 IME 候选框无法显示
- 污染会扩散到系统级（影响其他程序）

**影响**：
1. 玩家运行时（pygame 窗口）的 InputField **无法支持中文输入**，也不能通过补丁修复
2. 用户决策：**玩家运行时必须换 Qt 窗口**（与编辑器对齐）
3. 换 Qt 后 InputField 的 IME 桥接成为**必做项**（不是可延后项）

---

## 五、后续决策影响

原 CanvasUI 契约「冲突三：C. 先 B 后 A（编辑器中文输入单独立项）」的前提被推翻：
- 现在**没有"玩家运行时走 pygame 现成链路"这条退路**
- Qt IME 桥接从"编辑器可选项"变成"两种运行环境的必需项"

需要重新评估玩家运行时窗口架构（见后续决策台面）。
