## 已知小问题（本次测试发现）
- `set_color` 的参数名是 `name`（不是 `model`），传错时报"没有目标"——契约与 `unity_material_set` 的 `name_or_id` 不一致，建议统一。
- `unity_scripts_list` 返回的是**全局脚本注册表**（17 个），不是"该物体挂载的脚本"；要看挂载请用 `diag_inspect_gameobject` 的 `scripts` 字段。
- 停止播放会还原场景（玩家回原位、豆子恢复）——这是设计，但"吃豆分数"目前只在播放期有效，未持久化。
## 追加：可玩性修复（2026-11-07 二轮）

### 用户反馈
“按播放奇奇怪怪的；玩家在哪？怎么操作？怎么证明能玩？播放模式对键盘的反应和打包游戏一样吗？”

### 定位到两个真问题

1. **相机跟随把目标抬到 7 米**（`camera_follow` 的 `oy=7`）→ 相机盯着玩家上方 7 米，玩家掉出画面底部；
2. **点“播放”后键盘焦点在工具栏按钮上** → 视口收不到 WASD，`key_state` 为空 → 脚本 `is_key/get_action` 恒 False，表现“播放了但角色不动”。

### 修复
- `editor.py::toggle_play()` 进入播放时把焦点交还视口（`view.viewport.setFocus()`）；
- 吃豆人场景移除 `camera_follow`，改固定俯视：`camera_look pitch=-58°` + `camera_move distance=15`；玩家缩放 1.2 便于观察。

### 输入链路实证（离屏编辑器 + 模拟视口按键）

| 操作 | 玩家位移 |
|---|---|
| 按住 W 30 帧 | (0, **+2.068**) |
| 松开 W 30 帧 | (0, **0.000**)（立即停） |
| 按住 D 20 帧 | (**+1.157**, 0) |
| 退出播放 | 回到 (0,0)（播放快照还原） |

同时确认 `script_keys["w"]=True`、`get_action("向前")=True`，脚本 `on_start` 打印“共 37 颗豆子”。

### 播放模式 vs 打包游戏的输入差异（结论）

- **同**：两条路径最终都写 `engine.script_keys`（Qt 视口 `key_state` → `sync_script_keys()`；打包玩家 `pygame.key.get_pressed` → `_handle_events`），
  脚本用同一套 `get_action`/`is_key`，动作映射同一份 `输入配置.json` → **脚本行为一致**；
- **异**：① 编辑器播放需要视口有焦点（已自动处理）；② 编辑器“停止播放”会**还原场景**，打包游戏不会（这是设计差异，不是输入差异）。

## 追加：重做为真正的 2D 吃豆人（2026-11-07 三轮）

### 用户反馈的问题与处理

| 问题 | 原因 | 处理 |
|---|---|---|
| 三个红球绕着圆心转 | 用的是内置 `orbit`（公转）脚本 | 新写 `pacman_ghost.py`：**沿走廊网格移动**，到格心随机选方向（不反向） |
| 视角没有锁定 | 播放态下 `_update_camera` 仍让 WASD 平移编辑器相机 | `editor.py` 打补丁：播放态**禁用键盘相机控制**（WASD 只归玩家） |
| 主角比走廊宽、卡墙 | 玩家直径 1.2 > 走廊 1.0 | 玩家 scale 0.5（直径 0.5）；并改为**网格移动**（目标格是墙就不走） |
| 没有地板 | 场景没放地面 | 新增 `地板` 平面（20×20） |
| 想要正交/2D | 引擎主相机只有透视（`mat4_ortho` 仅用于阴影） | 用**高机位 + 小 FOV（26°）+ 俯视 -89°** 模拟正交 2D 视角 |

### 2D 吃豆人场景（PacMan2D.json，126 物体）
- 11×11 迷宫：**63 面墙 + 58 颗豆子**（墙/豆命名 `墙_x_z` / `豆子_x_z`，整数世界格坐标）
- 玩家：scale 0.5，`pacman_player`（网格移动 + 吃豆计分）
- 幽灵：3 个，`pacman_ghost`（网格移动，随机转向）
- 地板 + 平行光；相机：`camera_look pitch=-88.8` + `distance=9`（俯视锁定）

### 实测验证（离屏编辑器，走与 Qt 视口相同的输入链路）

| 验证项 | 结果 |
|---|---|
| 按 D 从 (1,0) 走到 x=4（x=5 是墙） | 停在 **4.0**，继续按 D 100 帧仍是 4.0 |
| 按 W | 沿走廊逐格移动（(4,0) → (4,3.8)） |
| 相机是否被 WASD 带走 | `(0,0,9) → (0,0,9)` **未动** |
| 吃豆 | 豆子 `visible: True → False`，得分 5/58、10/58、15/58 逐档打印 |
| 幽灵移动 | 沿走廊（如 z 恒 -4，x 从 -3.78 → 0.07），不再绕圈 |

### 新发现的引擎问题（已记录，未修）

`move_with_collision` 的推出逻辑有边界 bug：贴墙持续推挤约 70 帧后，物体会被**推到墙的另一侧**（实测从 x=0.71 穿到 1.238 并继续）。
本游戏改用网格移动后不受影响，但通用碰撞需要修（属引擎 P1）。

## 追加：规则闭环 + 播放器能力补齐（2026-11-07 五轮）

### 用户反馈三条
1. 播放未强制初始化相机（编辑态滑动的相机带进播放）；
2. 敌人之间会互相重叠；
3. 规则不明确：何时通关、结束后做什么。

### 修复

| 项 | 实现 |
|---|---|
| 播放强制相机 | `editor._apply_camera` 记录场景相机快照 `_scene_cam`，`toggle_play()` 进播放时**强制套用**（位置/目标/距离/朝向/正交/`fov`） |
| 相机 fov 序列化 | `sceneio` 相机段新增 `fov`（度）；编辑器与 VK 驱动都读 |
| 幽灵防重叠 | `pacman_ghost.py`：与同伴距离 < `avoid_r`(0.8) 时**掉头**，`avoid_cd`(0.1s) 冷却防抖 |
| 通关规则 | 吃完**所有可见豆子** → `won=True` + `set_logic_paused(True)` + 弹出「通关面板」 |
| 结束 UI | 面板含「新开一局」(重置豆子/分数/位置/解除暂停) 与「退出游戏」 |
| 退出语义 | 编辑器播放 → 退出播放回编辑态；独立播放器 → 关闭应用（统一 `request_game_exit()`） |

### 顺带修掉的 3 个引擎缺陷

1. **UI 声明式事件从不触发**：`loom_ui._fire_binding` 在 `ScriptComponent` 上找方法，而方法在运行时实例 `sc._script` 上 → 所有 `ui_bind_event` 点击无效；
2. **VK 播放器不加载 `scripts/` 目录**（GL 播放器继承引擎会加载）→ 打包后自定义脚本不生效；
3. **VK 驱动没有暂停/退出通道**：新增 `logic_paused` / `request_quit` / `set_logic_paused()` / `request_game_exit()`，`advance_logic` 暂停时冻结脚本与物理；`vk_player` 在 `request_quit` 时关窗。

### 验证

| 项 | 结果 |
|---|---|
| 编辑态把相机乱动（dist=25/yaw=1.2/ortho=False）后播放 | 恢复场景值：dist=9 / yaw=0 / pitch=-1.55 / ortho=True |
| 通关 | `logic_paused=True`、面板 visible、截图 `pacman2d_win.png` |
| 新开一局 | 58 颗豆子全部恢复、score=0、面板隐藏、解除暂停 |
| 退出游戏 | `_request_exit_play=True` → `is_playing=False`（回编辑态） |
| VK 驱动 | `ortho=True`、脚本成功加载（「共 58 颗豆子」）、暂停后幽灵静止、`request_game_exit→request_quit=True` |
