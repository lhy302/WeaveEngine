## 1 缺陷原文

> **D2：时钟设置不传播**（{BT}scene_driver{BT} 用 {BT}FixedStepClock(){BT} 默认 30Hz，不读 {BT}logic_fps/physics_fps{BT}；实测设 60Hz 仍 30Hz；tests 无门）

## 2 修前必红（2026-11-17 实测，不是推断）

新增门在**未修复状态**下跑出的原文：

```
FAIL 对拍 60Hz + 物理 120Hz：两端时钟参数逐项相等  GL=(60.0, 0.008333, 0.016667, 0, 2) VK=(30.0, 0.016667, 0.033333, 0, 2)
FAIL 对拍 20Hz + 物理 60Hz：两端时钟参数逐项相等  GL=(20.0, 0.016667, 0.05, 0, 3) VK=(30.0, 0.016667, 0.033333, 0, 2)
FAIL 对拍 45Hz（设置面板档位）：两端时钟参数逐项相等  GL=(45.0, 0.016667, 0.022222, 0, 2) VK=(30.0, 0.016667, 0.033333, 0, 2)
PASS 对拍 缺键 → 默认 30Hz：两端时钟参数逐项相等  GL=(30.0, 0.016667, 0.033333, 0, 2) VK=(30.0, 0.016667, 0.033333, 0, 2)
PASS 对拍 logic_fps=0 → 绑死模式（无分离时钟）：两端时钟参数逐项相等  GL=None VK=None

FAIL VK logic_fps=60：clock.logic_fps == 60.0  VK=(30.0, 0.016667, 0.033333, 0, 2)
FAIL VK logic_fps=45：clock.logic_fps == 45.0  VK=(30.0, 0.016667, 0.033333, 0, 2)
FAIL VK logic_fps=20：clock.logic_fps == 20.0  VK=(30.0, 0.016667, 0.033333, 0, 2)

FAIL physics_fps=120 → sub_dt=1/120 且 60Hz 下 2 子步  VK=(30.0, 0.016667, 0.033333, 0, 2)
FAIL physics_fps=60 → sub_dt=1/60 且 60Hz 下 1 子步（子步拉齐 fixed_dt）  VK=(30.0, 0.016667, 0.033333, 0, 2)
```

**读法**：{BT}GL=(logic_fps, phys_substep_dt, fixed_dt, steps, sub_steps){BT}。设置 60Hz 时 GL 60.0 / VK **30.0**，
与缺陷描述「设 60Hz 仍 30Hz」逐位吻合。

两个 PASS 是有价值的反例，说明**缺陷面比描述更窄**：
- 「缺键 → 默认 30Hz」两端一致 —— 因为 VK 的错值恰好就是默认值，**测不出来**（这正是它藏了这么久的原因）；
- 「logic_fps=0 → 绑死模式」两端一致 —— 因为 {BT}split_enabled(None){BT} **内部会自己 load_settings**，
  所以**开关那半碰巧是对的**，错的只有**时钟那半**。这条区分让修法能收得很窄（不必动开关逻辑）。

## 3 根因（file:line）

| 端 | 位置 | 代码 | 判定 |
|---|---|---|---|
| GL（正确） | {BT}Loom/engine.py:469-480{BT} | {BT}_s = guiloader.load_settings('loom'){BT} → {BT}split_enabled(_s){BT} → {BT}clock_from_settings(_s){BT} | ✅ 读设置 |
| VK（错误） | {BT}Loom/scene_driver.py:594-597{BT}（修前） | {BT}from core_clock import FixedStepClock, split_enabled{BT} / {BT}split_enabled(){BT} / {BT}FixedStepClock(){BT} | ❌ 时钟走**无参构造**，永远 30Hz |

**影响面**：{BT}vk_player.py{BT} / {BT}game_player.py{BT} 都构造 {BT}SceneDriver{BT}，而**打包游戏默认后端是 vulkan**
（{BT}game_player.py:159{BT}）—— 所以不只是「VK 播放器」，**打包产物也一样中招**。

## 4 修法（收窄到一行语义）

```python
# 修前
self._split_enable = split_enabled()
self._clock = FixedStepClock() if self._split_enable else None

# 修后（与 engine.py 逐条一致：读同一份设置，走同一个构造函数）
try:
    import guiloader as _gl_s
    _s_clock = _gl_s.load_settings('loom')
except Exception:
    _s_clock = {}
self._split_enable = split_enabled(_s_clock)
self._clock = clock_from_settings(_s_clock) if self._split_enable else None
```

**为什么用 {BT}clock_from_settings{BT} 而不是 {BT}FixedStepClock(logic_fps=...){BT} 手工拼**：
它是设置 → 时钟的**唯一换算口径**（{BT}core_clock.py:168-182{BT}），里面还含 {BT}phys_substep_dt{BT} 新键 /
{BT}physics_fps{BT} 旧键换算 / {BT}<50 视为误设兜底 60Hz{BT} 三条规则。两端共用同一个函数，才不会下次改口径又分叉。

## 6 基线未移动（修缺陷纪律）

| 项 | 修前 | 修后 |
|---|---|---|
| 全量回归 | 170.3s 全绿 | **169.8s 全绿** |
| 冒烟 | EXIT0 | EXIT0 |
| 默认设置（{BT}logic_fps=30, physics_fps=30{BT}）下的 VK 时钟 | 30.0Hz / sub_dt 1/60 / 2 子步 | **完全相同**（30.0 / 1/60 / 2） |
| 像素/性能基线 | — | **未动**（本修复只改时钟构造参数来源，不改渲染路径） |

> 默认值不变是这次修复能「不动基线」的关键：{BT}Loom/设置.json{BT} 里 {BT}logic_fps=30{BT}，
> 所以**存量行为的可观察结果不变**，变的是「用户把设置改成别的值时，现在真的生效了」。
