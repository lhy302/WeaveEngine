## 一、前提实验（Nuitka 编译模块外部可篡改性）

蓝图 §2.4 断言：official_manifest.py 编译进 exe 后外部改不动。本工程**未经验证**，故先做最小实验。

**实验设计**（隔离目录 tests/_tmp/nuitka_probe/）：
- hello_manifest.py（模拟 official_manifest）
- main.py（import 后打印 SECRET）
- Nuitka 2.7.1 --standalone 编译为 probe.exe

**投毒结果**：

| 攻击方式 | 结果 |
|---|---|
| 直接运行 | SECRET=abc123 ✅ |
| exe 同目录放同名 .py (HACKED_BY_USER) | SECRET=abc123 ✅ 攻击失败 |
| PYTHONPATH 指向含同名 .py 的目录 | SECRET=abc123 ✅ 攻击失败 |

**结论**：Nuitka 2.7.1 standalone 模式下编译模块优先于磁盘 .py，蓝图前提成立。

## 三、方案偏差记录（调研后确认，均属实现细节非路线分叉）

| 蓝图原文 | 实际做法 | 差异说明 |
|---|---|---|
| 「assemble() 之前先调 boot_check」 | 在 _read_registry 之后、_sha_gate 之前调 | boot_check 需要 registry 的 module_id→path 映射，故必须在拿到 data 后 |
| 「官方件被改 → 报警 + 拒绝加载该件」 | 任一官方件 modified/missing → AssemblyError（整机拒载） | 与 module_registry 现有铁律一致（官方件坏 = 拒载，不做部分加载） |
| 「LOOM_DEV=1 跳过校验」 | boot_check._is_dev_mode() 读环境变量，可显式传参覆盖（便于探针测试） | 无 |

无路线分叉，全程按蓝图推进。
