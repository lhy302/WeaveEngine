# Q-B7-48-1 裁决 B 落地留痕：线宽两端统一 = 四边形扩宽（2026-11-20）

> 裁决原话（人类 2026-11-20）：「**问题一：B**」 —— 两端统一改成「用四边形模拟粗线」，
> 不再依赖 GL 的 `line_width`（GL 有、wgpu 没有）。**明知 GL 画面也会变**。

## 1. 方案（为什么 CPU 扩宽）

| 项 | 选择 | 理由 |
|---|---|---|
| 扩宽位置 | **CPU**（`loom_line_geometry.build_line_quads`，纯 Python/numpy） | 同源（规则 5.5）：扩宽数学**只许一份**。放 CPU 上，GL 画 `TRIANGLES`、VK 画 `triangle-list`，两端只负责「画三角形」；放两端各自 shader 就是 GLSL + WGSL 两份数学，漂移无人可察 |
| 扩宽空间 | **屏幕空间像素**（不是几何空间） | 几何空间按世界单位偏移会近大远小（远处网格细成缝、近处 gizmo 糊成片）；裁决要的是「像素宽度」 |
| 线宽参数 | **像素**，默认 2.0（= 改造前 GL `ctx.line_width` 的视觉粗细） | 两端同名同义，`draw_lines(line_width=...)` 在两端**真的生效** |
| 深度 | 保留每个端点的 NDC z，配恒等 VP 直出 | `matlib.mat4_perspective` 的 `clip.z` 单调映射 [0,1]（near→0）；GL 窗口深度 =(z+1)/2、VK 深度 = z，两端相对遮挡关系与改造前一致 |
| 近平面裁剪 | 按 `clip.z >= 0` 裁剪（不是 `w > 0`） | 只按 w 裁会让裁剪点 ndc_z 变成天文数字，硬件随即按 z>w 把整个三角形再裁掉 —— 实测网格覆盖 36752→**2007**（线段大片消失）；按 z=0 裁则裁剪点恰在近平面，与「GL_LINES 由硬件裁」同义 |
| 绕序 | 输出 **(a,d,b)/(a,e,d)** = **CW-in-NDC** | 引擎 GL `front_face='cw'`（engine.py:308），且主 pass 后 CULL_FACE 是开着的；实测 CCW 版四边形在 CULL_FACE 开时**整块消失**（0 像素）。旧实现画 GL_LINES 永远不受剔除影响，这条不变量就是保持该语义的代价 |

## 4. GL 画面变化留痕（裁决明知的代价）

探针 `tests/_tmp/probe_qb748_gl_change.py`（未跟踪；PNG 产物在 `tests/_tmp/qb748_gl_change/`）：
**改前**用旧实现原样手法（同 program + 同 packed 顶点 + `vao.render(moderngl.LINES)` + `ctx.line_width=2.0`），
**改后**用生产 `ed.draw_lines`。同一份真实编辑器夹具、480x320：

| 夹具 | 覆盖像素 改前→改后 | MAE | 差异像素 |
|---|---|---|---|
| 网格 | 36752 → 38043 | 0.004431 | 4642（3.02%） |
| 选中框 | 900 → 933 | 0.000147 | 33（0.02%） |
| gizmo 平移 | 232 → 240 | 0.000029 | 9（0.01%） |
| gizmo 旋转 | 1376 → 1501 | 0.000449 | 146（0.10%） |
| **水平线（2px）** | 768 → 768 | 0 | **线宽像素 2 → 2** |

**视觉评价**：粗细不变（水平线逐列亮像素数 2 = 2，覆盖像素 768 = 768）；变的是**线的边缘/端点覆盖规则**
（四边形「像素中心落在矩形内」vs 驱动线段光栅化的 diamond-exit），差异集中在斜线边缘与端点，
2px 线看上去仍是 2px 线，网格/gizmo 观感一致（覆盖像素差 3%~9% 来自斜线/端点多覆盖的半个像素）。
UI Shape 描边同步受益：`ab_ui_only [UI]` 的 GL/VK MAE 由 0.002726 降到 **0.002591**（两端都走三角带了）。
