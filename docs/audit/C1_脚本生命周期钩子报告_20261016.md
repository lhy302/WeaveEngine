## 一、目标

脚本系统对齐 Unity：补 4 个生命周期钩子（on_enable / on_disable / on_destroy / on_collision_stay）.

---

## 二、改动清单

| 文件 | 动作 |
|---|---|
| scripts.py Script 基类 | 加 4 个空方法（on_enable/on_disable/on_destroy/on_collision_stay），纯增量 |
| engine.py update_scripts | 脚本实例化后调 on_enable（早于 on_start） |
| editor.py toggle_play 退出分支 | 清脚本实例前调 on_disable（坏脚本 try/except 兜底） |
| loom_model_gpu.py remove_model | models.remove 之前调 on_destroy（remove_subtree/clear_scene/load_scene 都经本函数） |
| loom_physics.py | 加 _script_overrides_stay/_any_script_overrides_stay 辅助函数；_collision_events_inline 与 _dispatch_collision_events 派发 stay |
| tests/_tmp/script_lifecycle_check.py | 新建探针（9 项断言） |

---

## 三、方案偏差记录（调研后确认，均属实现细节非路线分叉）

| 蓝图原文 | 实际做法 | 差异说明 |
|---|---|---|
| 「on_enable：update_scripts 实例化后调 on_enable」 | 在 on_start 之前调（同 try/except 保护） | Unity OnEnable 早于 Start，语义对齐 |
| 「on_disable：停止播放/禁用时调」 | toggle_play 退出分支的脚本清理循环前调 | Loom 无「运行时禁用」概念；停止播放是唯一触发点 |
| 「on_destroy：remove_model/remove_subtree 时对每个脚本调」 | 只改 remove_model（其余函数都经它） | remove_subtree/clear_scene/load_scene 均调 remove_model，天然覆盖 |
| 「on_collision_stay：在 current ∩ prev 上派发」 | 加 has_stay 判断，未定义 stay 脚本仍走原「集合不变 continue」快路径 | 保持蓝图 §4 铁律「无事件零开销」 |

无路线分叉，全程按蓝图推进。
