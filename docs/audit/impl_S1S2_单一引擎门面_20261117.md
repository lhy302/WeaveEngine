## 0 一句话结果

| 指标 | 之前 | 现在 |
|---|---|---|
| 两端公开成员 | GL 109 / VK 40 | **GL 112 / VK 98** |
| 两端**共同**成员 | 30 | **88**（+58） |
| **GL 独有** | 79 | **24**（−55） |
| 继承关系 | `GLEngine(13 个 mixin)` / `SceneDriver(object)` | **两者都继承 `EngineCore`** |

**这不是「逐条补 VK 的 40 条」**，而是「把后端无关的东西收进一个内核，两端共享」。差异从 79 条缩到 40 条，是结构变化的自然结果。

## 1 S2-1：EngineCore 骨架（行为零变化）

新增 `Loom/engine_core.py`：

```python
class EngineCore(TransformMixin, PhysicsMixin, InputMixin, CameraMixin,
                 FrameComponentMixin, ProfilerMixin, LogicThreadMixin, RaycastMixin):
```

- 这 8 个 mixin **不含任何 GPU 依赖**（moderngl / wgpu / 着色器 / 阴影 / 渲染 / HUD / 模型 GPU / 光照 / GLFW 全不在）；
- `GLEngine` 改为 `GLEngine(EngineCore, ShadowMixin, HudMixin, RenderMixin, ModelGpuMixin, LightingMixin, GlfwWindowMixin)`；
- **为什么能零行为变化**：grep 确认 14 个 mixin 里**没有一处 `super()` 调用**，所以继承树重排不影响任何方法解析；唯一跨 mixin 重名的 `_prof_*`（RenderMixin vs ProfilerMixin）早已由 `loom_render._mro_prof` 做成 **MRO 顺序无关**。
- 验证：`run_all` **174.3s 全绿**，`smoke` EXIT0，公开方法数 109 不变。

## 2 S1：宿主事件 API 统一（**这一步抓到了真缺陷**）

### 2.1 统一入口

`EngineCore` 新增三个**唯一**入口 + 三个可覆写钩子：

| 入口 | 语义 |
|---|---|
| `handle_key_event(ev)` | ① F11 全屏 ② F9/F10 逻辑时钟 ③ UI 焦点优先 ④ `on_key_event` 钩子 ⑤ key_state 更新 / Tab 选下一个 |
| `handle_text_input(ev)` | ① UI 焦点优先（IME 中文进 InputField）② `on_text_input` 钩子 |
| `handle_quit_request()` | 钩子抛异常也按「允许退出」（否则窗口关不掉＝卡死，比丢未保存更糟） |

宿主改造：
- `loom_glfw_window._on_key_cb` → 整段删掉，只留 `e.handle_key_event(_make_key_event(...))`；
- 文本回调 → `e.handle_text_input(...)`；关窗 → `e.handle_quit_request()`；
- `loom_player_window.py`（Qt 播放器窗口）→ 原来手写 `key_state[k]=True` + `on_key_event(...)`，现在也只调 `handle_key_event`。
  > **纠错（独立审查 P0-2）**：该文件用的是 `runtime.PlayerApp`（**GL**），不是 VK 播放器。
  > 真正的 VK 播放器 `vk_player.py:483-496` **仍是自己写 key_state + 直调 ui_bridge.on_key**，
  > 没有接 `handle_key_event`。所以「四个宿主形状相同」当时是错的，实际只接了 2 个。

于是「编辑器 / GL 播放器 / VK 播放器 / 打包游戏」的宿主代码**形状完全相同**，差别只剩「怎么把事件翻成 ev」。

### 2.2 门抓到的真缺陷（**事件 API 的初值两端不同**）

新门第一次跑就红：

```
GL: [('known_key_press', False, True)]      ← 记上了
VK: [('known_key_press', 'NO_KEY_STATE', None)]  ← key_state 是空的
```

根因：

| 端 | 位置 | 做了什么 |
|---|---|---|
| GL | `engine.py:380-386` | 建 `_key`（动作名→键码）+ `key_state`（相机 10 键 = False） |
| VK | `scene_driver.py:506` | 只有 `self.key_state = {}`，**连 `_key` 都没有** |

后果：VK 下 `handle_key_event` 永远记不上键（`k not in ks` 全跳），**相机键、脚本按键在 VK 下全失效** —— 这正是「受后端影响」的教科书案例：不是方法名不一样，是**同一个方法的初值不一样**。

修法：`EngineCore._init_input_state()` 统一建 `_key` + `key_state`，两端都调（幂等）。改名带下划线是因为它是内部初始化，不是用户 API（改名后 API 矩阵计数回到 112/82）。

## 3 S2-3：SceneDriver 继承 EngineCore

`class SceneDriver(EngineCore)` —— 它不再是「第二个引擎」，只是「VK 侧装配 + 后端驱动」。
MRO 上 `SceneDriver` 自己的定义优先（现有行为不变），`EngineCore` 补上 VK 原先缺的能力。

**直接效果**：VK 公开成员 40 → **82**，与 GL 共同 30 → **72**。脚本在 VK 下能调的东西**一夜之间多了 42 个**，且全部是**同一份实现**（不是第二份）。

## 4 新增门 `test_host_event_parity.py`（13 条断言）

| 段 | 断言 |
|---|---|
| 一 结构 | 两端都继承 `EngineCore`；`E.EngineCore is SD.EngineCore`（同一个类对象） |
| 二 入口 | 两端都有 3 个入口 + 3 个钩子；**入口是 EngineCore 的实现**（`getattr(GLEngine, n) is getattr(EngineCore, n)`）—— 防「又各写一遍」 |
| 三 语义对拍 | 同一串事件（未知键 / 已知键按下 / 释放 / 文本 / 退出）→ 两端结果**逐项相等** |
| 四 钩子覆写 | 子类覆写 `on_key_event` 消费 → 两端都消费且 key_state 不更新；覆写 `on_quit_request` 拒绝 → 两端都 False |

**为什么这个门比「方法名对齐」更有意义**：方法名对齐只是必要条件。若一端由 GLFW 回调触发、另一端由播放器手调，宿主仍要写两套代码 —— 那还是受后端影响。本门钉的是「同一串事件 → 同一串结果」。

## 4.5 S2-2（部分完成）：把「纯数据/逻辑」从 GL mixin 拆进内核

**判据（可审计）**：方法体里**不出现** moderngl / wgpu / 着色器 / VAO / 纹理 / 帧循环。
满足的搬内核，不满足的留后端。

本次搬走 11 个（新增 `Loom/loom_scene_query.py` · `SceneQueryMixin`）：

| 组 | 方法 |
|---|---|
| Layer / Tag | `tag_exists` / `layer_name` / `layer_id` / `register_tag` |
| 查找 | `find_by_tag` / `find_by_name` / `find_all_by_name` / `find_by_script` |
| SendMessage | `send_message_to_name` |
| 设置层/标签 | `set_object_layer` / `set_object_tag` |

效果：VK 82 → **93**，GL 独有 40 → **29**，共同 72 → **83**。

**第二批（同一天）**：再搬 5 个 —— `add_model` / `attach_model` / `add_material` /
`find_model_by_guid` / `toggle_logic_paused`（+ `set_logic_paused` 统一）。
新增 `Loom/loom_model_data.py`（`ModelDataMixin`）：把「数据面」与「GPU 上传」拆开，
GPU 只通过一个钩子 `_backend_upload_model(model)` 接触 —— GL 侧建 VBO/VAO，VK 侧空操作
（VK 渲染器每帧按 `_mesh_key` 从 mesh 现建缓冲，本来就没有持久 VBO 架构）。
效果：VK 93 → **98**，GL 独有 29 → **24**，共同 83 → **88**。
顺带修掉一个口径不一致：GL 的 `set_logic_paused` 只设标志，而 `toggle_logic_paused` 还会
reset 时钟/对齐插值 —— 同一件事两种效果；统一到内核后两者**效果相同**。
验证：`getattr(GLEngine, n) is getattr(SceneDriver, n)` 全部为 True（**同一份实现**，不是第二份）。
`run_all` **173.5s 全绿**，`smoke` EXIT0。

**为什么只搬这 11 个**：剩下的 29 条里，16 条是后端渲染原语（本该留后端）、8 条是
`add_model`/`add_light` 这类**数据与 GPU 上传混在一起**的（要先拆分）、5 条是时钟/脚本
（`toggle_logic_paused` 依赖 GL 独有的 `_ensure_split()`，VK 有自己的 `set_logic_paused`，
需要先统一时钟所有权 —— 属 S2-2 剩余部分）。

## 6 顺手发现的**假绿**（与本次改动无关，但是真问题）

`test_hub_update.py` **打印 FAIL 却退出码 0**，所以 `run_all` 从来没抓到它。实测证据：

```
$ py -3.13 tests/test_hub_update.py
FAIL ② is_program_files 判定正确  ('C:\\Program Files\\LoomHub', 'C:\\Users\\...\\Programs\\LoomHub')
总结果: FAIL ❌ ['② is_program_files 判定正确']
$ echo %ERRORLEVEL%
0
```

且**在 HEAD 上（我的改动之前）就是这样**（已用 `git stash` 验证），所以不是本次引入。

两层问题：
1. **测试基建**：该文件有 `sys.exit(1)` 和 fail-gate，但退出码仍是 0 → 具体机制未查明（留痕：**未核**）；
2. **真缺陷**：`LoomHub/hub_update.is_program_files('C:\\Program Files\\LoomHub')` 返回 **False**（应为 True）→ 安装到 Program Files 时**不会加 `/ALLUSERS`、不触发 UAC**，等于按用户级安装到系统目录（权限/更新都会出问题）。

处置：**本次不修**（Hub 侧，属 Hub 0.1.5 范围），登记进缺陷账本与待裁决。
