## 一、目标

退役 SAP 粗筛的 A 类对拍门 `LOOM_NO_SAP`，删除对应 B 路（triu 全对 + ancestry 过滤）回退分支。
C 路（默认）为唯一路径：C 一体内核 `loom_kernels.loom_collide_pairs`（SAP 窗口扫描 + yz + ancestry + 精判 + 去重单次调用）。

### C 决策的深度讨论（用户质疑后修订）

用户要求"先讲清楚引用 `_collider_from_aabb` 的探针 collide_prof*.py 是干什么用的"。
施工 Agent 详细核实后更正原判断：

- `collide_prof.py`（2026-09-07 任务1）：collide_pairs 热段取证，拆解 4.2ms 是哪些相位贡献
- `collide_prof2.py`（round-2）：提取写法微对比 + 新算法模拟等价性验证
- `collide_prof3.py`（新路径内拆）：cand/extract/C-kernel/list 各段耗时

三探针引用 `_collider_from_aabb` 的目的：**构造 C 内核输入数组（bmn/bmx/scn/rad/kind）**，
不是为了走 B 路。删 `_collider_from_aabb` 会连带破坏这三个性能取证探针，
违背"探针固化"铁律。**用户拍板：保留**。

## 六、方案偏差记录

**用户拍板的 4 个决策点**：

| # | 决策点 | 选择 |
|---|---|---|
| A | 退役方案 | **B（彻底退役）** |
| B | `_SAP_FALLBACK_PAIRS` 死常量 | **删** |
| C | `_collider_from_aabb` | **保留**（探针工具）|
| D | `collide_val_check.py` NO_SAP 对拍段 | **删** |

**C 决策的修订**：施工 Agent 原建议"删 `_collider_from_aabb`"，理由是"生产代码无引用"。
用户要求先讲清楚 collide_prof*.py 探针用途，施工 Agent 核实后**自我更正**：这三个是性能取证探针，
引用 `_collider_from_aabb` 是为构造 C 内核输入数组，删除会破坏历史物证。**改为保留**。

用户原话（决策依据）：
> "C：先讲清楚引用 `_collider_from_aabb` 的探针 collide_prof*.py 是干什么用的，为什么你会给出删的倾向。"

**教训**："生产代码无引用"不等于"可以删"——需区分"冗余实现"（该删）与"生产/测试分离的正常工具函数"（该留）。
