## 2 修法（裁决 A：抽共享模块，两端调同一份）

### 2.1 新增 `Loom/loom_collision.py`（配对 / 判重 / 派发 / 回调，纯函数）

| 函数 | 作用 | 来源 |
|---|---|---|
| `homogeneous_vertices(mesh, cache)` | 顶点 → 齐次 (V,4)，按 id(mesh) 缓存 | 原 `loom_transform._homogeneous_vertices` 同式 |
| `aabb_of(model, M, cache)` | 世界空间 AABB | 原 `loom_transform.get_bounding_box` 同式 |
| `collider_of(model, M, cache)` | `box` / `sphere` 碰撞体数据 | 原 `loom_physics.collider_bounds` 同式 |
| `ancestry_ranges(models)` / `is_related_idx()` | 同树不算碰撞 | 原 `_ancestry_ranges` / `_related` 同源（`fastpath.ancestry_dfs`） |
| `pairs(models, worlds, cache)` | 全部碰撞对（朴素 O(n²) + AABB 早退） | 新写；**与 GL 的 SAP+C 内核产出同一集合**（门 §三 逐对拍） |
| `call_cb(m, hook, other)` | 调脚本回调（坏脚本标记不崩帧） | 原 `FrameComponentMixin._call_collision_cb` |
| `dispatch(models, pairs)` | start/end/stay + trigger 分流 | 原 `PhysicsMixin._dispatch_collision_events`（整段搬走） |

### 2.2 GL 侧只做「委托」，行为零变化

| 原位置 | 改成 |
|---|---|
| `loom_physics._dispatch_collision_events` | `return _lc.dispatch(self.models, pairs)` |
| `loom_physics` 的 4 个模块级脚本钩子判定 | 改为 `from loom_collision import ...`（同名 re-export，外部导入点不用改） |
| `loom_frame_components._call_collision_cb` | `return call_collision_cb(m, hook, other)` → `_lc.call_cb` |
| `loom_frame_components.update_audio` / `_sync_audio_listener` | 委托模块级 `update_audio(host, dt)` / `sync_audio_listener(host)` |

### 2.3 VK 侧补三段 + 惰性音频

| 新增 | 内容 |
|---|---|
| `SceneDriver.update_audio(dt)` | 调 `loom_frame_components.update_audio`（与 GL 同一份） |
| `SceneDriver._sync_audio_listener()` | 调共享 `sync_audio_listener`；适配 VK 的相机属性名（`camera_pos`/`yaw`/`pitch` vs GL 的 `camera`/`camera_yaw`/`camera_pitch`） |
| `SceneDriver._ensure_audio()` | 惰性建 `AudioSystem`（与 GL 同一个类）；建失败**只警告一次**并降级（可见，不静默） |
| `SceneDriver._logic_prep(dt)` | 算本逻辑帧碰撞对；**只在本场有脚本时才配对**（没脚本就没人监听事件） |
| `SceneDriver._dispatch_collision_events(pairs)` | 调 `_lc.dispatch` —— 与 GL 是**同一个函数** |

## 3 两个实测踩到的坑（都写进代码注释了）

### 3.1 空列表也必须派发

第一版写成 `if self._prep_pairs:` —— 实测漏掉**所有「离开」事件**：

```
GL 事件: [(start,B), (start,A), (end,B), (end,A)]
VK 事件: [(start,B), (start,A)]              ← 少了两条 end
```

原因：上一帧有对、这一帧没有 = 物体分开了，要发 `on_collision_end`；真值判断把空列表当「没事发生」直接跳过。
改成 `if self._prep_pairs is not None:`（与 GL 同）后两端逐条相等。

### 3.2 门里的脚本必须走**真实注册路径**

`m.add_script(None)` + 手塞 `sc._script = counter` 是既有测试的写法，但它经不起 `_logic_frame`：
`_run_scripts` 会按 `script_id` 重新解析，`None` 解析成 `None` → 实例被抹掉 → 回调静默不发生。
本门改成 `scripts.register(类)`（键是 `cls.script_id`）+ `m.add_script('LogicFrameProbe')`，走真链路。

## 4 修后实测（门原文）

```
PASS GL 段序 = 参考实现（8 段齐全 + 插值翻页）
PASS VK 段序与 GL 逐项相等（段数含物理子步）
PASS VK 无缺失段
PASS VK 暴露 update_audio / _logic_prep / _dispatch_collision_events
PASS gap=0.2（重叠）：两端配对集合相同    GL=[(0,1)] shared=[(0,1)]
PASS gap=0.99（重叠(临界)）：两端配对集合相同
PASS gap=1.5（分离）：两端配对集合相同    GL=[] shared=[]
PASS 两端都产生了碰撞事件（>0）           GL=4 VK=4
PASS 两端事件序列逐条相等                 GL=[(start,B),(start,A),(end,B),(end,A)] VK=同
PASS 序列含 start 与 end（真的走了进入+离开）
总结果: ALL PASS
```

**「配对集合对拍」是这次最关键的一条断言**：它证明「VK 用朴素 O(n²) 也不改变语义」——
GL 的 SAP + C 内核与共享实现产出的对**逐对相同**（重叠 / 临界重叠 / 分离 三种情况）。

## 5 门有牙（证据链）

修复过程中门自己抓到两次问题，都是先红后绿，不是「写完就绿」：

| 时刻 | 门报的 | 说明 |
|---|---|---|

## 7 留痕（跳过 / 未核）

| 项 | 处置 | 理由 |
|---|---|---|
| **未做**：VK 的 prep 不算「AABB 缓存 / 光源 VP 缓存」 | 有意 | 那是 GL 渲染侧复用的缓存；VK 的 VP 在 `vk_renderer._pack_light_vps` 每帧自己算（B7-21 刚改过）。照抄会白算一遍 |
| **未做**：`_disp_gen` 节流 | 有意 | GL 用它防「同一逻辑帧同一份 pairs 被渲染侧再派发一次」；VK 渲染侧不派发碰撞事件，不需要 |
| **未核**：VK 侧 `update_audio` 在真机（有声卡）下的实际出声 | 未核 | 本门只证明「音频段被调用、AudioSource 语义与 GL 同一份实现」；真出声需实机听。**打包游戏/播放器默认后端是 vulkan**，建议下一次实机测试时专门听一次 |
| **未核**：trigger 分流（`on_trigger_enter/exit/stay`）的事件序列对拍 | 未纳入门 | 本门场景是普通碰撞对；trigger 分流逻辑与 GL 共用同一份 `dispatch()`，语义上不可能分叉，但**没有独立断言**。若要做，给夹具加一个 `is_trigger=True` 的物体即可（下一步补） |
| **未核**：`stay` 事件 | 未纳入门 | 同上：`_any_script_needs_stay` 是共享函数，但门里没有覆盖「持续接触」的第三帧 |
