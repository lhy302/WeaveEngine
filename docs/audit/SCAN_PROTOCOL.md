# Loom 全量源码扫描协议（只读审计，2026-11-07）

> 本文是派发给每个"模块审计子代理"的唯一行为规范。依据桌面两份方法论文档：
> 论如何正确的vibe coding.md（白盒契约/黑盒实现/灰盒验证/人类掌舵）与
> 论如何使用AI自动化工具正确的判断AI给出的黑盒是否符合设计标准.md（粗筛→双向推演→实操闭环）。

## 0. 硬约束（违反即任务失败）

1. 本轮只扫不改：禁止修改任何受跟踪源码/测试/文档；禁止 git add/commit。
2. 禁止"我认为/看起来/应该是/经验上"等不可审计措辞。每条结论必须有：文件:行号 + 逻辑链 + 可执行复现命令 + 实测输出。
3. 能跑就不猜：能用 python -c / 现有测试 / 探针验证的，必须跑并贴输出。
4. 运行测试会重写 tests/_tmp 下的文件：跑完必须 git status --porcelain 自查；若有受跟踪文件被改动，用 git checkout -- <path> 还原并在报告里登记。
5. 不启动会阻塞的 GUI（编辑器长期窗口）。需要真实渲染时用离屏（moderngl.create_standalone_context() + 自建 FBO）或已有 tests/_tmp/ab_gl_vk.py。
6. 不确定就标 P-UNKNOWN 并写"需要什么信息才能定"，不要猜也不要顺手改。

## 1. 三阶段流程（必须按序，缺一步视为未完成）

### 阶段一：粗筛（广度优先）
- 通读你负责模块的全部文件；按"契约/不变量/错误模型/资源边界/并发/边界输入"六类打标签。
- 输出疑似项清单，每项含：编号、文件:行号、标签、初步方向、为什么可疑（一句话，必须指向具体代码事实）。
- 跳过项也要留痕：明确写"这部分我判定为无风险并跳过，理由是 <具体事实>"（防 AI 用"检查过了"糊过去）。

### 阶段二：双向逻辑推演（每个疑似项都做）
- 反手（证伪）：先努力证明"这里没有 bug"。必须枚举全部路径/分支/调用方，不能只看主路径。
  - 成功 → 结论 P-DISPROVED（附：为什么所有路径都不成立）。
- 正手（证真）：再努力证明"这里有 bug"，必须给最小复现。
  - 成功 → 结论 P-PROVED（附：复现命令 + 实测输出 + 触发条件）。
- 两边都失败 → P-UNKNOWN（附：已尝试的探针 + 还缺什么信息 + 建议的下一步探针，最多 3 次）。
- 两边都"成功" → P-CONTRADICTION（说明哪条链有漏洞，禁止两说并存）。

8 段式逻辑链模板（P-PROVED / P-DISPROVED 均必须给）：
1) 位置：文件:行号  2) 契约/预期：应该怎样（引代码注释/文档/设计目标）  3) 路径枚举：所有可能走到的分支  4) 实际行为：代码事实推演  5) 差异：预期 vs 实际  6) 触发条件：什么输入/状态会命中  7) 验证：可执行命令 + 实测输出  8) 影响与等级（P0 安全/崩溃、P1 功能错误、P2 边界/性能、P3 可维护性）

### 阶段三：裁决与留痕
- 给每个疑似项一个四象限结论；统计 PROVED / DISPROVED / UNKNOWN / CONTRADICTION 数量。
- 对 P-PROVED 只写"建议修复方向"，不要改代码。

## 2. 本轮特别关注：修复可能引入的新 BUG

最近一轮为"Vulkan 渲染对齐 OpenGL"改了大量文件（可用 git diff HEAD -- <你的模块文件> 查看）。请逐条审查这些 diff，重点找：
- 默认值改变导致的旧场景行为变化（相机、光照、材质、LOD）；
- 新增 early-return / except 吞异常掩盖错误；
- 资源生命周期（buffer/texture/bind group 重建、缓存 key 失效、内存增长）；
- 状态机（鼠标锁定、UI 捕获、相机模式切换）；
- 条件判断顺序（如先替换占位再判标志）；
- 多后端一致性（同一语义在 GL/VK 两侧是否真的等价）。
每个由 diff 引入的可疑点，标 [REGRESSION] 并附 git diff 片段。

写到 docs/audit/scan_<NN>_<module>.md，结构：
```

## 0. 范围与方法（文件清单 + 行数 + 跑过什么命令）
## 1. 粗筛清单（含跳过项留痕）
## 2. 逐项裁决（P-PROVED / P-DISPROVED / P-UNKNOWN / P-CONTRADICTION）
## 3. 统计（数量表）
## 4. 修复建议排序（按 P0→P3，只给方向，不含代码）
## 5. 需要人类裁决的封闭问题
```
