## 2. scope 参数设计与 D10=A/B 语义保持

**选型：GUI 包装层跳过 agent_command_begin（方案 B）+ dispatch 增显式 `scope='agent'` 缺省参数（方案 A 同时做，供测试/未来调用方显式表达路径）。**

理由：
1. `_invoke_cmd` 的 B4 原壳语义 = 直调命令函数（不进 dispatch）——UI 树 4 处调用点要"逐位不变"，动 dispatch 会改变它们的日志/错误契约；
2. `dispatch` 的 agent_command_begin 包裹是 D10=A 的"agent 命令单位"判定，GUI 点击不是 agent 命令单位，从源头（包裹本身）跳过比"进去了再摘出来"干净；
3. 作用域还需要被**命令函数内部**读到（scene_save 白名单放行、object_add 自动聚焦限 agent），故加 `_CMD_SCOPE` 栈 + `current_scope()`：dispatch 按 scope push/pop，`_invoke_cmd` push('user')；命令只跑 Qt 主线程（HTTP 经 QTimer drain 回主线程），栈式嵌套安全。

**D10=A 保持证明（门 B1/B2，真调 editor.undo.UndoManager）**：
- agent_batch_begin（lease_s=0）后 GUI `_cmd_add`：`batch_size==0`（不吸批）、`undo_stack +1`（单独压栈）、`in_agent_command is False`、批归属仍 'agent'（_split_batch_for_user_edit 重开保 owner）；
- GUI 数值行会话批：`batch_owner=='gui'`、`in_agent_command is False`——**GUI 批不是 agent 批**（无租约、不经 agent_batch_begin）；agent_batch_begin 在 GUI 批激活时仍走防悬挂自动让位语义。

**D10=B 不破坏证明（门 B3）**：批内 `dispatch('undo')` → ok=False + blocked=True + last_refusal 落字；agent_batch_cancel 后恢复。registry 的 begin_batch 只**追加**缺省参数 `owner='agent'`，cmd_agent_batch_begin 的 TypeError 兼容分支不受影响（test_undo_batch / test_beta3_batch4_undo_lease 全绿）。

## 3. 相机命令进撤销栈（裁定②，T2）

- `EditorApp.set_orbit_view(target/distance/yaw/pitch)`：与 `set_camera_projection` 同款——先 `_orbit_view_state()` 快照 → 写入（pitch 钳 [-1.55,1.55] 与旧 cmd_camera_look 一致）→ 有变化才 `undo.push(_OrbitViewCommand)`（do/undo 走同一条 `_apply_orbit_view`，钳制只在写入路径，命令只持有两组值）。
- `cmd_camera_move`/`cmd_camera_look` 改走 set_orbit_view；无该方法的旧桩走直接写兜底（与 cmd_camera_proj 兜底同款，test_agent_commands 的 FakeEditor 不受影响）。
- **脏判定不跟随**：视角是编辑器视图状态（_scene_digest 口径，2026-11-08 批2 注）→ 门 C1 实测 camera_move 前后场景摘要逐位相等；对照 camera_proj 改 ortho 摘要变化（D7=A 先例不回归）。
- **右键轨道/WASDQE/滚轮/中键平移老链路不动**：门 C2 直接调 `ed._update_camera()`（editor 事件处理函数）——视角/目标/距离都变了且撤销栈深度不变（防回归断言）。

## 4. 附带发现（范围外，未修，已报 lead）

**引擎既有缺陷：相机挂相机崩**——`reparent` 命令 camera→camera 分支（及 GUI 层级树相机拖到相机行的旧直调路径，修前同样崩）在 `loom_camera.set_camera_parent:263 → world_rotation_matrix`（`components/transform.py:329`）取 `m.rotation`，而 CameraState 是 yaw/pitch 制 → `AttributeError`。修前 GUI 直调路径就是坏的（Qt 事件回调吞异常），命令化后两路同源同失败，门 A6 以"两路同失败、状态/撤销栈零变化"锁定等价性。修复需按 JVM 纪律单独立项。
