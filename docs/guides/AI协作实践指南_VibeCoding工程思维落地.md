## 〇、一句话总纲

> **人类白盒定契约与路线，AI 黑盒填实现，独立验证判断对齐，逃生门保底，工程路线由人类拍板。**

在本项目里，这句话具体展开为六条可执行纪律（对应理论文档的六层）：

| 层 | 本项目落地形式 |
|----|--------------|
| 白盒（人类） | 规则/红线/逃生门/验收口径，写在交接文档与需求里 |
| 黑盒（AI） | 算法/数据结构/优化手法，人类不审查内部 |
| 灰盒（观察） | `LOOM_PROFILE` 插桩 + `tests/_tmp/` 探针 + 压力场景 |
| 验证（判断） | 脚本式回归 + 逐位对拍 + Unity 差分 + 实测小游戏 |
| 运行时（保底） | `LOOM_NO_*` 逃生门 + 自然降级 + 容错 |
| 决策（人类） | 每个分叉口列选项+风险，人类显式选择 |

---

## 一、白盒层：人类定契约（本项目怎么做）

### 1.1 契约在本项目的四种载体

1. **交接文档**（`docs/guides/Loom_E重构交接文档.md`）——最权威的白盒。含方法论、红线、陷阱、回滚点。
2. **需求对话**——人类当轮下的指令（如"按你给出的优先级补全"）。
3. **逃生门命名约定**——`LOOM_NO_*`（见 1.3）。
4. **验收口径**——"逐位一致""回归全绿""位姿 0 差异"。

### 1.2 人类必须定义、AI 不得擅自决定的白盒项

- **行为红线**：如 `advance_logic` 的逃生门分支、逻辑线程仅限 Qt 宿主（交接文档已列）。
- **数值口径**：对齐 Unity 的数值必须逐位或按容差一致（§5.1 锚点）。
- **改动范围**：纯搬家禁止改逻辑；外科手术式修改，禁止"来都来了"。
- **风险偏好**：低风险优先（有现成 C 接口/缓存可加即做），高风险记录待批次。

### 1.3 逃生门：本项目的白盒安全边界（重要）

**每个优化/功能改动必须带逃生门**，这是人类预设的"回退路径"。已建立的命名：

| 逃生门 | 作用 |
|--------|------|
| `LOOM_NO_BATCH_PHYS=1` | 物理摩擦段回退逐体路径 |
| `LOOM_NO_FRUSTUM=1` | 关闭视锥剔除 |
| `LOOM_NO_SHADOW_CACHE=1` | 关闭阴影 VP 静止缓存 |
| `LOOM_NO_PBR=1` | 全局关闭 PBR（回 Blinn-Phong） |
| `LOOM_NO_CKERNELS=1` / `LOOM_NO_PIPELINE=1` | 关 C 内核/管线 |
| `LOOM_NO_SPLIT=1` | 关逻辑/渲染分离 |

**规则**：新改动若无法安全回退，必须先在对话里向人类说明并获得确认。

## 二、黑盒层：AI 填实现（本项目怎么做）

AI 负责、人类不审查的：

- 算法与数据结构（如导数法 TBN、Gribb-Hartmann 平面提取、降位深压缩）
- 性能手法（桶键缓存、批量 C 打包、SoA 平面）
- 内部函数拆分与命名

**约束**：内部实现必须满足白盒契约（红线/数值口径/逃生门），但不要求人类理解每行。

---

## 三、灰盒层：观察但不完全控制（本项目怎么做）

### 3.1 插桩

- `LOOM_PROFILE=1` 开启阶段耗时插桩（`_profile` / `_prof_add`）。
- 看热点用 `tests/_tmp/prof_*.py` 系列。

### 3.2 探针（`tests/_tmp/`，永久保留）

- 命名约定：`probe_*`（调研）、`prof_*`（性能）、`verify_*`（验证）、`dbg_*`（调试）。
- **探针是资产**：它们记录了"当时怎么判断的"，压缩对话后是唯一线索。
- 探针不入主测试，但随提交入库。

### 3.3 压力场景

`保存/压力测试/` 8 个场景 + 生成器 `tests/_tmp/gen_stress_scenes.py`。改性能相关代码前，先用它们量化。

## 四、验证层：判断是否对齐（本项目怎么做）

### 4.1 测试是脚本式（铁律）

```
py -3.12 tests/xxx.py        # exit=0 为过；末尾 sys.exit(0/1)
```
**禁止 pytest**（会 INTERNALERROR）。新测试照 `tests/test_lod.py` 模板。

### 4.2 验证手段分级（按风险）

| 手段 | 用于 | 本项目实例 |
|------|------|-----------|
| 单元/回归测试 | 所有改动 | 24 个 test_*.py |
| **逐位对拍** | 数值敏感改动 | 物理摩擦段 C 化（maxdiff=0） |
| **集合一致性** | 剔除/筛选类 | 视锥剔除（引擎375=独立复算375） |
| **差分测试** | 对齐 Unity | Unity AlignProject 对照 |
| **实测小游戏** | 端到端 | 收集彩球（发现 2 bug） |
| 边界/非法注入 | 健壮性 | 缺贴图/无效压缩/错误路径 |

### 4.3 防过拟合的落地（本项目的薄弱环节，必须警惕）

⚠️ **最大风险：验证者（AI）与被验证代码（AI 写的）是同一个 AI，探针也由 AI 写。**

缓解措施（尽量遵守）：
- 优先用**独立 oracle**：引擎结果 vs 手算/独立复算（如视锥集合、Unity 差分）。
- 探针尽量"从零复算"而非"调用被测代码自证"。
- 关键改动做**反例回归**（把实测发现的 bug 固化成 `test_*.py`）。

### 4.4 本项目的 oracle 来源（优先级从高到低）

1. **Unity 对照**（最独立）——`E:\UnityAlign\AlignProject`
2. **手算/独立复算**——探针里自己写公式
3. **数学不变量**——归一化、对称、幂等、往返等价
4. **引擎内部缓存对象身份**——弱 oracle，仅作辅助

---

## 五、运行时层：最后防线（本项目怎么做）

- **逃生门**（§1.3）——环境变量一键回退。
- **自然降级**——无贴图绑白纹理、无 LOD 零开销、DLL 缺失静默回退。
- **容错**——贴图文件缺失跳过、无效参数回退默认、`try/except` 保护非关键路径。
- **断言**——`mesh._validate` 等开发期校验（不关 `-O`）。

---

## 六、决策层：人类掌舵（本项目怎么做）

### 6.1 必须让人类决策的分叉口

- 工程路线（如"静态层分离做不做""物理写回段是否攻坚"）
- 优先级排序（如"PBR vs 压缩先做哪个"）
- 风险接受度（如"中等风险改动要不要现在做"）
- 数值对齐口径（如"容差多少算对齐"）

### 6.2 AI 的标准动作：列选项 + 风险 + 建议，等人类选

本项目范例（照此执行）：

```
【数据】量化收益/成本
【候选】A/B/C 三条路，各列风险等级与工作量
【我的建议】倾向 X，理由……
【请你定】你选哪个？（不要自己拍板）
```

### 6.3 禁止行为

- ❌ 默默选完路线，只给结果
- ❌ 用"我建议"代替"你决定"
- ❌ 把高风险改动的决定权揽到自己身上

### 6.4 人类决策的记录

每次人类拍板后，写进提交信息或交接文档（如"接受暂缓静态层"），作为后续一致决策的依据。

## 七、每轮工作的标准闭环（照此执行）

```
1. 【白盒】读需求 + 交接文档，确认红线/验收口径/逃生门
2. 【调研】先读代码 + 探针量化（不猜）；不确定就向人类提问
3. 【决策】若遇分叉口 -> 列选项+风险 -> 人类选
4. 【实现】黑盒填充，带逃生门，外科手术式修改
5. 【验证】语法 -> 对拍 -> 回归 -> 边界/反例；高风险做差分
6. 【提交】还原运行时文件 -> 暂存 -> 提交（信息含为什么）
7. 【记录】更新交接文档（关键决策/踩坑/回滚点）
8. 【实测】端到端跑一遍（小游戏/压力场景），找 bug
```

## 八、红线清单（违反即返工）

1. 禁止 pytest；用 `py -3.12 tests/xxx.py`
2. 禁止用大段 edit 删方法群（用临时脚本 + 从后往前删）
3. 提交前必须 `git checkout --` 还原运行时文件（`editor_state.json` 等）
4. 纯搬家禁止改逻辑；性能改动禁止改数值口径
5. 性能改动必须带逃生门
6. 提交信息里的 `%` 在模板字符串里要写 `%`（曾多次误写 `%%`，用 `--amend` 修）
7. 验证探针与被测代码同属 AI 可写域时，必须显式声明"这是弱 oracle"
8. 遇到分叉口必须问人类，不得自行拍板

## 九、成熟度自评（本项目当前水平）

| 等级 | 状态 |
|------|------|
| L0 固定用例测试 | ✅ 已达（24 个 test_*.py） |
| L1 隐藏随机合法输入 | ⚠️ 部分（对拍/集合一致性，非随机） |
| L2 隐藏非法与边界输入 | ⚠️ 部分（手工设计边界，非系统注入） |
| L3 接口契约与组合验证 | ✅ 部分（回归覆盖接口） |
| L4 对抗搜索与反例回归 | ⚠️ 弱（人工设计 + bug 固化，无自动对抗） |
| L5 关键路径形式化 | ❌ 未做 |
| L6 运行时监控与自动回滚 | ✅ 部分（逃生门 + 容错，无自动回滚） |
| L7 人类掌舵 | ✅ **已达**（决策层贯彻到位） |

**结论**：本项目强在 L0/L3/L6/L7（测试、逃生门、人类掌舵），弱在 L1/L2/L4/L5（随机验证、对抗搜索、形式化）。

**下一步可提升**：把 L4（对抗搜索找反例）和 L2（系统化边界注入）做成可复用工具。

## 十、给接手 AI 的交接提示

1. **先读两份文档**：本文件 + 《Loom_E重构交接文档.md》。
2. **所有假设都用代码验证**，不猜；探针写到 `tests/_tmp/`。
3. **遇到分叉口，停下来问人类**（列选项+风险，等选择）。
4. **每个改动都问自己**：逃生门在哪？数值口径变了吗？回归覆盖了吗？
5. **压缩对话后**：本文件 + 交接文档是你的全部上下文来源，探针是你的证据库。
