> **开发阶段声明（2026-11-08，对所有后续 Agent 生效）**：当前全部开发都是**内测开发**，**没有任何实际用户**。因此：
> ① 破坏兼容性的更新**无需考虑用户影响**，不必为迁移旧数据/旧配置/旧存档额外设计或兜底；
> ② 遇到「要不要为兼容加设计」的分叉，默认选**直接改、不迁就**；
> ③ 已实现的旧格式迁移/备份代码可以保留（已有测试覆盖，删了反而多一次改动），但**不要**再新增同类兼容负担；
> ④ 版本号只是内部开发标识（引擎 `0.1.0.beta4`、LoomHub `0.1.2`），不是对外的兼容承诺；
> ⑤ **版本号 = 正在开发的版本号**：开发期间内部代号一直不变（当前引擎 `0.1.0.beta6`、LoomHub `0.1.4`），
> **该版本线真正发包之后**才跳到下一个号（beta6→beta7、0.1.4→0.1.5）。两条线独立：引擎发包只跳引擎的号，Hub 发包只跳 Hub 的号。
> 维护规则：新增文档必须在下方对应目录登记；归档文档移入 `archive/` 并从主索引移除。

### 本轮要点速览（2026-11-08）

- 修复：8 个批次、37 个受跟踪文件；审计基线的 5 个红（`test_hub` / `test_scripts` / `test_render_api` / `test_vk_camera_align` / `test_eai_real`）**全部转绿**

- **发布形态改为「编译版」**：引擎包 = `Loom.exe`（Nuitka standalone）+ `build_game.exe`（onefile）+ 预置运行时 + 可编辑数据目录；**不再带嵌入式 Python 与 .py 源码**（332 MB -> 110 MB）。配方与三个坑见 `handoff/接手总纲…md` §3.2b

- **方法论结论**：`except: pass` / `or True` / 假 `saved:True` 会让此后**所有**审计一起失效（本轮 N1、N3 两次现场证据），故新增硬不变量：不得出现被吞异常
