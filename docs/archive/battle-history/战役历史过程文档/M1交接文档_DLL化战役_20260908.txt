1. 战役一句话 + 关键定案 (v1.3 纯 DLL 架构 — 最重要, 别搞错)
--------------------------------------------------------------------
引擎 = Python 基座 (只写挂载/调度/编辑/场景IO/插件加载/注册表组装)
+ 功能全部拆成 DLL (C ABI 接口)。"DLL 本身就是最好的模块化"。

★v1.3 定案 (用户拍板, 推翻了 v1.1 备胎铁律 — 勿再引入 Python 冗余):
  - 核心组件 = 官方 DLL 唯一实现, 不做 Python 冗余。Python 基座永不
    实现核心功能 (调度/UI/IO 除外)。
  - 兜底只对准用户注入的 DLL: 校验失败 = 弹出; 运行崩溃 = Minidump
    落盘 + 弹出 → 回退官方 DLL。绝不回退到 Python 实现。
  - 搬移 = 绞杀者模式: 对拍逐位 → 验收 → 删旧 Python 实现 (不长期留两份)。
  - M4 脚本 = Lua 5.4 (用户拍板, 弃嵌入式 CPython)。
  - M2→M3 串行; M5 (gui+editor.dll) 置后至 M6 之后; CMake 待 DLL≥4 再迁。

★北极星 (§10.3 三问, 每个架构决策的最终判据):
  ① 让"注入创意"更容易?  ② 让"Agent 操作"更容易?  ③ 坏注入下存活概率更高?
  三问不过不放行; 与性能冲突时方向优先, 但 M2/M3 对拍逐位与 FPS 验收不降。

[√] 3.1 loom_module.h — 契约头 v1.0 (376 行, 中文注释齐全)
    内容: LOOM_MODULE_MAGIC 0x4D4F4F4C ('LOOM' 内存序) /
    ABI 版本编码 (高16主/低16次, LOOM_ABI_MAKE/MAJOR/MINOR) /
    LOOM_MODULE_INFO (magic,abi_version,module_id[64],version[16],
      official(uint32: 1=官方 0=用户注入+信任闸), provides_count,
      depends_count, reserved) / LOOM_TENSOR (data,shape[4],ndim,dtype;
      LOOM_DTYPE_F32/F64/I32/I64/U8) / 错误码 (0=-1容量-2参数-3内部
      -4ABI-5未init-6不支持) / 7 最小导出函数集:
      loom_module_info() / loop_module_provide(i) / module_depend(i) /
      loom_module_init() / loom_module_deinit() / loom_module_abi() /
      loom_module_has(iface) — 均 extern "C", 后三者 typedef 已定义

    铁律已写入注释: 帧内存=基座 arena 预分配 grow-only (DLL 不 malloc);
    热重载=无跨帧隐藏状态 (deinit→FreeLibrary→LoadLibrary→init 零迁移);
    init 可重入 (同一 DLL deinit 后再 init 必须干净重建)。

[√] 3.4 crash_reporter.py — 崩溃落盘 (M1-6 验收通过, 9/9)
    切根: Loom(py源代码-工作区)\Loom\crash_reporter.py + 探针
    tests\_tmp\crash_reporter_check.py (自报告 ALL PASS 9/9, 复跑核实)。
    要点 (写进了模块 docstring, DSH 接读):
      - 不上 Breakpad: 单机开发+MSVC 在场, dbghelp 一次 ctypes 调用即可
      - dump 级别 MiniDumpNormal|WithHandleData(0x4) 手动路径;
        崩溃上下文 (unhandled filter 内进程已损坏) 下加 0x40
        (IndirectlyReferencedMemory) 否则 0x800703E6 被拒, 再降级裸
        Normal(0x0) 重试 — 留证据 > 证据完美
      - filter 回调只做两件事 (备份+Dump, 全包 try/except) 立即返回
        EXCEPTION_EXECUTE_HANDLER; 不在崩溃回调里做复杂事 (再崩=死循环);
        不碰锁 (崩溃时锁可能被别的线程持有→死等)
      - 手动 write_dump(reason) 给 ctypes OSError 路径 (ctypes 把 DLL 内
        0xC0000005 转 OSError 抛给基座 → 基座捕到后调它落盘, 再走弹出
        坏 DLL→回退官方)
      - register_scene_backup(fn) 场景备份闭包; 限流同分钟最多 2 个;
        LOOM_NO_CRASHDUMP=1 逃生门; ctypes 回调持模块级全局引用防 GC
      - ★py3.12 真崩坑 (探针实测): ctypes.string_at(0,4) 被空指针守卫
        静默拦截 (不崩不抛); 裸崩要用 ctypes.c_int.from_address(0).value

[√] 3.5 build_all.bat — 统一构建 (M1-7, 全链验收 EXIT=0)
    位置: Loom(py源代码-工作区)\Loom\build_all.bat
    职责: 锁 MSVC 工具链 → 一键重编全部 DLL (当前: ckernels) → 跑全量
    对拍网 (tests\_tmp 下 *_check.py)。用法: build_all.bat [skip_checks]。
    ★已加 ckernels + 4 个既有对拍探针调用, 实测 ALL PASS EXIT=0。
    【核心坑已写进文件头注释】bat 解析括号坑: 项目路径含括号
    "Loom(py源代码-工作区)", 含括号变量在 if (...) 块内展开会提前闭合
    块结构, 报错 "\Loom\ckernels\build_ckernels.bat was unexpected at
    this time" — 对策: cd /d "%~dp0" 定位后全相对路径; 错误分支用单行
    if ... goto; 不建含括号变量的二次展开。★另一个坑: pushd 后 call
    必须 .\ 前缀 (call "裸名" 在 pushd 上下文不解析)。
    新增 DLL 时: [DLL 清单] 段加 call :build_dll <子目录> <bat名>;
    新增探针: [对拍清单] 段加一行。
