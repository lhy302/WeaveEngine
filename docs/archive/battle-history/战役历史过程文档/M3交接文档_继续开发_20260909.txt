三.5、★收尾时抓到并修掉的回归 (重要, 防复发)
--------------------------------------------------------------------
全量回归曾 FAIL: `collide_val_check.py` IndexError + 物理管线
"逻辑线程同步超时 (1.0s) → 主线程直跑"。
根因: N3 的异步逻辑线程在**无头探针**里也被启动 (探针直驱 advance_logic →
线程启动 → 与探针双驱逻辑帧 + 物理管线)。
**修复**: 异步逻辑线程仅在 Qt 宿主编辑器 (`_external_ctx=True`) 激活;
无头探针/测试一律走同步旧路径 (engine.advance_logic 的 async 分支加
`_external_ctx` 判定)。
修复后: collide_val_check / e2e / aabb_par / world / interp_pose 全部恢复
ALL PASS; 编辑器性能不受影响 (仍 160 fps / paint_total 2.78 ms/帧);
**全量回归重跑 EXIT=0, 21 探针 ALL PASS** (`build_all_run_m3n6_final2_20260909.log`;
[GATE-REGRESSION] on 5.011/off 5.234 PASS; [GATE-FPS] 编译版 +8.9% PASS)。
★教训: 新增后台线程类优化, 必须在"无头探针"与"GUI 宿主"两种形态下都过
全量回归 —— 探针直驱引擎与 Qt 宿主驱动是两条不同的代码路径。

五、继续开发队列 (按预期收益排序)
--------------------------------------------------------------------
Q1. **降低逻辑线程的 GIL 占用** (预期渲染段整体回到 sync 水平, 省 ~0.5-1.0 ms/帧):
    · InterpState.advance 的 _grab (501×3 property 读) —— 可让引擎把
      _transform_snapshot 的平面直接喂给它 (同值, 省一次全量抓取)
    · _aabbs_batched 脏行路径的逐行 Python (m3 gather / Point3D 构造 1002 个/步)
      → 出口改返回 numpy 行表, 碰撞消费者同步改读行表
    · _transform_snapshot 慢路 (逻辑帧必走): 501×3 property 读 + 3 次 numpy 建
      → 评估 "TransformComponent 直接持 SoA 平面" 的重构
Q2. **ctypes 调用摊薄**: interp_world 单次 0.608 ms (C 本体 ~0.17) ——
    差额是 GIL 等待+13 次数组编组。可 (a) 把 loc/parent/depth 等稳定数组
    的指针缓存起来; (b) 评估直接持 CDLL 函数对象 (绕过 get_fn 的 tuple key)。
Q3. **GPU 侧** (需画质取舍, 用户已说 GPU 弱可接受, 优先级降低):
    PCF 3×3=9 taps → 4 taps (视觉略噪); 阴影 1024→512 (可感知)。
    已测算: 阴影 pass 占帧时间 ~26%; 无光源 633 fps。
Q4. **逻辑线程竞态收敛** (N3 已知代价): it.advance 与 render_pose 并发读写
    prev/curr 平面 → 建议改 swap 而非拷贝 (单引用替换, 无撕裂)。
