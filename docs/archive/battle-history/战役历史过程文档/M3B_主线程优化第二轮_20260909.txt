二、逐项改动与实测收益
--------------------------------------------------------------------
[P0] 渲染插值矩阵 → pipeline.dll (engine.compute_render_matrices)
  · 复用已交付的 `pipeline_glue.world_matrices` (同一 C 入口), 逃生门
    LOOM_NO_INTERP_DLL=1, 自检 LOOM_VERIFY_INTERP=1。
  · 数值等价: **1210 帧逐帧对拍 max_abs_diff = 0.000e+00 (逐位一致)**。
  · interp 段 1.186 → 0.739 ms/帧 (−38%)。

[P1] 两处缓存 (均只在结构/状态变化时失效)
  · interp_state.render_pose: argsort(known) 缓存 (键 = _ids 对象身份 + 行数)。
  · engine._render_parent_depth: 父链索引 + 深度缓存 (键 = id(models)/_struct_gen/n)。
  · mt_interp_parent **0.190 → 0.003 ms/帧 (−98%)**; interp 合计 0.739 → 0.528。
  · 数值复验: 1226 帧 max_abs_diff = 0.000e+00。

[P2] 桶分组缓存 (engine._prepare_bucket_frame)
  · 分组只依赖 (结构 stamp, 外观 stamp), 与位姿无关 → 稳态不再每帧跑 501 次
    属性链 + dict 分组。
  · buckets 段 **1.351 → 0.97 ms/帧 (−28%)**。
  · 顺带修测量 bug: `aabbs` 有 3 处绕过 _profile 直接累加 (time.time 口径),
    与包裹层重复计数, 把真实 1.5 ms 虚报成 3.3 ms (现拆为 aabbs / aabbs_inner)。

[P3] 变换快照快速路径 (engine._transform_snapshot)
  · 用 TransformComponent._xform_gen (position/rotation/scale 三个 setter 的
    唯一写入口, 已 grep 核实无旁路) 做"值未变"判定 → 稳态渲染帧跳过 501×3 次
    property 读 + 3 次 numpy 建数组。
  · world_matrices 段 **0.997 → 0.525 ms/帧 (−47%)**。

[P3c] compute_world_matrices 复用父链缓存
  · 原每渲染帧重建 id2i 字典 + Python 循环 ≈ 0.19 ms; 挂父写入全部走
    GameObject.parent property (setter 对活引擎实例 _bump_struct), 缓存失效面完备。
  · world_matrices **0.525 → 0.274 ms/帧 (−48%)**; 旧 parent 数组逐位比较随
    缓存落地冗余, 保留 shape 断言作廉价防御。

[P4] 每实例材质列缓存 (engine._prepare_bucket_frame)
  · sat / rgba 列只依赖外观 (_appearance_gen) → 原每帧 501 次属性链 + 逐行
    标量写, 改缓存 + 向量化整块赋值。
  · buckets **0.911 → 0.468 ms/帧 (−49%)**。
