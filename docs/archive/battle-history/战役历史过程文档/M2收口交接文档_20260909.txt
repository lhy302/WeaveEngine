五、★待用户决策：验收② 定标（三选一）
--------------------------------------------------------------------
定量依据 (权威值):
  · ON 最高核 71.45% ⇒ 每帧 CPU = 71.45% × 13.392 ms = **9.569 ms/帧**
  · 目标 45% ⇒ **6.027 ms/帧** ⇒ **需降 3.542 ms/帧** (降幅 37.0%)
  · 而**主线程自身 8.753 ms/帧已超 6.027**; 物理子步早已在子线程 (culverin C ABI 收益 ≈0);
    三方案推算最优也只到 最高核 约 56-67% (B) / 70-71% (A、C)
  ⇒ 在「每核负载 ≤45%」原判据下, **M2 范围内不可达**; 杠杆在 Qt 事件循环 + GL 提交 +
    Python 胶水 (~8.15 ms/帧 = 8.753 − 0.6)。

选项:
  (a) 改口径: 判据改为「ON 主线程 ms/帧 ≤ OFF」(8.753 < 9.532, 回归闸已 PASS) 或
      「并行度核当量」。**注意**: 核当量 ON 2.41 vs OFF 2.42 无差异 → 核当量口径下②仍不达成;
      只有「主线程 ms/帧」口径能给出达成结论, 且属**改判据**, 须同时改名与留痕。
  (b) 转 M3: 把 Qt/GL 提交 + Python 胶水多线程化/外包 → 唯一能在原判据下真正达标的路径,
      工程量最大 (涉及渲染层重构)。
  (c) 接受现状: ①③④⑤ 达成 + ② **书面转出** (记录不可达的定量依据与杠杆点)。

**建议**: 以 (c) 收口 M2, 同时把 (b) 立为 M3 首个目标; 若必须给 ② 一个「达成」结论,
则选 (a) 并把口径改名为「主线程负载」, 在 M2_权威数字表 与验收报告中同步留痕。
