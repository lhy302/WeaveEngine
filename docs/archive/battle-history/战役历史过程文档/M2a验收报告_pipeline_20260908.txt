四、本阶段发现并修复的真实缺陷
--------------------------------------------------------------------
D1 C 侧 scene_bounds 把行主序矩阵乘写成列优先索引
   (view[0]*cx + view[1]*cy + ... 应为 view[0]*cx + view[4]*cy + ...)
   → 场景包围盒 maxdiff 31.97, 被 pipeline_val_check B 子项逐位对拍当场拦下。
   ★这是「先建对拍网再动代码」的直接价值实证。
D2 热路径函数缺 __declspec(dllexport) (只在契约导出上加)
   → ctypes get_fn 找不到符号; 修复: 头文件引入 LOOM_PIPE_API 宏, 声明与定义同链接属性。
D3 mat4_perspective 初版与 matlib 逐元素不一致 (m[11] 符号/m[14] 表达式)
   → 修正为与 matlib.mat4_perspective 完全同式。
D4 pipeline_glue 缺 core_components 入 sys.path → ModuleNotFoundError 静默降级
   → 修复: 显式插入 CC 与引擎根两个路径。
[子代理发现的观察项, 留 M2b] → 已于第 9 轮修复 (见 M2验收报告 D5)
D5 越界 vis_idx 未返回 LOOM_ERR_PARAM 而是 rc=0/out_kind=-1
   (DLL 无入参范围校验但未崩) → M2b 补边界检查。  （2026-09-09 R4: D5 已于第 9 轮修复, 见 M2验收报告 D5 条目）

五、与总纲 M2 的差异说明 (重要, 已写入设计文档 §2)
--------------------------------------------------------------------
总纲 M2 原文含「物理子步调度」入 DLL。本阶段裁决 **暂留基座 Python**:
  · culverin (Jolt) 是 pybind11 绑定, 非 C ABI, pipeline.dll 无法直接链接
    (规格原文亦写明"需小改 culverin 包装为 C 接口, 两案实施时选");
  · 物理子步调度本身在 Python 侧只占 ~µs, 真正耗时是 Jolt 步进 (C++ 内部, 不占 GIL);
  · prep 链 33.52ms/帧 才是 GIL 热点 → 先吃收益最大、风险最小的一块。
⇒ M2a (本阶段) = prep 链 C 化; M2b (后续) = culverin C ABI 包装 + 物理子步入 DLL,
  并完成「核0 67%→≤45%」的每核负载验收。
