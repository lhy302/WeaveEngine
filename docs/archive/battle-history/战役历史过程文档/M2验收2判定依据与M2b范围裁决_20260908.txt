1. 硬账换算 (为什么 ② 不可能靠 M2 的搬移达成)
--------------------------------------------------------------------
  换算规则: 每帧 CPU ms = busy% × 帧时间, 帧时间 = 1000/FPS (口径: editor_core_check.py --both --secs 12,
  播放稳态 12s; 产物 tests\_tmp\editor_core_verdict_r{1,2,3}.json)
  R1 ON: 帧时间 = 1000/75 = 13.333 ms/帧; 最高核 66.06% → 8.808 ms/帧; 目标 45% → 6.000 ms/帧; 需降 2.808 ms/帧 (降幅 31.9%)
  R2 ON: 帧时间 = 1000/73 = 13.699 ms/帧; 最高核 68.64% → 9.403 ms/帧; 目标 45% → 6.164 ms/帧; 需降 3.239 ms/帧 (降幅 34.4%)
  R3 ON: 帧时间 = 1000/76 = 13.158 ms/帧; 最高核 79.66% → 10.482 ms/帧; 目标 45% → 5.921 ms/帧; 需降 4.561 ms/帧 (降幅 43.5%)
  ON 均值 (n=3): 帧时间 = 1000/74.67 = 13.392 ms/帧; 最高核 71.45% → 9.569 ms/帧; 目标 45% → 6.027 ms/帧; 需降 3.542 ms/帧 (降幅 37.0%)
  已作废: 旧「帧时间 = 1000/78 = 12.821 ms/帧 / 核0 66.2% → 每帧 CPU 8.487 ms / 目标 45% → 每帧 CPU 5.769 ms /
   ⇒ 需降 2.718 ms/帧 (降幅 32.0%)」——基于作废 ON 档 (三轮无一复现), 见 M2_权威数字表_20260908.md。

  而 M2 已搬移的 prep 链在 ON 档只占 ~0.6 ms/帧 (shadow_bounds 0.594ms, 探针 percore_check
  PlayerApp 口径; 与 §1.2 权威 300 帧值 0.584ms 为不同帧数采样, 不作 A/B;
  aabbs/collide 本就在 worker 池, 非主线程独占)。
  已作废: 旧「即便把 prep 链完全移出主线程, 核0 也只能到约 58.0% —— 离 45% 差 13 个点」
  —— 该 58.0% 由作废 ON 档 66.2% 外推; 按 §1.1 权威值, 三轮 ON 差额为 2.808 / 3.239 / 4.561 ms/帧
  (按权威均值口径 3.542 = 9.569 − 6.027; 三轮差额的算术均值为 3.5357, 两者口径不同), 见 M2_权威数字表_20260908.md。

2. 主线程 8.753 ms/帧 的构成 (ON 均值 n=3, editor_core_check 12s 播放口径; M2 无法覆盖的部分)
--------------------------------------------------------------------
  · prep 链 (已 C 化):            ~0.6 ms   ← M2 已交付
  · Qt 事件循环 + paintGL 调度:    Qt 架构锁死主线程 (报告结论三)
  · GL 提交 (桶准备/VAO/uniform):  架构锁死主线程
  · Python 胶水 (interp/脚本/dispatch/_logic_frame 编排): 持 GIL
  ⇒ 这四项占 ~8.15 ms/帧 (8.753 − 0.6, ON 均值 n=3 口径; 旧「~7.4」基于作废 8.038), 属 Qt/Vulkan 层改动与基座编排重构, **超出 M2 范围**。

--------------------------------------------------------------------
3. 裁决 (本阶段结论)
--------------------------------------------------------------------
  · M2 (pipeline.dll) 的交付面 = 逻辑帧 prep 链 C 化, 已 100% 完成并逐位对拍。
  · 验收② 的 45% 目标**不由 M2 承担**: 它是 Qt/GL 主线程架构问题。
  · 故 M2 的验收状态判定为: ①③④⑤ 达成, ② **转 M2b/M3+ 范围**
    (总纲 §六 原文 M2 验收含 ②, 但实现上 ② 的瓶颈不在 M2 的搬移对象;
     此差异已记录于 M2验收报告 §五「与总纲 M2 的差异」)。
  · M2 可判定为**完成** (交付面完成 + 三条可达成验收全过 + 差异已书面裁决)。

4. M2b 候选路线 (供下一步决策)
--------------------------------------------------------------------
  a) culverin C ABI 包装 → 物理调度离主线程
     预期: 主线程可再降 ~1-2ms (物理回读/调度), 核0 → 约 50-55%, 仍不足 45%。
     【已校正】该预期不成立 (调度/回读已在物理子线程), 收益按 M2b可行性评估_culverin_ABI_20260908.txt §1.4/§三
     下调为 ≈0, 最高核 71.45% → 约 70-71% (ON 均值 n=3, editor_core_check 12s 播放口径)。
  b) 渲染提交/胶水段外包 → 需 Qt/Vulkan 层改动
     预期: 这才是 45% 的关键, 但属 M3+ (render_prep.dll / Vulkan 后端) 范畴。
  c) 接受 ② 重新定标: 把「核0 ≤45%」改为「主线程每帧 CPU ≤X ms」或
     「进程总并行度 ≥N 核当量」(ON total 均值 241.65% = 2.42 核当量, OFF 264.46% = 2.64;
     editor_core_check 12s 播放口径, tests\_tmp\editor_core_verdict_r{1,2,3}.json)。

     < OFF 264.46%, 且 ON 自身 s=53.69pt; 09-07 产物 tests\_tmp\tps_fps_core_result.json
     实测 total=194.8%、核0=63.8%; 见 M2_权威数字表_20260908.md。
