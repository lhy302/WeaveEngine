★数值口径的两次校正 (重要, 已写入设计文档 §4):
  · 首次实测发现「场景包围盒逐位 0」是随机数凑巧 — numpy `corners @ view`

    矩阵乘法 ≤1 ULP**, 并新增 `loom_pipeline_mat4_mul_ref` 钉死该界。

    AABB/碰撞对逐位」。

--------------------------------------------------------------------
五、与总纲 M2 的差异 (边界裁决, 已写入设计文档 §2)
--------------------------------------------------------------------
总纲 M2 原文含「物理子步调度」入 DLL。本阶段裁决 **暂留基座 Python**:
  · culverin (Jolt) 是 pybind11 绑定, 非 C ABI, pipeline.dll 无法直接链接
    (规格原文亦写明"需小改 culverin 包装为 C 接口, 两案实施时选");
  · 物理子步调度本身在 Python 侧只占 ~µs, 真正耗时是 Jolt 步进 (C++ 内部);
  · prep 链才是 GIL 热点 → 先吃收益最大、风险最小的一块。
碰撞对: 其 SAP 内核 (loom_collide_pairs) 已在 M1 前的 ckernels 落地并在线;
  本阶段实测其输出与 Python 段位**逐位一致** (100 帧), 故未重复搬移,
  仅确认口径 (决策记录见台账)。
