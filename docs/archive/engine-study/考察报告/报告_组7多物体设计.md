## 二、设计选项（按收益/风险排序）

### 选项 1【头号，强烈推荐】物理桥 ensure_models 去 O(N²) — 查找表化

- **改什么**：physics_bridge.py:783-787 的 `next(...)` 线性扫，改为循环外一次建 `by_model = {}`（按 entries 原序 `setdefault(id(e['model']), e)`，保持“取第一个匹配”语义——每模型至多一个 entry，与 next() 等价），循环内 O(1) 查。
- **预期**：physics 22.84 → **约 8-11ms**（省 10-15ms/帧@500 球）。收益随 N 平方增长，N 越大越值钱。
- **失效路径**：仅当 `_entries` 里出现同一模型两个 entry 才不等价——`_build_one` 只在 ent is None 时调用、ensure_models 移除时同步清 `_last_sync`，重复不可能；用 `setdefault` 保守取首个，与 `next()` 逐位同语义。
- **契约边界**：不改任何 pre/post/睡眠语义；created/destroyed/rebuilt 计数与重建顺序不变。

### 选项 2【头号靶正解】AABB 矩阵指纹缓存（设计 A 改良版：不用 setter 置脏）

- **改什么**：engine.py `_model_aabbs_par` 外层加引擎级缓存（照抄 `_transform_snapshot` 的 stamp+钉住模式，engine.py:2477-2522）：
  - 缓存体：`{'stamp': (id(models), _struct_gen, len), 'mesh': [id(mesh), id(mesh.vertices)]×n（钉住两个对象）, 'mat': (n,4,4) f64 当帧矩阵副本, 'mn'/'mx': (n,3), 'all': 全量 Point3D 列表, 'vis': visible 过滤列表}`；
  - 每帧：stamp 对上 → `changed = np.any(fw != cache['mat'], axis=(1,2))`（501×16 次比较，~10µs）+ mesh/顶点列表身份比对 → **全未变则直接返回缓存列表对象**（Point3D 不可变、消费方只读，可共享）；有变的行才重算（子集走 `_aabbs_batched`，n<512 自动串行 njit 不碰 numba 池）。
  - `_scene_light_bounds_par` 角点循环同步改成从 mn/mx 数组 np.repeat/tile 向量化（消第 6 项 1-2ms）。
- **为什么不用 setter 置脏（设计 A 原案）**：变换 setter 只存在于 GameObject 委托层，`m.transform.position=` 直写现在没人用但**不设防**（与 `_bucket_key` 的 params 原地 mutate 备案同类边界）；父子树还要做子树级联置脏。矩阵指纹直接比对**最终世界矩阵**，脚本/物理/动画/挂父/直写 transform 任何路径改了位形都会现形，数学上“矩阵逐位相等 ⟹ AABB 逐位相等”，零漏报零误报，是唯一无需契约辩护的方案。代价仅 64KB 矩阵副本 + 每帧一次向量比较。
- **预期**：播放态 500 球（80% 静止+20% 旋转脚本）：aabbs 11.02 → **约 2.3-2.5ms**（省 ~8.6ms）；编辑器态（无物移动）：11.02 → **约 0.2ms**（省 ~10.8ms）。附带修掉编辑器点击卡顿（`_pick` 改读缓存行，editor.py:329 一行改）。
- **失效路径**：① mesh 换/params 热改 → `spec_to_mesh` 重建新 Mesh，id(mesh) 变 → 行失效 ✔；② `mesh.vertices` 原地改列表 → 顶点列表身份比对（与 `_homogeneous_vertices` engine.py:2712 同款防御）✔；③ **id 复用** → 必须把 mesh 与 vertices 对象钉在缓存里（照抄 engine.py:2490-2498 铁律）✔；④ 非法路径裸 `models.append` 不 bump → len/stamp 兜底（与 snapshot 同）✔；⑤ 旋转球每帧矩阵都变 → 永远 miss 永远重算（正确但无收益，见未决问题 3）。
- **契约边界**：返回对象从“新建”变“共享缓存”——消费方全部只读（已核实 4 个消费点）；线程安全：缓存决策在调用方主线程做，pool 分块仍只包 `_aabbs_batched`（其 thread-local staging 本就线程安全）。
- **★子坑必须一起处理**：改动行重算时子集大小 n 每帧不同，现堆叠缓冲按 `(gi,n,V)` 键各存一份 → 最坏 O(N²·V·32B) 内存爆炸。改**grow-only**：每 (V 组， 线程) 一份按最大 n 分配、`[:n]` 切片视图（前导轴切片保持 C 连续，njit 直接受）。上限 500 球时 ≈32.6MB/组/线程。

### 选项 3【推荐】碰撞 broadphase：triu 之前 AABB 粗筛

- **改什么**：engine.py:3364 triu 之前，用已选 2 的缓存 AABB 数组构造粗筛盒（box→bmn/bmx；sphere→`scn∓rad`，见取证 5 的安全性证明），按 lo[:,0] 排序 + searchsorted 扫掠剪枝 → 幸存对再进 triu/related/overlap。估计对数超阈值（如 >5 万）则整段回退现 triu 路径（行为不变）。
- **预期**：500 球间距 2.0 半径 0.8 → x 区间互不重叠 → 125,250 对 → **≈0 对**：省 triu 分配 2MB + related 4 次 125k gather + overlap_vec + 线程池分块 ≈ **5-8ms/帧**（shadow_prep 33.52 → 约 26-28ms）。
- **语义**：粗筛盒是每对碰撞体的几何超集 ⇒ 剪掉的对必不满足 `_pair_overlap`（三种形状组合均成立）⇒ 返回对集合逐位相同。**不得**按 motion type 跳 static-static（会改“静态体+脚本”的事件语义，见取证 5）。related 过滤挪到幸存对上，逐对独立、结果不变。
- **失效路径**：粗筛实现 bug（排序键/开闭区间）——用对拍测试兜底（见第四节）；pair 列表顺序可能与旧版不同（`_dispatch_collision_events` 建 set，顺序不敏感，但需核对测试断言是否 sorted 比较）。

### 选项 4【二档】基元解析 AABB（设计 B，与选项 2 叠加）

- **改什么**：对 `mesh.primitive in {'cube','sphere','plane'}` 且当帧矩阵**旋转块恰为单位阵（逐位）**的物体，AABB 闭式求解：8 局部角点（±size/2 / ±r / 平面）经 S@T 变换取 min/max——IEEE 单调性论证下与顶点路径**逐位一致**（取证 3 的局部 AABB 是精确的；乘加单调传递）。旋转块非单位阵 → 回落顶点路径。挂在选项 2 的缓存 miss 行上。
- **预期**：选项 2 已把静止球打到零，选项 4 的增量场景 = “大量平移无旋转的动态体”（下落球海）：每物体 O(1) 替代 2035 顶点变换，此类场景 aabbs ~11ms → <0.5ms。**对当前 500 球压测无额外收益**（旋转球不适用、静止球已被缓存命中）。
- **失效路径**：① 非均匀/负缩放 → 用两角取 min/max 天然覆盖 ✔；② 挂父后旋转块非 I → 自动回落 ✔；③ obj 网格无解析式 → 回落 ✔；④ 判定用“实际 fw 旋转块==I 逐位”而非“rotation==0”，浮点 rotation=2π 产生的非精确 I 自动不命中，正确性兜底 ✔。
- **契约边界**：唯一数值风险是“以为精确其实不精确”——必须逐位对拍（下节）后才可合入；建议作为选项 2 之后的独立小步。

### 选项 5【顺带，低成本】杂项 O(N) 消减

- `_prepare_bucket_frame` 材质行写向量化：逐实例 `col_rows[q]=r` 改为按帧收集 `mat._rgba` 引用后一次 fancy 写/或按 id(material) 缓存行（需钉住 `_rgba` 数组对象——color setter 会换新数组，身份可比，engine.py:694-698）。省 ~0.7-1.5ms。注意 **M23 共享材质语义**：同材质多实例必须同值（gather 方案天然保持）。
- post_step 无 DYNAMIC 体时提前于 4 次 numpy 数组读取前早退（physics_bridge.py:937-959 顺序调整）。省 ~0.3ms。
- `_compute_light_vps` 的 visible 过滤列表、`_entry_signature` 暂不动（读字段是语义必需）。
- 播放态 `compute_world_matrices` 快照重建（2.34ms）可做增量 SoA，但收益小、动核心函数，列为低优先。

**合计预期（500 球播放态）**：61.14ms → 约 **30-34ms（30FPS 上下）**；编辑器态 25ms → 约 **12-13ms（≈80FPS）**。两项头号工程 = 选项 1 + 选项 2，占收益 ~70%。

## 三、红线与风险

1. **物理睡眠/唤醒语义（physics_bridge P1 修复 _b①②）一行不动**：`_free` 自由积分（830-846）、策略 R/guard（885-924）、残速死带（1006-1022）、睡眠体速度归零（968-969）、静态→KINEMATIC 销毁重建升级（858-876）。选项 1/5 均为查找等价或早退等价，不触碰这些分支。
2. **static-static 碰撞对不可按 motion type 跳过**：引擎几何碰撞与 Jolt 无关，“静态体+脚本”今天收事件（取证 5）。broadphase 只能做几何超集剪枝。
3. **逐位一致验收标准（D6）**：本项目历次优化以“逐位/1e-7 内”验收（fastpath.py:162-163, aabb_par_check.py 先例）。选项 4 的闭式 AABB 与 broadphase 都必须过逐位对拍；任何“保守放宽 AABB”的捷径（如用局部盒 8 角变换替代顶点云，旋转下最大可差 √3 倍）**明确否决**。
4. **M23 共享材质先例式坑**：材质缓存若按 id(material) 存值，必须处理 color setter 换 `_rgba` 数组对象（engine.py:694-698）——用“钉住数组对象+身份比对”而非假设不变；否则改色不生效（与 `_bucket_key` params 原地 mutate 备案同型风险）。
5. **numba spin 治理成果不可回退**：选项 2 的 miss 行重算子集（如 100 球）必须继续走串行 njit（n<512 闸门，engine.py:3180）；不得为“摊平缓存 miss”把闸门下调或恢复默认 prange。
6. **堆叠缓冲内存**：选项 2 引入变长子集重算，必须同步改 grow-only staging（设计 A 备案），否则键 `(gi,n,V)` 按不同 n 累积可到 GB 级。
7. **id 复用**：一切按 id() 建的缓存键必须钉住对象本体（_transform_snapshot 铁律，engine.py:2490-2498），mesh/mesh.vertices/material._rgba 三处均适用。

## 五、未决问题（需用户拍板或实测确认）

1. **实施顺序拍板**：建议 选项1（物理桥 O(N²)，一处 10 行内改动、收益最大、风险最低）→ 选项2（AABB 矩阵指纹缓存，主工程）→ 选项3（broadphase）→ 选项5 杂项；选项 4 视选项 2 后压测残量再定。
2. **grow-only staging 内存上限**：每 (V组， 线程) 常驻约 32.6MB（500 球满配）是否可接受；不可接受则改“miss 行走逐模型旧路径”（慢 ~2ms 但零常驻）。
3. **20% 旋转球仍每帧重算 AABB**（矩阵每帧必变）：500 球压测 aabbs 11→约 2.3ms 后是否满足；归零需破坏逐位一致（球顶点云旋转后 AABB 本就随采样变），不建议。
4. **编辑器静态帧是否顺带做 world_matrices 结果缓存**（快照命中即整批矩阵复用，编辑器再省 ~1.5-2ms）：动 `compute_world_matrices` 核心函数，收益中等，需拍板。
5. **`_prepare_bucket_frame` 静态帧跳过实例缓冲重写**（GL 侧脏跳过）：可再省 ~1ms，但涉及“帧间缓冲内容假设”，建议单独小步+截图对拍验证。
6. **broadphase 幸存对回退阈值**（估计对数 > 多少回退 triu）取值需实测标定；以及依赖选项 2 先落地的耦合顺序确认。
