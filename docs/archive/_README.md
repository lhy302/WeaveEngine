# 历史归档说明

> ⚠️ **本目录下的文档是"过程记录"，不是"当前设计"。**
> 检索设计资料时请**排除本目录**，只读 `docs/design/`、`docs/guides/` 与 `docs/handoff/`。
> 保留价值：追溯决策来龙去脉、复盘踩过的坑、查看某轮优化的原始取证。

**归档规则**：一个版本发包后，把该版本的 `docs/audit/` 记录与当期交接文档**整体**移入 `archive/v<版本>/`；
被新文档取代的设计移入 `archive/被取代的设计/`。**只增不改，不改写历史记录**。

> **链接注意**：归档文档内部的相对链接指向的是它**原来的位置**，移动后可能失效。
> 需要交叉引用时，请按文件名在 `archive/` 下检索，不要相信文档里的相对路径。

## 从归档里找东西的几条捷径

| 想找 | 去哪 |
|---|---|
| 某个数字/结论**当初是怎么测出来的** | 对应版本的 `scan_*` / `verify*` / `final*` |
| 某个缺陷**修之前的现场** | 对应版本的 `fix_*` / `impl_*` |
| 某个设计**为什么被推翻** | `被取代的设计/` + 当期 `待裁决清单`（已关闭项保留原值与裁决依据） |
| 上一版**怎么跑的、踩过什么坑** | 对应版本的 `接手须知_*` |
