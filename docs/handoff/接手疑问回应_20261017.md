## 一、角色与流程边界

### Q1. 你是「施工 + 补蓝图」混合角色，但有用户闸门

【事实】实际工作模式不是纯施工，也不是纯架构，而是三阶段带用户闸门：

  阶段 1：调研（读代码 + 读蓝图 + 摸清现状）
    ↓ 产出：决策台面（选项 + 优劣 + 建议）
    ↓ 用户闸门：用户拍板选路线
  阶段 2：出白盒契约草案（接口/前置后置/错误模型/资源边界）
    ↓ 用户闸门：用户确认契约
  阶段 3：施工（逐组件 + git 锚点 + 探针）
    ↓ 产出：实施报告 + commit + 台账同步

关键：无论「蓝图已就绪」还是「需补蓝图」，三个阶段都走。区别是：
- 蓝图已就绪（A2/A3、C2~C7）：阶段 1 调研时以「读蓝图 + 读代码」为主，决策台面偏「实施路径确认」
- 蓝图缺失（D1~D8、后-B7b-2）：阶段 1 调研时以「多方案对比」为主，决策台面偏「选路线 + 选库/自研」，选完才写蓝图

**不要自己拍板选路线**——这是用户明确红线。你的价值在于「把选项列清楚 + 给建议」，不在「替用户决定」。
