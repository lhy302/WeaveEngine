# 工程设计失误盘点（2026-11-17，全引擎结构扫描）

> 触发：人类要求「完完整整梳理一遍整个引擎的细节，看看有多少类似『场景版本管理』这样的**纯工程设计失误**」。
> 参照物是 B15/B7-16：不是某行代码写错，而是**职责放错层 / 同一语义多处表达 / 契约与实现脱钩**。

B14（UI 描边深度，只在 GL 侧修；VK 侧是另一套实现，是否同类问题**未核实**）、B5（`VkWorldUIPipeline` 不读 `RasterState`）、B7-14（阴影编码两端不同）
全部是这条根因的产物。它不是「代码重复」问题，而是**没有唯一的语义定义处**。

### D2 时钟参数不传播（真缺陷，已实测）

| 端 | 代码 | 行为 |
|---|---|---|
| GL | `engine.py:478-479`：`split_enabled(_s)` → `clock_from_settings(_s)` | 读 `logic_fps` / `phys_substep_dt` / `physics_fps` |
| VK | `scene_driver.py:594-597`：`split_enabled()` → **`FixedStepClock()`** | 只用类默认值 **30Hz / 1/60s** |

探针（`py -3.13`，把 `guiloader.load_settings` 打桩返回 `{'logic_fps': 60, 'physics_fps': 120}`）：

```
clock_from_settings(用户设置 logic_fps=60, physics_fps=120): 60.0  0.0083333
SceneDriver 实际: 30.0  0.0166667  split= True
=> 用户设 60Hz 逻辑帧，VK 驱动拿到的是 30.0 Hz
```

**反证它不是「有意为之」**：同一个 `__init__` 在 588-590 行**已经**为 `interp_mode` 调了 `load_settings`，
596 行又调了一次拿 `logic_fps<=0` 判定 —— 设置就在手边，却没用它构造时钟。
影响面：设置面板提供 `logic_fps` 20/30/45/60/120 与 `physics_fps` 30/60/120/240（`core_clock.py:166-182`），
**这些档位对 VK 播放器与 VK 打包游戏全部无效**；且 VK 侧没有 `frame_buffer`（TPS 缓冲）实现（`scene_driver.py` 0 命中）。

**为什么没有测试挡住**：`Loom/tests` 里提到 `SceneDriver` 的行有 53 处，其中提到 `_clock`/`logic_fps`/`settings` 的 **0 处**；
时钟测试（`test_core_clock.py`、`test_clock_pause_restart.py`）都只测 `FixedStepClock`/`clock_from_settings` 本身，不测「驱动是否用了设置」。

### D6 序列化函数兼职事务

`sceneio.scene_to_dict(engine, camera=None, ...)`（`:1933`）用「`camera is None`」当**模式开关**：

| 行 | 代码 | 含义 |
|---|---|---|
| `:1985` / `:2001` | `if camera is not None: print(...)` | digest 模式不出声 |
| `:1995-1996` | `sync=(ctx is not None and camera is not None)` | **是否把材质写回资产库**（磁盘副作用）由这个布尔决定 |

后果：想「只算摘要不落盘」就得传 `None`，于是函数里每一处副作用都必须记得用 `camera is not None` 挡住 ——
新增一处副作用忘了挡，digest 调用就会偷偷写盘。这是典型的 T2（纯变换与事务混在一个函数里）。

统计口径：正则抓 `os.environ.get/os.getenv/environ[...]`，只算生产 `.py`（排除 `tests/`）。

| 指标 | 值 |
|---|---|
| 真实环境开关 | **38 个** |
| docs 里提过 | **34 个**（覆盖其实不错，不是「一堆黑开关」） |

### D9 隐式环境态 `_CUR_BASE_DIR`

| 位置 | 动作 |
|---|---|
| `sceneio.py:1367` | 定义 `_CUR_BASE_DIR = None` |
| `sceneio.py:2032` | `scene_from_dict` 里 `global _CUR_BASE_DIR; _CUR_BASE_DIR = base_dir` |
| `scene_driver.py:632` | VK 驱动**也**直接写 `_sio._CUR_BASE_DIR = base_dir` |
| `sceneio.py:1381` | `root = getattr(ctx, 'root', None) or _CUR_BASE_DIR`（资源相对路径解析的兜底） |
| 恢复 | **没有**任何地方在加载结束后还原 |

即：资源路径解析依赖一个「上次谁加载过场景」的全局变量。同一进程里先后加载两个不同目录的场景（编辑器换场景、播放器预热、测试并行）时，
第二次加载期间的相对路径解析会用**第一次**的目录 —— 目前靠「每次都重新赋值」掩盖，一旦有嵌套/异步加载就露馅。

### D11 插件系统：契约无夹具

`plugin_loader.py` 836 行 + `plugin_sandbox.py`（受限 import 白名单/黑名单）是一整套契约（manifest 字段、layer、deps、min_engine、受限执行环境），

### D13 C/Python 两侧 ABI 版本各写一遍

| 侧 | 定义 | 值 |
|---|---|---|
| C | `Loom/core_components/loom_module.h:42`：`#define LOOM_ABI_VERSION_CURRENT LOOM_ABI_MAKE(1, 0)` | (1,0) |
| Python | `Loom/core_components/module_loader.py:68`：`LOOM_ABI_VERSION_CURRENT = loom_abi_make(1, 0)` | (1,0) |
| 文档 | `docs/design/架构互联协议总表.md:40` | (1,0)（第三份） |
| 测试 | `Loom/tests` 里 ABI 断言 | **0 条** |

所有 C 模块（`ckernels`、`pipeline`、`physics`、`script` 等）在自己的导出表里填的是 **C 头里的那个宏**；
Python 加载器校验时用的是**自己那份常量**。两侧同值靠人记，没有任何构建期或测试期对拍。
后果分两档：主版本不一致 → 全部模块被拒（响亮但难查）；**次版本不一致 → 按 `loom_module.h:51` 的判据（只比主版本）会静默放行**，
而次版本恰恰是「语义已变但仍兼容」的那一档 —— 这正是最需要闸门的地方。

| 根因 | 含义 | 条目 |
|---|---|---|
| **G1 同一语义没有唯一定义处** | 语义靠「两边都记得改」维持 | **D1**（引擎门面）、**D3**（场景契约）、**D5**（常量）、**D9**（环境态）、**D10**（项目根）、**D12**（元数据）、**D13**（ABI 版本） |
| **G2 契约/配置没有登记处** | 有声明、无登记、无夹具 | **D4**（插件版本）、**D7**（环境开关）、**D11**（插件夹具）、D12（package_id） |
| **G3 纯变换与副作用混在一个函数** | 用参数当模式开关 | **D6**（`camera=None`）、**D9**（全局隐式参数） |
| **G4 错误处理没有设施** | 静默/上报一次/抛出三套并存 | **D8** |

这条归类解释了为什么「一次修一个」总是修不完：B13/B14/B11/B5/B7-14/B15 全部落在 G1 与 G4 里，
每次都在**具体位置**打补丁，而根因（没有唯一定义处 / 没有统一设施）从未被动过。
