## 一、角色与流程边界

### Q1. 我的角色定位到底是"施工 Agent"还是"架构 Agent"？
- **为什么问**：《下一阶段工程路线分叉与施工交接.md》明确"双 Agent 分离：画架构的 Agent 产出白盒蓝图；施工 Agent 按蓝图推进"。但《接手总纲_B线收官版》又让我"从第三节选 2~4 个方向深入调研，按决策台面模板产出分析"，且 D1~D8 / 后-B7b-2 都要求"先补蓝图"——补蓝图是架构活，按蓝图施工是施工活。我同时被要求做两件事，需要明确边界。
- **期望回答**：二选一或明确分工——(a) 我是施工 Agent，只做"蓝图已就绪"的方向（A2/A3、C2~C7），蓝图缺的方向等架构 Agent 补完再施工；(b) 我是"施工+补蓝图"混合角色，但补蓝图前必须先出"决策台面"让用户选路线，选完才写蓝图。

### Q2. "决策台面"的最终读者是谁？
- **为什么问**：读者决定我用什么语言写。如果读者是项目主人（非技术背景或半技术），我要避免堆术语、多给类比；如果读者是另一个架构 Agent，可以用协议层编号、代码符号。
- **期望回答**：指明读者身份 + 偏好的详细程度（如"给项目主人看，技术细节折叠到附录"）。

### Q3. "后 50 项"的完整编号清单在哪？
- **为什么问**：总纲说"前 50 项 + 后 50 项中的 B 线 + A1/C1 全部已命中；剩 A2/A3、C2~C7、D1~D8、E1~E3、F1/F2"。我数了一下：B1~B7b(8) + A1~A3(3) + C1~C7(7) + D1~D8(8) + E1~E3(3) + F1~F2(2) ≈ 31 项，与"后 50 项"差约 19 项。是编号有跳号（如 B6 被 B2 覆盖），还是有一批方向没写进总纲第三节？
- **期望回答**：给一份"后 50 项完整编号表"（含已命中/未命中/被覆盖/已废弃四种状态），或明确说"编号非连续，31 项即全部"。

## 二、后-B7b-1 移除绑死模式（用户明确单独立项、改动面大）

### Q4. 四个"else 分支"的精确位置和目标态语义？
- **为什么问**：总纲只说"core_clock.split_enabled 的 logic_fps<=0 判定、loom_render.render 的 else 分支、scene_driver.advance_logic 的 else 分支、engine.__init__ 的 _split_enable 短路"，没给文件路径、行号、当前行为、目标行为。我读代码能定位，但"目标态"是设计决策，不能我猜。
- **期望回答**：对每个分支给：(a) 文件:行号；(b) 当前 logic_fps<=0 时走什么路径（绑死模式具体行为）；(c) 期望的替代语义——是"logic_fps<=0 视为非法配置直接报错"，还是"logic_fps<=0 自动取某默认值（如 60）"，还是"删除该判定，logic_fps 恒 >0"？

### Q5. 旧场景/旧存档是否依赖绑死模式？
- **为什么问**：如果历史 .lsc 游戏包或 设置.json 里存在 logic_fps<=0 的配置，删除绑死模式会导致旧存档打不开或行为突变。需要知道是否要做版本迁移。
- **期望回答**：是否有历史配置依赖？若有，迁移策略（自动改写 / 拒绝加载并提示 / 兼容读取）。

### Q6. 测试探针里有没有针对绑死模式的用例？
- **为什么问**：删代码前要知道哪些探针会红，避免"删完发现对拍网大面积失败"。
- **期望回答**：tests/_tmp/ 下相关探针文件名清单（grep logic_fps / split_enabled / 绑死）。

### Q7. 后-B7b-1 与后-B7b-2 是否有先后依赖？
- **为什么问**：两者都动帧调度/渲染结构。如果先做画质分级再做移除绑死，画质分级可能建立在绑死模式之上又要返工。
- **期望回答**：建议的顺序 + 理由。
