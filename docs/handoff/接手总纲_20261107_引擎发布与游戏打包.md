## 1. 运行时架构（先看这张图）

```
入口
  Loom.py --agent --open scene   -> Qt 编辑器（ui/loom_gui.py 的 LoomGUI + EditorApp）
  Loom.py --run scene / 游戏配置.json -> 播放器
      resolve_backend: CLI --backend > 游戏设置.json render_api > 引擎 设置.json > 默认 vulkan
      vulkan -> vk_player.run_vk -> scene_driver.SceneDriver（驱动层：脚本/物理/动画/相机/UI）
      opengl -> runtime.PlayerApp（继承 GLEngine，等同编辑器去掉 UI）
  发布游戏 MyGame.exe -> game_player.py（读 游戏包.lsc，PlayerApp 或 VK 驱动）
```

关键分层：

| 层 | 文件 | 说明 |
|---|---|---|
| 引擎核心 | engine.py + loom_*.py 各 mixin | GLEngine 由 mixin 组合：渲染/输入/物理/相机/脚本/UI |
| 编辑器 | editor.py、ui/loom_gui.py | EditorApp 继承 GLEngine；Qt 视图 + MCP 命令桥 |
| GL 播放器 | runtime.PlayerApp | 只读场景，无编辑器 UI |
| VK 播放器 | vk_player.py + scene_driver.py + vk_renderer.py + vk_ui.py | 独立驱动，与 GL 语义对齐 |
| 脚本 | scripts.py（内置）+ scripts/*.py（游戏脚本，热重载） | 动作层 get_action，避免硬编码键名 |
| UI | loom_ui.py（保留模式 Canvas）+ vk_ui.py（VK 管线/输入桥） | 声明式事件 ui_bind_event -> 脚本方法 |
| 工程配置 | 设置.json（引擎）、游戏设置.json（每游戏）、输入配置.json（键位基线） | 优先级见 §3.4 |

### 2.5 渲染后端切换（每游戏配置，Unity 做法）
- 配置文件：**游戏设置.json**，放在游戏文件夹（= MyGame.exe 同级）；可用环境变量 LOOM_GAME_DIR 覆盖（测试用）
- 键：render_api(vulkan/opengl/auto) / mouse_lock_allowed / mouse_locked / key_bindings
- 解析优先级：CLI --backend > 游戏设置.json > 引擎 设置.json > 默认 vulkan
- Vulkan 不兼容：非显式指定时**崩一次（exit 1）**并把 render_api 写回 opengl（写进游戏配置），下次启动走 GL
- 脚本 API：engine.get_render_api() / get_saved_render_api() / set_render_api(api)（返回 restart_required）
- EAI 命令：render_api {api?}（编辑器侧可查/改）

### 2.6 鼠标锁定 / 键位（用户明确要求的两轮）
- 锁定由配置决定：mouse_lock_allowed（默认 true）、mouse_locked（默认 true）；不允许锁定则每帧强制解锁
- **强制解锁键**：动作名 解锁鼠标（默认 Tab），在 GLEngine.update_scripts / SceneDriver._update_scripts 每帧检测（_poll_mouse_unlock_key），不依赖游戏脚本
- 键位可配置：游戏设置.json 的 key_bindings（如 {"解锁鼠标": ["F10"]}），优先级高于引擎 输入配置.json 与 DEFAULT_ACTIONS
- 改键 API：engine.get_action_bindings() / set_action_binding(action, keys)（立即生效 + 写入游戏配置）；EAI 命令 key_binding
- VK 播放器之前**完全不读键位配置**（打包版改键无效），已补：读引擎配置 + 游戏覆盖
- 键位表补全：_KEYMAP 30 -> 76 键（全字母/数字/F1-F12/Esc/Enter/编辑键/标点）；loom_glfw_window._GLFW_TO_PG 重建为 80 项并与之对齐
- 退出释放：vk_player finally 与 loom_render 主循环退出前都强制释放鼠标捕获（防异常退出把玩家光标锁死）

### 2.7 本轮修掉的引擎级 P0

| 问题 | 根因 | 修复 |
|---|---|---|
| 打包版 Vulkan 玩约 60 秒必闪退 | vk_player 看门狗用的 last_ok 只在启动初始化、渲染循环从不更新 -> 到点 os._exit(9) | 每成功渲染一帧刷新 last_ok |
| 打包版（VK）所有 UI 按钮点不动 | UIManager.draw_all(engine) 把同一个对象既当绘制目标又当脚本宿主；VK 传的是 VkUIEngine（无 .models）-> _ACTIVE_ENGINE 错 -> 找不到脚本实例；且 draw_frame 没把 engine 透传给 draw_ui | draw_all(engine, script_host=None) 分离两者；VkUIEngine 转发 script_host；draw_frame/draw_ui 透传 engine=driver |
| 贴墙推挤会穿到墙另一侧 | _push_out 盒-球分支在球心进入盒内时沿"盒中心->球心"推，越过中心就推向另一侧 | 改为沿最近面推出（与盒-盒最小穿透轴一致） |
| 复活即被秒杀（55 秒被抓 54 次） | 复活点无无敌时间 | invuln 参数（默认 1.5s） |
| 键位改到 F10/Esc 无反应 | _KEYMAP 只有 30 个键，is_key 查不到 | 补到 76 键 + GLFW 映射同步 |

## 6. 已知问题 / 未完成（按重要性）

### 6.1 VK 播放器 UI 命中坐标系不一致（**最该先修**）
- 现象：打包版通关面板能显示，但用合成鼠标点击按钮不触发（编辑器与 headless 路径都正常）。
- 根因线索：场景里的 screen Canvas 尺寸是 1008x935（保存场景时的编辑器窗口），而打包游戏窗口是 1280x800；
  UIManager.dispatch_mouse 用窗口像素坐标与 canvas 坐标直接比较，VK 播放器没有每帧把 screen Canvas 尺寸同步到窗口。
  GL 路径因为编辑器/播放器都会把 canvas 尺寸跟窗口同步，所以不受影响。
- 修复方向：在 VK 播放器每帧（或 resize 时）把 screen Canvas 的 width/height 同步为物理窗口尺寸（对齐 GL 行为）；
  或 dispatch_mouse 前把鼠标坐标按 canvas/window 比例换算。修完请用真鼠标 + 合成点击各验一次。
- 注意：headless 探针（SceneDriver + UIInputBridge，直接给 canvas 坐标）是**能触发**的，说明事件派发链本身已修好，剩下的纯是坐标空间问题。

### 6.2 播放器运行时要随源码重编
任何引擎源码改动都必须重跑 --build-runtime（6-10 分钟）并重打引擎包，否则打包版行为与源码不一致。目前没有版本戳/增量机制；
建议后续：给 player_runtime 写源码哈希，build_game 检测到不匹配时告警。

### 6.3 其它既有已知项（非本轮引入）
- 插件沙箱是进程内弱隔离（_GuardedApi 仍转发下划线属性）
- VK 阴影容量：平行光最多 2 张、点光仅 1 套（第 3 盏起告警）
- Shape 描边非逐像素等价（WebGPU 线宽恒 1px）
- 引擎没有离屏 RenderTexture 型 Canvas
