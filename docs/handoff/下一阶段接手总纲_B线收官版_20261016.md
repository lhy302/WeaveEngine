## 四、施工铁律（违反即返工）

1. **镜像目录安全**：当前是 `D:\my-project`，**绝不写入主机原目录 `D:\my-project`**
2. **逐组件稳定**：一次只动一个组件，崩了能定位
3. **git 锚点**：每次改动前 commit；做不出来 `git checkout` 回退
4. **探针固化**：新探针放 `tests/_tmp/`，**永久保留，禁测完删除**
5. **二值审计**：汇报只用【已命中】/【未命中】+ 物理证据，**禁主观百分比**
6. **契约先行**：实现前先出白盒契约草案（接口/前置后置/错误模型/资源边界）交用户确认
7. **命令行**：优先 Git Bash（`bash -c "..."` 中转），禁裸调 bash
8. **前提先证**：涉及"编译后不可篡改"这类前提断言，动手前先做最小实验（A1 Nuitka 试刀先例）
9. **蓝图偏差检查**：蓝图笼统时真实代码可能有额外维度，先读代码再定方案，**有路线分叉交用户拍板**
10. **commit 分主题**：bug 修复与 feature 分离；预存缺陷不混入主线 commit

### 9.3 关于 GitHub 分发格式的行业惯例（施工前调研）

**GitHub Releases 附件的常见格式**：

| 格式 | 用途 | 用户体验 |
|---|---|---|
| **`.zip`** | 便携包（解压即用）/ 源码包 | 用户需手动解压 + 找 exe |
| **`.exe` (Inno Setup / NSIS)** | 傻瓜式安装包（推荐） | **双击 → 下一步 → 完成**（如 Cuckoo Code 的安装包）|
| **`.msi`** | Windows Installer 标准包 | 双击 → 向导安装，支持组策略批量部署 |
| **`.7z`** | 高压缩比便携包 | 同 zip，但需 7-Zip 解压 |

**常见做法**：
- **引擎本体**：用 `.zip`（跨平台友好，且引擎依赖 Python 环境需二次配置）
- **最终用户产品（Hub）**：用 `.exe` 安装包（Inno Setup 免费且功能足够，NSIS 更轻量）
- **CI 自动构建**：GitHub Actions `workflow_dispatch` 或 `release` 触发 → 构建 → `softprops/action-gh-release` 上传到 Release

**分发路径**（推荐）：
```
GitHub Actions
  → 构建 LoomHub（Nuitka 编译为独立 exe）
  → Inno Setup 打包为 installer.exe
  → 上传到 GitHub Release 附件
  → 用户下载 installer.exe → 双击安装
  → LoomHub 内拉取引擎 zip（另附一份到 Release）
```
