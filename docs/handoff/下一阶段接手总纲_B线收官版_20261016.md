### 3.6 LoomHub 分发体系（排在其他所有任务之后）

**用户明确**：这是最后做的工程任务，等引擎本体稳定、可发布真实版本时再启动。

**目标**：让最终用户傻瓜式安装整个生态（Hub + 引擎本体），无需手动配 Python / 依赖。

**最终用户体验**：
1. 用户下载 LoomHub 安装包（GitHub Releases 附件）
2. 双击安装（标准 Windows 安装向导）
3. LoomHub 启动，检测本机未安装引擎 → 弹窗询问
4. 用户确认 → 自动从 GitHub Releases 拉取引擎 zip → 解压 + 校验 SHA256 + 配置路径
5. 完成，用户可直接在 Hub 里选项目开玩

**需要实现的功能**：

| 编号 | 功能 | 说明 |
|---|---|---|
| H1 | 自身更新检测 | 启动时调用 GitHub API 检查 Releases 是否有新版 |
| H2 | 引擎分发 | 从 GitHub Releases 拉取引擎包（zip 优先），进度条展示下载 |
| H3 | 引擎安装辅助 | 用户授权 → 解压 → 校验 SHA256 → 注册到 `interpreters.json` |
| H4 | 版本管理 | 支持安装多个引擎版本（稳定版 / 预览版），Hub 内切换 |
| H5 | 失败兜底 | 网络断 / 磁盘满 / 校验失败 → 明确报错 + 重试 + 回滚 |
| H6 | 安装包制作 | LoomHub 自身打包为 .exe 安装包（Inno Setup 或 NSIS）|

**前置依赖**：
- 引擎能产出可独立分发的 zip（含 Python 运行时 + DLL + 资源）——现有 `build_game.py` / `build_entry.py` 需确认
- `.github/workflows/` 新建（CI 构建 + Release 上传）

**施工步骤建议**：
1. 先补蓝图 `docs/design/LoomHub分发体系设计.md`（定义接口契约）
2. 小步验证：先做 H1 + H2，跑通最小闭环
3. 再做 H3~H5（安装 / 版本 / 兜底）
4. 最后 H6（Inno Setup 打包 + GitHub Actions）
5. **等引擎稳定后打第一个 Release**（必须由用户明确拍板）

**红线**：
- 引擎主仓库里只放设计文档，Hub 代码改动在 `LoomHub/` 目录
- 不自作主张发版
- 不引入网络依赖到引擎本体（Hub 才做网络；引擎保持离线可运行）

## 四、施工铁律（违反即返工）

1. **目录安全**：本地开发用镜像目录 D:\my-project - 副本，**绝不写入主机原目录 D:\my-project**。（如在 GitHub 克隆的仓库里接手，此条不适用）
2. **逐组件稳定**：一次只动一个组件，崩了能定位
3. **git 锚点**：每次改动前 commit；做不出来 `git checkout` 回退
4. **探针固化**：新探针放 `tests/_tmp/`，**永久保留，禁测完删除**
5. **二值审计**：汇报只用【已命中】/【未命中】+ 物理证据，**禁主观百分比**
6. **契约先行**：实现前先出白盒契约草案（接口 / 前置后置 / 错误模型 / 资源边界）交用户确认
7. **前提先证**：涉及「编译后不可篡改」这类前提断言，动手前先做最小实验
8. **蓝图偏差检查**：蓝图笼统时真实代码可能有额外维度，先读代码再定方案，**有路线分叉交用户拍板**
9. **commit 分主题**：bug 修复与 feature 分离；预存缺陷不混入主线 commit
