# 用户配置目录契约（2026-11-08 定稿，第 0 批修复的地基）

> **开发阶段声明（2026-11-08，对所有后续 Agent 生效）**：当前全部开发都是**内测开发**，**没有任何实际用户**。因此：
> ① 破坏兼容性的更新**无需考虑用户影响**，不必为迁移旧数据/旧配置/旧存档额外设计或兜底；
> ② 遇到「要不要为兼容加设计」的分叉，默认选**直接改、不迁就**；
> ③ 已实现的旧格式迁移/备份代码可以保留（已有测试覆盖，删了反而多一次改动），但**不要**再新增同类兼容负担；
> ④ 版本号只是内部开发标识（引擎 `0.1.0.beta4`、LoomHub `0.1.2`），不是对外的兼容承诺。
>
> 对本契约的直接含义：§6「旧格式迁移」与 §5 的「迁移失败备份」**不是**为真实用户做的兼容承诺，
> 只作为「防止本机开发环境把自己搞坏」的保险。将来若迁移逻辑成为负担，可直接删掉、改为「不认识就重置」。

> 依据：beta3 回补审计 `docs/audit/_scan_beta3_summary.md` §6.0 D5/D9 的人类裁决。本文件是**白盒契约**，实现必须满足；实现完成前不得改动依赖它的上层修复。

## 0. 问题

当前所有运行期配置都写在"程序旁边"（`guiloader.program_dir() = dirname(sys.argv[0])`）：
- 引擎装到 `C:\Program Files\Loom\<版本>\Loom\` → `设置.json` / `输入配置.json` 不可写（ACL: Users=RX；64 位进程无 UAC 虚拟化）；开发机全程"以管理员运行"，把问题遮住了。
- LoomHub 装到 `C:\Program Files\LoomHub\` → 同样不可写。
- 打包游戏放只读目录 → `游戏设置.json` / `日志.txt` 写不了。
- 测试进程 → 落在 `Loom/tests/`，已实测把 `test_render_api.py` 弄红；并会在每次跑测试时改写**受跟踪**的 `Loom/输入配置.json`。

## 1. 分层契约

| 层 | 位置 | 写者 | 语义 |
|---|---|---|---|
| **默认模板层** | 发布夹/引擎目录里的同名文件（`设置.json`、`输入配置.json`、`游戏设置.json`） | 构建产物 / 开发者 | **只读**；引擎运行时**永不写**；随版本更新自动生效 |
| **用户层** | `%LOCALAPPDATA%\Loom\…` | 运行时 | 只存"用户改过的键"（delta） |
| **备份** | 用户层同目录 `*.bak-<yyyyMMdd-HHmmss>.json` | 迁移/损坏时 | 留证，不丢数据 |

**不做便携模式（Q4=B）**：不识别 `portable.flag`，一律用户目录。

## 2. 路径规范（单点收口）

新增 `Loom/userpaths.py`（**唯一**允许拼用户目录的地方）：

```python
def user_root() -> str:            # %LOCALAPPDATA%\Loom  (无 LOCALAPPDATA 时回退 ~/.loom)
def engine_settings() -> str       # <root>\engine\settings.json
def hub_settings() -> str          # <root>\hub\settings.json
def game_settings(game_id) -> str  # <root>\games\<game_id>\settings.json
def project_settings(pid) -> str   # <root>\projects\<pid>\settings.json
def log_path(app) -> str           # <root>\logs\<app>\日志.txt
def backup_path(path) -> str       # 同目录 <name>.bak-<时间戳>.json
def ensure_dir(p) -> None          # makedirs(exist_ok=True)
```

**禁止**在这 8 处调用点各自拼 `%LOCALAPPDATA%`：`guiloader`、`game_settings`、`loom_input`、`run_player`、`scene_driver`、`engine`、`game_player`、`LoomHub/hub_config.py`。全部改为调 `userpaths`。

**`LOOM_GAME_DIR` 仍为最高优先级的强制覆盖**（测试与调试用）；另新增 `LOOM_USER_ROOT` 覆盖 `user_root()`（测试用）。

## 3. 标识（Q1/Q5）

| 对象 | 标识 | 规则 |
|---|---|---|
| 打包游戏 | `game_id` | 优先读游戏包/配置里的 `game_id` 字段；缺省 = `<清洗后的标题>-<sha1(exe 目录)[:8]>` |
| 编辑器工程 | `project_id` | 工程目录下 `.loom/project_id`（首次使用时生成 uuid4 并落盘）；已存在则读 |

`project_id` 文件缺失**且**用户配置里已有该路径的 `origin` 记录 → 沿用原记录，不产生新目录（防"删了 id 文件就丢配置"）。

## 4. 文件格式与合并（Q2）

```json
{
  "schema": 1,
  "game_id": "PacMan2D-1a2b3c4d",
  "origin": "D:\\Games\\PacMan2D",
  "updated_at": "2026-11-08 13:00:00",
  "values": { "render_api": "opengl", "key_bindings": { "解锁鼠标": ["F10"] } }
}
```

- **`values` 只存 delta**：用户没改过的键不出现。
- **读取合并**：`merged = deep_merge(默认模板, values)`（一层深合并足够；标量覆盖，dict 递归一层，list 整体替换）。
- **未知键保留**：模板里没有、`values` 里有的键**保留**（向前兼容）。
- **模板新增键自动生效**：因为以模板为底，新版模板加键后用户自然拿到。

## 5. 启动流程

```
1. 算标识（game_id / project_id）
2. 用户层文件存在?
   否 → 写 {schema:1, values:{}} → 用默认模板启动
   是 → 解析
        ├ 解析失败 或 缺 schema 或 来自旧版位置/旧文件名  → 尝试迁移转换
        │    ├ 成功 → 原子写回新格式（保留可识别键）
        │    └ 失败 → 备份 + 写 {schema:1, values:{}}（= 默认启动）
        └ schema == 当前 → 合并启动
3. 任何写入失败 → **抛异常**，由上层决定提示/退出；禁止 try/except: pass
```

## 6. 旧格式迁移（Q3）

需识别的旧形态（至少）：
1. `<exe 旁>游戏设置.json`（当前发布形态，无 schema 字段）
2. `<exe 旁>游戏配置.json`（更早形态，键名 `render_api` 等，见 P-02-03）
3. `<引擎目录>设置.json` / `<引擎目录>输入配置.json`（无 schema）

转换规则：把已知键搬进 `values`，不认识但合法的键一并搬（宁留勿丢）；任何异常 → 按 §5 失败分支处理。

## 7. 写入语义（D5 的硬要求）

- 一律 `tmp + os.replace` 原子写。
- **禁止**以下模式（本轮审计的病灶）：
  - `return ok or True`（`run_player.py:101`）
  - 失败仍返回 `{'ok': True, 'saved': True}`（`engine.set_action_binding`、`agent_commands`）
  - `except Exception: pass` 吞掉写失败（`package_engine` 元数据回写、`loom_input.rebind_action`）
- 写失败必须让上层可判定 → 返回值/异常二选一，并在调用处**处理**（报错退出或明确提示）。
- **日志引导**：`game_player._bootstrap_logging` 改写 `userpaths.log_path('game')`；失败时向 stderr 打印一次"日志落盘失败（原因）"，不再完全静默。

## 8. 受跟踪文件降级为只读模板

- `Loom/输入配置.json` → 重命名为 `Loom/输入配置.default.json`（保留 git 历史用 `git mv`），运行时只读它作模板。
- `Loom/tests/设置.json` 之类测试夹具**不参与**本改造（测试必须用 `LOOM_USER_ROOT` / `LOOM_GAME_DIR` 指向临时目录）。
- **不变量**：跑完整套测试后 `git status --porcelain` 除预期新增文件外必须为空。
