# 功能补全 5 档施工路线图（2026-10-17 制定 · 2026-10-18 进度更新）

> 性质：施工指导文件。规定「补哪些功能、按什么顺序补、每步怎么测」。
> 制定依据：用户定案「骨架+血肉并行，对标 Unity，按 80% 中型游戏会用到的功能优先补齐」。
> 分档原则：按实际使用频繁程度分 5 档；档内按依赖树基座优先 + 同层按实现难度由难到易；
> 档内每功能只做崩溃冒烟测试，档末做完整模拟测试（正常/极限/非法/畸形/Unity 对齐）。
> 基线：已完整的功能见附录 A，不重复施工。

## 〇、总则

### 0.1 五档定义

| 档位 | 使用频率 | 判定标准 |
|---|---|---|
| 第 1 档 | 极高频 | 几乎所有类型游戏都会用到；缺了做不出像样的游戏 |
| 第 2 档 | 高频 | 大多数游戏会用到；缺了游戏体验明显打折 |
| 第 3 档 | 中频 | 相当一部分游戏会用到（取决于游戏类型）|
| 第 4 档 | 低频 | 特定类型游戏才用（载具、布娃娃、开放世界）|
| 第 5 档 | 极低频 | 可延后，或在脚本层实现即可 |

### 0.2 档内排序规则（用户 D1 决策确定）

**第一优先：依赖树基座优先。** 若功能 A 依赖功能 B，则 B 必须先于 A 施工。被依赖的功能是依赖树节点上较高的基座，优先施工以尽早解锁依赖链。

**第二优先：同一依赖层级内按实现难度由难到易。** 难度判断依据：改动文件数、是否触及热路径、是否需要新 DLL 接口、是否需要新建子系统。

**冲突处理**：若难度排序与依赖关系冲突，**依赖优先**。在文档中显式标注「依赖优先调整」以便追溯。

### 0.3 测试策略（两阶段）

**阶段一：档内冒烟测试（每个功能做完立刻做）**
- 只测一件事：**引擎能正常启动、不崩溃**
- 方式：启动编辑器 → 加载默认场景 → 进出播放 → 退出；无异常即通过
- 不做：功能正确性、边界、性能
- 目的：快速定位「是谁把引擎搞崩了」，避免攒到最后一起排查

**阶段二：档末完整测试（一档全部做完后做）**
- 模拟真实用户操作：按该档功能的典型使用场景，走一遍完整流程
- 极限数值：最大值、最小值、0、负数、超大数、超长字符串
- 非法数值：类型错误、空值、越界索引、不存在引用
- 畸形数值：NaN、Infinity、Unicode 特殊字符、超长嵌套
- Unity 对齐：同一操作在 Loom 与 Unity 2022.3 LTS 中的表现是否一致
- 目的：确认这一档功能真正可用，而非「勉强能跑」

### 0.4 每档施工纪律

1. 开工前 git commit 一次（回退锚点）
2. 每完成一个功能：冒烟测试 → 通过则 commit → 进入下一个功能
3. 档内全部完成：完整测试 → 全部通过则 commit 并更新台账 → 进入下一档
4. 任何一步失败：git checkout 回退到该功能开工前，不硬撑
5. 探针放 tests/_tmp/，永久保留

### 2.6 序 14 LayerMask 详细技术路线（2026-10-18 勘察落盘）

#### 2.6.1 现状硬事实（读代码 + 读 Culverin 签名确认）

| 事实 | 位置 | 影响 |
|---|---|---|
| Layer/Tag 已有整数字段 | loom_components.py（Layer 32 位掩码 + Tag 字符串） | LayerMask 的位语义可直接复用 |
| Culverin `raycast(start, direction, max_dist, ignore)` **无 category/mask 参数** | `_culverin_c.pyi:446` | **物理层无法直接按 LayerMask 过滤射线**，必须 Python 侧二次过滤 |
| `overlap_sphere` / `overlap_aabb` 同样无 mask 参数 | `_culverin_c.pyi:455-456` | 区域查询也需 Python 侧过滤 |
| 物理桥的 category/mask 已被"树位"占用（每根树 1 位，同树不互撞） | `physics_bridge.py:730` `cat, mask = bit, ALL_MASK & ~bit` | **LayerMask 与树位必须共存**，不能简单覆写 |
| 引擎几何碰撞（`_collision_events_inline`）是纯 AABB 逐对判定，完全不看 Culverin category/mask | `loom_physics.py:643-690` | 几何路径的 LayerMask 过滤是纯 Python 判断，改动面小 |

#### 2.6.2 设计（三条独立过滤点）

**过滤点 A：Raycast（loom_raycast.py）**
- `raycast(origin, direction, max_dist, layer_mask=0xFFFFFFFF)` 新增参数
- 物理路径：Culverin 返回 handle → 反查 model → 检查 `model.layer & layer_mask` → 不匹配则记入 ignore 列表并重新 raycast（循环直到命中匹配层或超限）
- 几何路径：AABB 遍历时直接 `if not (m.layer & layer_mask): continue`
- `raycast_all` 同理（循环 raycast 天然支持过滤）
- `raycast_screen` 只是参数透传

**过滤点 B：几何碰撞检测（loom_physics.py）**
- `_collision_events_inline` 的逐对判定加 `if not (m.layer & other.layer): continue`
- 语义对齐 Unity：Unity 的 Layer 碰撞矩阵默认同层互撞、不同层可配；Loom 简化为"双方 layer 相与非零才判定"
- ⚠️ 需要注意 `_related`（祖先链不互撞）已存在，LayerMask 是叠加条件

**过滤点 C：物理桥 category/mask（Culverin）**
- 当前树位占用 bit 0~30，第 31 位保留
- 方案：树位机制保持不变（同树不互撞是引擎既有契约），LayerMask 只在**查询层**（Raycast / Trigger 检测）过滤，**不改 Culverin 的碰撞检测矩阵**
- 理由：改 Culverin category/mask 会破坏"同树不互撞"契约，风险大；LayerMask 在查询层过滤已覆盖 90% 场景

#### 2.6.3 改动面

| 文件 | 改动 |
|---|---|
| `loom_raycast.py` | raycast/raycast_all 加 layer_mask 参数 + 过滤逻辑（物理循环 raycast + 几何跳过） |
| `loom_physics.py` | `_collision_events_inline` 逐对判定加 LayerMask 条件 |
| `agent_commands.py` | raycast/raycast_all/raycast_screen 命令加 layer_mask 参数 |
| `loom_mcp.py` | 3 个 Raycast 工具 schema 加 layer_mask |
| `loom_components.py` | ColliderComponent 加 `layer_mask` 字段？→ **暂不需要**（层在 GameObject 上已有） |

#### 2.6.4 验收标准

- 探针 `tests/_tmp/verify_layermask.py`：
  1. 两个不同 layer 的物体，raycast 只传某一层 mask → 只命中该层
  2. layer_mask=0 → 全部无命中
  3. layer_mask=0xFFFFFFFF → 全部命中（与不加参数等价）
  4. 几何后端与物理后端过滤结果一致
  5. 碰撞事件：不同 layer 的两物体重叠 → 不触发 on_collision_start

#### 2.6.6 实际交付记录（2026-10-18 完成 · commit cc06b7a）

**范围偏差（用户拍板）**：路线初稿设计了三条过滤点（A Raycast 查询 / B 几何碰撞 / C Culverin category-mask）。实际施工时用户明确选定 **只做 A（Raycast 查询过滤）**，理由：
1. 物理桥的 category/mask 已被"树位"占用（每根树 1 位），做碰撞矩阵需重构物理桥，风险高
2. 引擎几何碰撞（AABB）与物理桥（Culverin）会语义分裂
3. 99% 小游戏场景用不到碰撞矩阵，属第 2/3 档候选

**实际交付**：
- `loom_raycast.py`：`_layer_match` 静态方法 + `raycast/raycast_all/raycast_screen` 三 API 加 `layer_mask=None` 参数
  - 物理路径：Culverin raycast 无 category/mask 参数 → 循环 raycast + ignore，不匹配的 handle 逐个排除（最多 100 次防死循环）
  - 几何路径：`_raycast_geom_all` 遍历时直接 `_layer_match` 跳过
- `agent_commands.py`：3 个 EAI 命令加 `layer_mask` 参数解析（转 int，非 int 返回 `{'error': 'layer_mask 必须是整数位掩码'}`）
- `loom_mcp.py`：3 个 MCP 工具 schema 加 `layer_mask: integer`

**语义**：`layer_mask` 位掩码，`bit i` 表示 layer i；`None`/负数=不限；`0`=全不匹配；默认 `None`（保持旧行为）。

**验收**：`tests/_tmp/smoke_layermask.py` 13 项全 PASS：
- raycast 无 mask / 单层 mask / 多层 mask / mask=0 / mask=0xFFFFFFFF / mask=-1
- raycast_all 多掩码 / mask=0 空
- EAI 三命令透传 / 非法 mask 报错
- MCP 三工具 schema 含 layer_mask / 实际透传

### 2.7 序 17 Trigger 详细技术路线（2026-10-18 勘察落盘）

#### 2.7.1 现状硬事实

| 事实 | 位置 | 影响 |
|---|---|---|
| `ColliderComponent` **无 is_trigger 字段** | `loom_components.py:119-133` | 需新增字段 + 序列化 + 编辑器 UI |
| Culverin `create_body` **有 is_sensor 参数** | `_culverin_c.pyi:243` `is_sensor: bool = False` | 物理层可直接建 sensor 体（不产生接触力，只触发事件） |
| 碰撞事件派发**用纯几何 AABB**，不读 Culverin contact | `loom_physics.py:643-723` | Trigger 检测可复用现有事件链路，无需改 C 层 |
| 现有碰撞事件：`on_collision_start/end/stay` | `loom_physics.py:684-689` | Trigger 语义可复用同一差分机制 |
| 物理桥 `_build_one` 目前不传 is_sensor | `physics_bridge.py:752-755` | 需在 `_build_one` 传 `is_sensor=col.is_trigger` |

#### 2.7.2 设计（Unity 语义对齐）

**A. 字段与语义**
- `ColliderComponent.is_trigger: bool = False`
- Trigger 体**不产生物理阻挡**（一方是 trigger 时，双方可重叠穿过）
- 双方都非 trigger → 正常碰撞（现有行为）
- 任一方是 trigger → 不推挤、不产生 on_collision_* 而是派发 on_trigger_enter/exit/stay

**B. 事件派发（loom_physics.py）**
- 现有 `_colliding` 差分机制扩展：
  - 碰撞对 (i,j) 中若**双方都不是 trigger** → 走现有 `on_collision_*`
  - 若**任一方是 trigger** → 走新 `on_trigger_enter/exit/stay`（派发给双方，各自回调收到对方引用）
- 新增脚本钩子（scripts.py Script 基类）：
  ```python
  def on_trigger_enter(self, other): pass
  def on_trigger_exit(self, other): pass
  def on_trigger_stay(self, other): pass
  ```
- 触发条件：`(a.is_trigger or b.is_trigger) and 几何重叠`

**C. 物理层（physics_bridge.py）**
- `_build_one` 传 `is_sensor=bool(getattr(col, 'is_trigger', False))`
- Culverin is_sensor 体：不产生接触力（动态体穿过不会被推开），但接触事件照常上报
- ⚠️ 当前事件派发走几何 AABB 而非 Culverin contact，所以 is_sensor 的物理效果（不阻挡）由 Culverin 保障，事件由几何差分派发——两条路并行，语义一致

**D. 序列化与编辑器**
