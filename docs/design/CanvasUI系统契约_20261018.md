## 二·五、字体与字符集契约（2026-10-18 追加）

> 用户要求：「UTF-8 字符集补全全显示」——不只中文，emoji/日文/韩文/符号都要能显示。
> 背景事实：现有 _render_text 是单字体（雅黑）直渲染，2026-08-15 因性能问题删除了逐字符回退。
> 本契约恢复回退机制，但用缓存消除性能开销。

### 2.5.1 回退链（顺序固定）

| 序 | 字体文件 | 用途 |
|---|---|---|
| 1 | C:/Windows/Fonts/msyh.ttc | 微软雅黑（主字体，中文优先） |
| 2 | C:/Windows/Fonts/seguiemj.ttf | Segoe UI Emoji（彩色 emoji） |
| 3 | C:/Windows/Fonts/seguisym.ttf | Segoe UI Symbol（数学符号/箭头/杂项符号） |
| 4 | C:/Windows/Fonts/simsun.ttc | 宋体（生僻字补充） |
| 5 | C:/Windows/Fonts/msgothic.ttc | MS Gothic（日文，最后避免抢中文） |
| 6 | C:/Windows/Fonts/malgun.ttf | Malgun Gothic（韩文） |

**规则**：从左到右查，第一个有该字形的字体胜出。主字体（雅黑）覆盖绝大多数中文，日常文本不会触发回退。

### 2.5.2 字符→字体映射缓存（方案 B 决策）

    _char_font_map: dict[str, int]   # 字符 -> 字体链索引（0=主字体，1=emoji...）
    _char_font_missing: set[str]     # 全链都没有的字符（记录避免反复查）

- **首次查询**：某字符第一次出现时，逐字体调 get_metrics 判定，结果写入缓存
- **后续查询**：直接命中缓存，零 freetype 调用
- **缓存失效**：进程级永久有效（字体文件不热重载）
- **内存估算**：常用汉字 3000 + emoji 2000 + 其他 ≈ 1 万个字符，约 100KB

**前置条件**：字体链加载成功（任一字库缺失则该索引标记为不可用）
**后置条件**：get_metrics 调用次数 = 首次遇到的不同字符数，之后恒为 0

### 2.5.3 分段渲染

渲染一段文本时，按「连续同字体」切分成若干段，每段一次 font.render，最后按 x 偏移拼接：

    输入："你好😀世界"
    分段：[("你好", 雅黑), ("😀", emoji), ("世界", 雅黑)]
    渲染：3 次 render，按累计宽度横向拼接

**前置条件**：文本非空
**后置条件**：渲染结果与逐字符渲染视觉一致
**边界**：空文本返回零尺寸 Surface

### 2.5.4 emoji 等比缩放（决策 B）

emoji 位图尺寸与普通文字不一致（实测 😀 在 32 号字号下是 44×37，中文约 32×32）。
处理方式：**等比缩放到文字行高，垂直居中**。

- 目标高度 = 主字体在该字号下的行高（font.get_linesize()）
- 按等比缩放，不变形
- 水平方向按缩放后宽度前进，垂直方向相对基线居中

**前置条件**：emoji 段渲染出的 Surface 高度 != 目标行高
**后置条件**：emoji 与相邻文字视觉上"一样高、一样齐"

### 2.5.5 性能边界

| 场景 | 开销 |
|---|---|
| 纯中文文本（首次） | 每字符 1 次 get_metrics（主字体就命中） |
| 纯中文文本（缓存后） | 0 次查询，1 次 render |
| 中英 emoji 混排（首次） | 每字符 ≤ 6 次 get_metrics（最坏走满链） |
| 中英 emoji 混排（缓存后） | 0 次查询，N 次 render（N=连续段数） |
| 文字纹理 LRU 命中 | 0 次查询，0 次 render（直接用缓存纹理） |

**验收标准**：同一段文本第二次渲染的开销必须等于 LRU 命中（即完全走缓存，不触碰字体链）。

## 三、数据模型契约

### 3.1 UIElement 基类

    name: str
    rect: (x, y, w, h)        # 相对父容器的偏移与尺寸（像素）
    anchor: (ax, ay)          # 锚点 0~1，默认 (0, 0) 左上
    pivot: (px, py)           # 轴心 0~1，默认 (0, 0) 左上
    visible: bool             # 默认 True
    enabled: bool             # 默认 True（False 时不可交互）
    parent: UIElement | None
    children: list[UIElement]
    z_order: int              # 同级排序，默认 0

- **前置条件**：无
- **后置条件**：构造后 anchor/pivot 在 [0,1]，w/h >= 0
- **不变量**：树结构无环；parent 为 None 时挂 Canvas

### 3.2 Canvas（UI 根）

    class Canvas:
        canvas_type: 'screen' | 'world'   # 屏幕空间 / 世界空间
        # screen 模式
        width, height                      # 默认跟随窗口
        # world 模式
        target: GameObject | None          # 宿主物体（世界位置/旋转来自它）
        world_scale: float                 # 世界单位->像素换算，默认 1.0
        # 公共
        root: UIElement                    # 根元素（Panel）
        z_order: int                       # 多 Canvas 之间的排序

**不变量**：screen Canvas 数量任意；world Canvas 必须绑定 GameObject。

### 3.3 11 种元素（C3 完整集）

**第一批（基础，§七施工阶段 1）**

| 元素 | 专有字段 | 说明 |
|---|---|---|
| Panel | bg_color: (r,g,b,a) | 纯色矩形；alpha < 255 时半透明 |
| Text | text, font_size, color, align ('left'/'center'/'right'), wrap_width | wrap_width > 0 时自动换行；**支持全 UTF-8（含 emoji），字体回退见 §2.5** |
| Image | texture_path, tint: (r,g,b,a), fit ('stretch'/'contain'/'cover') | 贴图显示 |

**第二批（交互，施工阶段 2）**

| 元素 | 专有字段 | 说明 |
|---|---|---|
| Button | text, normal_color, hover_color, pressed_color, on_click: callable | 四态：普通/悬停/按下/禁用 |
| Slider | min_value, max_value, value, direction ('h'/'v'), on_change: callable | 拖动滑条 |
| Toggle | is_on: bool, label, on_change: callable | 勾选框 |
| ProgressBar | value: 0~1, fill_color, bg_color | 只读进度条 |

**第三批（复杂，施工阶段 3）**

| 元素 | 专有字段 | 说明 |
|---|---|---|
| ScrollView | content_size: (w,h), scroll_pos: (x,y), show_bar: bool | 裁剪 + 滚动条；需 moderngl scissor |
| InputField | text, placeholder, max_length, on_submit: callable | 键盘焦点 + 输入法支持 |
| Dropdown | options: list[str], selected_index, on_change: callable | 点击展开列表 |
| GridLayout | cell_size: (w,h), spacing: (sx,sy), columns: int | 自动排列子元素 |

**第四批（世界空间，施工阶段 4）**

World Space UI 不新增元素类型，而是让上述 11 种元素在 world Canvas 下工作：
- Canvas 绑定 GameObject，取物体世界位置
- 计算方式：世界位置 -> 相机投影 -> 屏幕坐标 -> 正常 UI 渲染
- 可选「面向相机」（billboard）或固定朝向

## 四、布局契约（B1 绝对定位 + 锚点）

### 4.1 计算公式

对每个元素，最终屏幕位置：

    parent_rect = 父元素的屏幕矩形（Canvas 根为 (0,0,width,height)）
    ax, ay = anchor
    px, py = pivot
    x = parent_rect.x + (parent_rect.w - rect.w) * ax - rect.w * px + rect.x
    y = parent_rect.y + (parent_rect.h - rect.h) * ay - rect.h * py + rect.y

- anchor=(0,0), pivot=(0,0) -> 左上角对齐（默认）
- anchor=(1,1), pivot=(1,1) -> 右下角对齐（贴右下角）
- anchor=(0.5,0.5), pivot=(0.5,0.5) -> 居中

### 4.2 前置后置

- **前置**：anchor/pivot 在 [0,1]；rect.w/h >= 0
- **后置**：计算后得到屏幕矩形，供渲染与命中测试使用

### 4.3 屏幕缩放

Canvas width/height 变化时（窗口 resize），所有元素按新父矩形重算。
**不自动缩放元素尺寸**（那需要额外的 scale 字段，暂不做）。

## 五、渲染契约

### 5.1 渲染顺序

1. Canvas 按 z_order 升序
2. Canvas 内按树深度优先遍历（父先于子）
3. 同级按 children 列表顺序（后加的画在上面）

### 5.2 复用现有绘制原语

| UI 元素 | 绘制方式 |
|---|---|
| Panel | draw_screen_rect(rect, bg_color) |
| Text | draw_text_quad(text, x, y, color, size) |
| Image | blit_texture 或新增带 tint 的贴图 quad |
| Button | draw_screen_rect（底色）+ draw_text_quad（文字） |
| Slider | draw_screen_rect（轨道）+ draw_screen_rect（滑块） |
| Toggle | draw_screen_rect（框）+ draw_screen_rect（勾）+ draw_text_quad（标签） |
| ProgressBar | draw_screen_rect（背景）+ draw_screen_rect（填充） |
| ScrollView | 开 moderngl scissor 裁剪后绘制子元素 |
| InputField | draw_screen_rect（框）+ draw_text_quad（文本）+ 光标线 |
| Dropdown | draw_screen_rect（框）+ draw_text_quad（当前项）+ 展开时画列表 |
| GridLayout | 只计算子元素位置，自身不绘制 |

### 5.3 渲染挂载点

在 loom_render.py 的 _draw_hud() 调用之后追加 _draw_canvas_ui()。
HUD 先画（在底层），Canvas UI 后画（在上层）——保持 E1 决策的 HUD 独立。

### 5.4 透明与混合

Panel/Image 支持 alpha 通道，需要开启 GL 混合（现有 draw_screen_rect 已用 enable_only=moderngl.BLEND）。

## 六、输入契约（D1 UI 独占输入）

### 6.1 输入事件类型

    on_mouse_move(pos)        # pos = (x, y) 屏幕像素
    on_mouse_down(pos, button) # button = 'left'/'right'/'middle'
    on_mouse_up(pos, button)
    on_key_down(key, char)    # InputField 专用
    on_key_up(key)

### 6.2 命中测试

从**最上层**（z_order 最大、树最深）往下测：
- 元素 visible 且 enabled 且点在其屏幕矩形内 -> 命中
- 命中 ScrollView 时，超出其内容区的子元素不参与命中

### 6.3 独占规则

1. 先做 UI 命中测试
2. 命中任何 UI 元素 -> 该事件**不传给 3D 世界**
3. 未命中 -> 正常传给 3D 世界（相机控制、物体拾取等）

### 6.4 焦点管理

- InputField 需要键盘焦点：点击 InputField -> 获焦；点击别处 -> 失焦
- 同一时刻最多一个元素持有键盘焦点
- 焦点元素接收 key_down/key_up

### 6.5 与现有输入系统的关系

现有引擎有 mouse_pos / buttons / pressed / released 字段。
UI 层在每帧渲染前消费这些状态，命中检测结果决定是否「消费掉」该事件（3D 侧读到消费标记就跳过）。

## 八、序列化契约

场景文件新增 ui 段：

    "ui": {
      "canvases": [
        {
          "canvas_type": "screen",
          "z_order": 0,
          "elements": [
            {"type": "panel", "name": "root", "rect": [0,0,1920,1080],
             "anchor": [0,0], "pivot": [0,0], "bg_color": [0,0,0,128],
             "children": [...]}
          ]
        }
      ]
    }

- 元素按树嵌套（children）
- 事件回调（on_click 等）**不序列化**（运行时由脚本重新挂载）
- 缺 ui 段 -> 无 Canvas，行为不变

## 九、错误模型

| 场景 | 处理 |
|---|---|
| 元素类型未知 | 跳过 + 警告 |
| rect 宽/高为负 | 钳制到 0 |
| anchor/pivot 越界 | 钳制到 [0,1] |
| Image 贴图文件缺失 | 画纯色占位 + 警告 |
| Canvas target 物体不存在 | world Canvas 跳过渲染 + 警告 |
| ScrollView 内容尺寸 < 容器尺寸 | 禁用滚动 |

## 十一、待办记录（防遗忘，用户明确要求）

### 待办 1：B2 Flexbox 布局模型

**状态**：**未实现，按 B3 决策延后**

**触发条件**（满足任一即可考虑启动）：
- 用户在实际做游戏时反馈「手算坐标太烦」
- 出现「同一个 UI 要适配多种屏幕尺寸」的需求，锚点不够用
- 复杂 UI（如 10+ 元素的菜单/背包）的开发效率明显被坐标计算拖累

**预期设计**：
- 在现有 B1 基础上增加 layout 字段：'absolute'（默认）| 'flex'
- flex 模式下，flex_direction（row/column）、justify_content、align_items、gap、grow 生效
- 参考简化版 Yoga 算法（不做完整的 flex-wrap / order）
- B1 的 anchor/pivot 继续对 flex 容器的整体定位生效

**注意**：这是**明确待办，不是可选功能**。后续接手的 Agent 在完成 C3 元素后，需重新审视是否需要 Flexbox。

### 待办 2：World Space UI 的高级特性

以下不在本契约阶段 4 范围内，作为后续扩展：
- 曲面 UI（弯曲贴在曲面上）
- UI 与 3D 深度混合（被 3D 物体遮挡）
