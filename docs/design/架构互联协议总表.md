# Loom 引擎架构互联协议总表

> **性质**：白盒契约层权威文档。定义 Loom 全工程各组件之间的**唯一耦合点**。
> **用途**：拿回架构控制权 —— 任何改动前先在此定位"动了哪层协议"，评估影响面。
> **取证来源**：`core_components/loom_module.h`、`module_loader.py`、`module_registry.py`、
> 各 `*_glue.py`、`engine.py`、`agent_commands.py`、`plugin_loader.py`、`scripts.py`、
> `sceneio.py`、`build_all.bat`（均为当前工作区代码）。

---

## 0. 分层总览

依赖方向**单向向下**（上层 import 下层，下层绝不 import 上层）：

```
[0] C ABI 契约层          loom_module.h (DLL ↔ Python 唯一耦合点)
[1] 注册表/加载器层        module_loader.py (机械层) + module_registry.py (策略层)
[2] Glue 桥接层           fastpath / pipeline_glue / script_glue / physics_glue
[3] 基座 Python 层        GLEngine (13 mixin) + editor/runtime/vk_player
[4] UI 契约层             IEditorView / IHubView (可替换)
[5] 自动化协议层          EAI (agent_commands) / MCP (loom_mcp) / HUB-EAI
[6] 插件协议层            plugin_loader (L1 分级)
[7] 脚本协议层            scripts.py (@register)
[8] 序列化协议层          sceneio.py / game_pack.py
```

## 1. 协议层 [0]：C ABI（DLL ↔ Python 基座）

### 1.1 契约文件
`core_components/loom_module.h` v1.0 —— **所有核心组件 DLL 与 Python 基座之间唯一耦合点**。

### 1.2 魔数与 ABI 版本
```c
#define LOOM_MODULE_MAGIC 0x4D4F4F4Cu        /* 字节序 'L','O','O','M' */
#define LOOM_ABI_MAKE(major, minor) (((major)<<16) | ((minor)&0xFFFF))
#define LOOM_ABI_VERSION_CURRENT LOOM_ABI_MAKE(1, 0)
```
**校验规则**：主版本必须相等（破坏性变更拒绝加载）；DLL 次版本 > 基座已知次版本 = 允许（DLL 更新），基座按已知接口调用。

### 1.3 强制导出集（7 个，extern "C"）

| # | 导出 | 签名 | 职责 |
|---|---|---|---|
| 1 | `loom_module_info` | `const LOOM_MODULE_INFO*(void)` | 返回静态模块信息（禁栈指针） |
| 2 | `loom_module_provide` | `const char*(uint32_t idx)` | 枚举 provides，越界返 NULL |
| 3 | `loom_module_depend` | `const char*(uint32_t idx)` | 枚举 depends |
| 4 | `loom_module_init` | `int32_t(void)` | 建立设备资源（**可重入**） |
| 5 | `loom_module_deinit` | `void(void)` | 释放（热重载前必调） |
| 6 | `loom_module_abi` | `uint32_t(void)` | ABI 版本快捷查询 |
| 7 | `loom_module_has` | `int32_t(const char*)` | 可选能力查询（缺席=按 0） |

**必需 6 个**（has 可选）：`module_loader.LOOM_REQUIRED_EXPORTS`。

### 1.4 结构体（POD，内存布局冻结）

**LOOM_MODULE_INFO（104 字节）**：
```c
uint32_t magic; uint32_t abi_version;
char module_id[64]; char version[16];
uint32_t official;        /* 1=官方 0=用户注入 */
uint32_t provides_count; uint32_t depends_count; uint32_t reserved;
```
⚠️ 必须 104 字节（4+4+64+16+4+4+4+4）。按 65 字节建镜像会整体错位（已实证），`module_loader` 用模块级 assert 钉死。

**LOOM_TENSOR（帧数据张量描述）**：`void* data; int64_t shape[4]; int32_t ndim; int32_t dtype`。基座 arena 预分配，行主序 C 连续。
dtype：`F32=0 F64=1 I32=2 I64=3 U8=4`。

### 1.5 错误码公约
`0`=OK；`-1` CAPACITY（缓冲不足，扩 arena 重试）；`-2` PARAM；`-3` INTERNAL（考虑弹出）；`-4` ABI；`-5` NO_INIT；`-6` UNSUPPORTED。

### 1.6 两条所有权铁律
1. **帧内缓冲区** = 基座 arena 预分配（grow-only），DLL 收 LOOM_TENSOR 裸参数，**绝不在帧路径 malloc/free**。
2. **DLL 私有资源**（物理世界/音频设备）归 DLL 管，生命周期由 init/deinit 显式交接。

### 1.7 热重载铁律
**DLL 无跨帧隐藏状态**。跨帧状态（物体位置/速度/场景图）全留基座。换 DLL 流程 = `deinit → FreeLibrary → LoadLibrary(新) → init`，场景零迁移。

### 1.8 官方组件清单（registry.json 钉 SHA256）

| module_id | path | provides |
|---|---|---|
| `module_ref` | core_components/module_ref.dll | module_ref.echo |
| `ckernels` | ckernels/loom_kernels.dll | ckernels.aabbs, ckernels.collide |
| `pipeline` | core_components/pipeline/pipeline.dll | pipeline.light_vps, scene_bounds, aabbs, world_matrices |
| `script` | core_components/script/script.dll | script.batch_rotate, batch_move |
| `physics` | core_components/physics/physics.dll | physics.pre_step, post_step, substep_loop |

## 2. 协议层 [1]：注册表 / 加载器

### 2.1 两层分工
- **module_loader.py（机械层）**：LoadLibrary / 校验 / 调用 / 卸载。**不 import module_registry/fastpath/engine**（无反向依赖）。
- **module_registry.py（策略层）**：槽位模型 / 回退矩阵 / 拓扑 init / 运行期自愈。规则权威文档 = `core_components/注册表格式与契约设计说明.txt`。

### 2.2 装配流程
```
LoadLibrary → GetProcAddress 验 6 必需导出 → 校验 magic/abi
  → 读 provides/depends → 注册表依赖校验（拓扑排序，防环）
  → init → 投入使用
```
循环上限 `_LOOP_CAP=64`（防死循环 → AssemblyError）。

### 2.3 铁律（报告 v1.3 §6）
**兜底只对准用户注入 DLL（official=false）**；官方组件坏 = `AssemblyError` 报错，**绝不静默降级**，核心组件无 Python 冗余。

### 2.4 逃生门
- `LOOM_NO_DLL='pipeline'` → 注册表层跳过槽位（get 抛 `ModuleNotAvailable`）
- `LOOM_NO_DLL='*'` → 全跳过
- 解析：未设→空集；`'*'`→`{'*'}`；`'a,b'`→`{'a','b'}`

### 2.5 运行期自愈三闸
1. **静态装配**：非法 PE/魔数/接口不符 → 剔除坏库 + 回写 `enabled:false` + 顶回官方 DLL。
2. **硬件级崩溃回退**：空指针访问违例 → ctypes 转 OSError → `pop_and_fallback()` → 回退官方参考实现，进程不崩。
3. **崩溃内存转储**：`crash_reporter.py` 挂 dbghelp.MiniDumpWriteDump，异常时向 `崩溃日志/` 落 .dmp。

## 3. 协议层 [2]：Glue 桥接层

统一模式（4 个 glue 同构）：
```python
def disabled():  # 读环境变量逃生门
def handle():    # 惰性组装 (module_registry.assemble) + 缓存 + is_live 校验
```

| Glue | 桥接 | 特有 |
|---|---|---|
| `fastpath.py` | 三级分派 **C > numba > numpy/pure** | 冻结环境（Nuitka）不 import numba |
| `pipeline_glue.py` | pipeline.dll | `LoomLight` ctypes 结构体镜像 |
| `script_glue.py` | script.dll | `LoomLuaScript` 封装内嵌 Lua 5.4 VM |
| `physics_glue.py` | physics.dll | pre_step/post_step 批量摩擦 |

**核心桥接签名（Python 侧）**：
- `fastpath.aabbs_minmax(...)` / `aabbs_minmax_par(...)` / `depths(...)` / `ancestry_dfs(...)`
- `pipeline_glue.light_vps/scene_bounds/aabbs/world_matrices/...`
- `script_glue.batch_rotate(rot, speeds, dt, out_rot)` / `batch_move(pos, vel, dt, out_pos)`
- `physics_glue.pre_step(lin_vel, ang_vel, is_dynamic, use_gravity, is_active, friction, rolling_fric, gravity_y, dt)`

## 4. 协议层 [3]：基座 Python 层

### 4.1 依赖方向
```
Loom.py / build_entry.py (入口)
  ↓
editor.py (EditorApp) / runtime.py (PlayerApp) / vk_player.py
  ↓
engine.py  GLEngine = 13 个 Mixin 组合:
  ShadowMixin, FrameComponentMixin, PhysicsMixin, InputMixin, HudMixin,
  CameraMixin, RenderMixin, ModelGpuMixin, LightingMixin, WindowMixin,
  TransformMixin, ProfilerMixin, LogicThreadMixin
  ↓
fastpath.py / parallel.py
  ↓
scripts.py
  ↓
vk_renderer / physics_bridge / audio_backend
  ↓
undo.py / sceneio.py / gui.py / filedialog.py
  ↓
matlib.py / mesh.py
```

### 4.2 关键分层原则（不变量）
- engine **不 import** editor/runtime（保证打包只带 engine）
- editor 继承 GLEngine 覆写 render()（编辑器专属画面）
- runtime 继承 GLEngine 不改渲染，只跑场景+脚本
- Vk 播放器**不依赖 GLEngine**：scene_driver（数据+步进）与 vk_renderer（绘制）分离
- physics_bridge / audio_backend **零 GL**，缺库自动禁用回退

### 4.3 数据模型（engine.py）
- `GameObject`：name/guid/visible, position/rotation/scale, parent/children, scripts[], renderer.material, collider, rigidbody, audio_source, animator, vbo/vao 句柄, `_bucket_key` 惰性缓存
- `Material`：color/saturation + `_rgba`/`_sat_f32` 缓存（共享材质改色当帧跟变是 M23 契约）
- `LightState`：kind/position/direction/color/intensity/mode/shape/size/shadow
- `CameraState`：position/yaw/pitch/roll(度制)/fov/pitch_lock/parent
- `Point3D`：三维向量/点

### 4.4 逻辑帧步序（`_logic_frame`）
```
[脚本 update] → [物理子步 ×N] → [音频] → [动画]
  → [逻辑帧 prep: AABB/光源VP/碰撞对] → [事件派发] → [插值翻页]
```

## 6. 协议层 [5]：自动化协议（Agent ↔ 引擎）

| 通道 | 文件 | 规模 | 传输 |
|---|---|---|---|
| **EAI** | agent_commands.py | 62 个 cmd 方法 | HTTP 127.0.0.1 + `.agent_port.json` + X-Agent-Token |
| **MCP** | loom_mcp.py | 24 Tools / 4 Resources | JSON-RPC 2.0 stdio |
| **HUB-EAI** | hub_commands.py | 16 命令 | HTTP |

### 6.1 EAI 协议
```
端口/令牌: <程序目录>/.agent_port.json = {port, token, pid, url}
POST /cmd  {cmd, args} → {ok, result} | {ok:false, error}
GET  /logs?after=N → {seq, lines}
GET  /status → 引擎状态摘要
```
- 命令全在 **Qt 主线程执行**（HTTP 线程收命令 → 入队 → QTimer → 主线程执行 → 回填）
- 命令表 = GUI 功能清单（`qt_view._cmd_*` 同名映射）
- **写路径白名单**：程序目录 / 场景目录 / 用户目录 / Temp

### 6.2 EAI 命令分类（62 个）
场景类（scene_new/save/load）、物体类（object_add/list/select/rename/delete/duplicate）、脚本类（script_add/remove/var/scripts）、编辑类（undo/redo/gizmo/set_transform/set_visible）、材质类（set_color/saturation/material/materials/set_texture/set_pbr/set_lod/set_env）、光照相机类（light_add/set/camera_add/active/move/look/set/preview）、物理类（collider/rigidbody/physics_simulate）、音频动画类（audio/animator）、资源类（assets/asset_*/import_obj/prefab_*）、系统类（status/screenshot/settings_get/set/plugins/plugin_button/play/quit/engine_metrics/inspect）。

## 7. 协议层 [6]：插件协议（L1 分级）

### 7.1 清单
`plugin.json`：`{id, name, version, entry, min_engine, deps}`；
核心插件额外必填：`{layer: editor|player, capability, desc}`。

### 7.2 入口
`entry.py` 的 `def register(api): ...`（必需）。

### 7.3 两级信任
| 级别 | 目录 | 权限 |
|---|---|---|
| 普通插件 | plugins/editor|player | 受限环境（无 open/exec/eval，import 白名单） |
| 核心插件 | core_plugins/<类别>/ | 全权，SHA256 信任闸，重启生效 |

### 7.4 能力入口
`api.*` 是插件唯一能力入口（`api.read_asset` 限插件目录，`api.register_editor_button` 跨层按钮）。

## 8. 协议层 [7]：脚本协议

```python
@register
class MyScript(Script):
    script_id = 'my_script'
    name = '名称'
    params = (('key','标签',默认,min,max,'fmt'), ...)
    def on_start(self): ...
    def update(self, dt): ...
    def on_collision_start(self, other): ...   # 已有
    def on_collision_end(self, other): ...     # 已有
```
- 挂载：GameObject 的 `scripts[]`（ScriptComponent: script_id + script_vars）
- 加载：`load_script_dir`（scripts/ 目录，.py/.lua）+ `register_sources`（游戏包内存源码）
- Lua：`make_lua_script_class` 桥接 script.dll 内嵌 Lua 5.4 VM
- 坏脚本容错：`_script_broken` 标记不崩帧
- C 批处理分流：`rotate`/`move` 走 script.dll 批量，其余走 Python update

## 10. 构建链与打包链

### 10.1 DLL 构建（build_all.bat）
```
锁 MSVC 工具链 (VS2022 Community vcvars64)
  → 逐 DLL 调 build_*.bat (cl /O2 /LD /MD, 禁 fp:fast, /Brepro 可复现)
  → refresh_registry_sha.py 回填 SHA256 进 registry.json
  → 跑对拍网 (tests/_tmp/ 下探针, exit 0 = PASS)
```
**约定**：新增 DLL 在 [DLL 清单] 加 `call :build_dll <子目录> <bat名>`；新增探针在 [对拍清单] 加一行。
**坑**：路径含括号 `Loom(py源代码-工作区)`，bat 内禁含括号变量二次展开；文件必须 UTF-8 无 BOM。

### 10.2 打包链（Nuitka）
```bash
# 编辑器
py -3.12 -m nuitka --standalone --msvc=latest --assume-yes-for-downloads \
   --windows-disable-console --output-dir=Loom --output-filename=Loom.exe build_entry.py
# LoomHub（另加 --include-module=filedialog,guiloader,parallel,...）
# 构建器
py -3.12 -m nuitka --standalone ... --output-filename=build_game.exe build_game.py
# 玩家运行时: build_game.exe --build-runtime (内部调同样命令)
```

### 10.3 三级性能降级保证
任何热路径：**C DLL > numba > numpy/pure Python**（数值逐位同源）。每个组件有逃生门环境变量。

## 12. 改动定位速查

| 想改什么 | 动哪层 | 影响面 |
|---|---|---|
| 加一个核心计算组件 | [0]+[1]+[2] | 新 DLL + registry 条目 + glue |
| 改组件算法 | 仅 DLL 内部 | 契约不变则零影响 |
| 加编辑器命令 | [5] EAI + GUI | 命令表 |
| 加脚本生命周期钩子 | [7] + engine 调度 | 脚本系统 |
| 改场景格式 | [8] | 版本迁移 |
| 换 UI | [4] | 只换实现类 |
| 加插件能力 | [6] api | 沙箱边界 |
