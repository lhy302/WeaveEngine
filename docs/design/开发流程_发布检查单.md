# 开发流程 · 发布检查单（强制）

> **为什么有这份文档**：2026-11-13 第一次正式发 beta6 时，资产哈希全对、对拍全绿、测试全绿，
> 但**两个 Release 的正文还写着「内测 · 草稿」**，Hub 说明里还留着**过期的「默认 `C:\Program Files\Loom`」**
> —— 而这一版刚把默认安装根改成「跟随 LoomHub 位置推荐」。
> 结论：**发布前只核资产、不核正文，等于没核。** 正文是用户第一眼看到的东西。

## 0. 一句话流程

```
版本真源 → 资产重打 → 冒烟盖章 → 包=代码对拍 → 说明体检(机器) → 说明通读(人)
        → tag → Release + 上传 → 远端复核(API) → 记录落盘
```

## 1. 发布前（缺一不可）

| # | 检查项 | 怎么核 | 不过怎么办 |
|---|---|---|---|
| 1 | **版本真源一致** | 引擎读 `Loom/解释器.json`、Hub 读 `LoomHub/版本.json`；与 `LOOM_ENGINE_VERSION`/`LOOM_HUB_VERSION` 一致 | 停下，别改环境变量凑 |
| 2 | **资产是当前 HEAD 打的** | `tools/verify_pkg_vs_head.py <source.zip> <compiled.zip>` EXIT=0 | 重编重打 |
| 3 | **冒烟分别盖章** | 三件各自 `smoke.py --stamp`，`smoke_passed_at > built_at` | 重跑冒烟 |
| 4 | **说明体检（机器）** | `tools/release_github.py` 内置 `notes_lint`：禁「草稿/未执行/待人类裁决/TBD/TODO/待定」、禁已作废说法、**必须含本资产 sha256 与字节数** | 改说明，别绕门 |
| 5 | **说明通读（人）** | 逐节读一遍：默认值/数字/功能列表**是不是这一版的事实**；有没有「等人类裁决」「未执行」这类过程语 | 改成已发布口径 |
| 6 | **tag 命名** | `engine-v<ver>` / `hub-v<ver>`；与上一个版本不冲突 | 改名重打 |
| 7 | **prerelease 标记** | 引擎 beta 一律 `prerelease=True`；Hub 正式版 `False` | 改代码里的 `create_release(...)` |
| 8 | **本机分发副本一致** | 桌面/网盘那份的 sha256 与 `tools/dist` 相同 | 重新拷贝并复核哈希 |

### 说明文件的硬要求（`tools/release_notes/<kind>-<version>.md`）

- **标题不带「草稿」**；beta 可以写「内测 / prerelease」，但正文必须是**已发布事实**；
- **必须写出本次资产的真实 sha256 与字节数**（骨架里写上一个包的数字是最常见的坑）；
- 功能列表必须是**这一版实际做的**；改了默认值就必须同步这里（例如安装根默认值）；
- 不写「待裁决/未执行/下一步计划」——那属于路线登记，不属于发布正文。

## 2. 发布中

```powershell
$env:GIT_TERMINAL_PROMPT = "0"
# token：优先 GITHUB_TOKEN；否则用 git 凭据管理器（注意给 path 才能取到）
$in  = "protocol=https`nhost=github.com`npath=lhy302/WeaveEngine.git`n`n"
$tok = ($in | git credential fill | Where-Object { $_ -like "password=*" }) -replace "^password=",""
$env:GITHUB_TOKEN = $tok.Trim()

py -3.13 tools/release_github.py engine     # 默认先跑全套回归，非零即中止且零远端写操作
py -3.13 tools/release_github.py hub
py -3.13 tools/release_github.py --update-notes   # 正文写错时只改正文，不重传资产
```

**顺序保证**：工具的 `main()` 先做版本白名单 → 资产存在性 → 回归门 → token 校验，
**任何一步失败都不会创建 Release/上传资产**；说明体检 `_notes_gate` 也在 `create_release` 之前。

## 3. 发布后（远端复核，必须做）

```powershell
$rs = Invoke-RestMethod "https://api.github.com/repos/lhy302/WeaveEngine/releases" -Headers @{ "User-Agent"="loom" }
$rs | Where-Object { $_.tag_name -in "engine-v0.1.0.beta6","hub-v0.1.4" } |
  Select-Object tag_name, draft, prerelease,
    @{n="assets";e={($_.assets | ForEach-Object { $_.name + " " + $_.size }) -join "; "}}
```

逐项确认：

1. `draft=False`；引擎 `prerelease=True`、Hub `prerelease=False`；
2. **资产名与字节数** == 本地 `tools/dist` 那份（`Get-FileHash` 对 sha256）；
3. **正文首行**不是「草稿」，且**不含**过期词（`草稿/未执行/待人类裁决`）与过期默认值；
4. 正文里出现的 sha256/字节数 == 实际资产；
5. 正文里的功能列表 == 这一版真实改动（人工再看一遍）。

## 4. 事故案例库（都是真发生过的）

| 事故 | 后果 | 现在怎么防 |
|---|---|---|
| 正文「内测 · 草稿」直接发出去 | 用户第一眼看到「草稿」 | `notes_lint` 禁词 + 发布后复核首行 |
| 说明里的默认值过期（写着 `默认 C:\Program Files\Loom`，实际已改） | 用户按说明理解会错 | `STALE_CLAIMS` + 人工通读 |
| 说明里 sha/大小是上一个包的 | 用户核对哈希发现不一致 | `notes_lint` 强制含本资产 sha256/字节数 |
| 只核资产、不核正文 | 资产对、正文错，照样发出去 | 本文档 + §3 复核第 3/4/5 条 |
| 发布前全量回归平时红着没人看 | 发出去的版本带红 | 工具默认 `--require-tests`，除非显式声明 |

## 5. 机器判不了的部分（必须人读）

`notes_lint` 只检**能机器判的**（禁词、作废说法、哈希/字节数）。以下必须人读：

- 功能列表是不是这一版做的；
- 已知限制/不兼容声明是否写清楚（例如 `v12 场景单向不兼容`）；
- 有没有把「过程语」写进正文（「待裁决」「下一步」「未执行」）；
- 数字口径是否与另一份说明一致（引擎与 Hub 两份说明会互相引用对方的包）。
