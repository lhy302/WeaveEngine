## 二、数据模型契约

### 2.1 GameObject 新增字段

    GameObject.layer: int      # 0~31，默认 0
    GameObject.tag:   str      # 默认 "Untagged"

- **前置条件**：无（构造后即存在）
- **后置条件**：构造后 layer == 0 且 tag == "Untagged"
- **不变量**：0 <= layer <= 31；tag 必须是已注册 tag

### 2.2 Unity 内置 Layer 定义（0~7）

| 编号 | 层名 | 说明 |
|---|---|---|
| 0 | Default | 默认层 |
| 1 | TransparentFX | 透明特效层 |
| 2 | Ignore Raycast | 射线检测默认忽略 |
| 3 | （空） | 用户可自定义 |
| 4 | Water | 水体层 |
| 5 | UI | UI 层 |
| 6 | （空） | 用户可自定义 |
| 7 | （空） | 用户可自定义 |
| 8~31 | （空） | 用户自定义 24 层 |

### 2.3 Unity 内置 Tag（7 个）

Untagged、Respawn、Finish、EditorOnly、MainCamera、Player、GameController

## 三、存储与持久化契约

### 3.1 配置文件 layer_tag.json

位置：**程序目录**（与 设置.json 同级）。

> **变更记录（2026-10-18 用户拍板）**：原定「与场景文件同级目录」改为「程序目录」。
> 理由：layer/tag 是项目级概念，所有场景共享一套；而场景目录可由设置项 save_dir 改变，
> 若配置跟随场景目录，会导致切换目录后配置丢失、或同一项目出现多套层定义。
> Unity 同样是项目级配置（ProjectSettings/TagManager.asset），不是场景级。

    {
      "version": 1,
      "layers": {
        "0": "Default", "1": "TransparentFX", "2": "Ignore Raycast",
        "4": "Water", "5": "UI"
      },
      "tags": ["Untagged", "Respawn", "Finish", "EditorOnly",
               "MainCamera", "Player", "GameController"]
    }

- **前置条件**：文件不存在时自动以默认值创建
- **后置条件**：加载后 layers 补全 0~31（未命名层名为空串）；tags 至少含 7 个内置
- **错误处理**：文件损坏 → 回退默认值 + 控制台警告，不阻止启动

### 3.2 Tag 内联注册语义

用户行为：属性面板 Tag 输入框打下 "Enemy" 回车。

1. 校验：非空、长度 <= 64、不含控制字符、不区分大小写不重名
2. 通过 → 写入 layer_tag.json 的 tags 数组 + 应用到物体
3. 失败 → 错误提示，保持原 tag 不变

代码侧行为：
- 「obj.tag = "Enemy"」时若未注册 → 抛 TagNotRegisteredError
- 提供 engine.register_tag(tag) 显式注册
- 提供 engine.tag_exists(tag) 查询

**例外**：场景加载时引用未注册 tag → 自动注册 + 警告（不阻止加载）

### 3.3 场景序列化契约

_emit_object 新增：

    {
      "layer": 3,
      "tag": "Enemy"
    }

_apply_object 读取：
- 缺字段 → 默认值（layer=0, tag="Untagged"），旧场景自动兼容
- layer 越界（<0 或 >31）→ 钳制 0 + 警告
- tag 未注册 → 自动注册 + 警告

**不升版本号**（v10 保持，靠缺省值兼容）

## 四、Python 公共接口契约

### 4.1 查询接口

    engine.tag_exists(tag: str) -> bool
    engine.layer_name(layer_id: int) -> str      # 未命名返回 ""
    engine.layer_id(name: str) -> int            # 找不到返回 -1
    engine.find_by_tag(tag: str) -> list[GameObject]

### 4.2 修改接口

    engine.register_tag(tag: str) -> bool        # 已存在返回 False（幂等）
    engine.set_object_layer(obj, layer_id: int) -> None   # 越界抛 ValueError
    engine.set_object_tag(obj, tag: str) -> None          # 未注册抛 TagNotRegisteredError

### 4.3 前置后置条件

| 接口 | 前置 | 后置 |
|---|---|---|
| register_tag | tag 非空、<=64 字符 | tag 在注册表；返回是否新增 |
| set_object_layer | 0 <= layer_id <= 31 | obj.layer == layer_id；触发 undo 快照 |
| set_object_tag | tag 已注册（否则抛异常） | obj.tag == tag；触发 undo 快照 |

## 五、EAI 命令契约

### 5.1 新增命令

    set_layer       {name?, layer}      → {layer, layer_name}
    set_tag         {name?, tag}        → {tag}
    get_layer_tag   {name?}             → {layer, layer_name, tag}
    list_tags       {}                  → {tags: [...]}
    list_layers     {}                  → {layers: {"0": "Default", ...}}

### 5.2 错误模型

| 场景 | 返回 |
|---|---|
| 物体不存在 | {"ok":false, "error":"object not found: 方块"} |
| layer 越界 | {"ok":false, "error":"layer must be 0..31, got 999"} |
| tag 未注册 | {"ok":false, "error":"tag not registered: Enemy"} |

**双层语义（刻意设计）**：EAI 的 set_tag 先 register_tag 再应用（宽松，便于 AI 自动化）；底层 Python API 严格（未注册抛异常）。GUI 和 EAI 都走内联注册。

## 七、GUI 契约

### 7.1 属性面板插入位置

_build_obj_inspector 中，名称之后、父级之前：

    名称:  [_______________]
    Layer: [Default ▼]
    Tag:   [Untagged ▼] [可编辑输入]
    父级:  ...

### 7.2 Layer 下拉框

- 显示格式：「{layer_id}: {layer_name}」，如「3: Enemy」、「3: (未命名)」
- 只读（不能输入数字，避免越界）
- 变更立即应用 + 触发 undo

### 7.3 Tag 下拉框 + 输入框

- 下拉框显示所有已注册 tag
- 输入框可编辑，回车后：校验 → 通过则内联注册+应用+刷新下拉框；失败则背景变红+状态栏提示

### 7.4 undo 支持

set_object_layer / set_object_tag 走 commit_model，进 undo 栈

## 八、错误模型汇总

| 错误类型 | 抛出位置 | 处理 |
|---|---|---|
| TagNotRegisteredError | 底层 obj.tag 赋值 | 抛异常，调用方负责注册 |
| ValueError | set_object_layer(999) | 抛异常 |
| 场景加载 layer 越界 | _apply_object | 钳制 0 + 警告 |
| 场景加载 tag 未注册 | _apply_object | 自动注册 + 警告 |
| 配置文件损坏 | layer_tag.json 读取 | 回退默认 + 警告 |
| GUI 输入非法 tag | 输入框校验 | 红色背景 + 状态栏提示 |
