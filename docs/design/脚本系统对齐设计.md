# 脚本系统对齐设计（Loom vs Unity）

> **性质**：白盒契约 + 对齐计划。定义 Loom 脚本系统的现状、与 Unity 的差距、补齐路线。
> **取证来源**：`scripts.py`、`engine.update_scripts`、`loom_frame_components._call_collision_cb`、
> `loom_physics._dispatch_collision_events`（均为当前代码）。

---

## 1. 现状（已实现）

### 1.1 脚本基类契约
```python
class Script:
    script_id = None          # 唯一标识（小写蛇形，序列化用）
    name = '脚本'
    params = ()               # ((key,label,default,min,max,fmt), ...) → 检查器滑块
    def __init__(self):       # 引擎绑定 obj/engine，填充 vals
    def on_start(self): ...   # 进播放调一次
    def update(self, dt): ... # 每帧
```

### 1.2 生命周期钩子（当前已有）

| 钩子 | 触发时机 | 备注 |
|---|---|---|
| `on_start()` | 进播放（首次实例化后） | 坏脚本标记 `_script_broken` 不崩帧 |
| `update(dt)` | 每逻辑帧 | |
| `on_collision_start(other)` | 开始接触某物体 | ✅ **已有** |
| `on_collision_end(other)` | 与某物体分离 | ✅ **已有** |

碰撞回调派发链：`_logic_frame` → `_dispatch_collision_events(pairs)` → `_call_collision_cb(m, hook, other)`。
**机制**：每物体记 `m._colliding` 集合（上一帧 id 集），diff 出新增/消失，只对变化派发。

### 1.3 内置脚本（11 个）
rotate(自转) / orbit(公转) / bob(浮动) / wasd_move(WASD移动) / camera_follow(相机跟随) /
fall(重力落地) / bounce(弹跳) / first_person(第一人称) / third_person(第三人称) /
jump(跳跃) / count_touch(触碰计数，教学)

### 1.4 脚本来源
- `scripts/` 目录（`.py` / `.lua`，文件名白名单 `[A-Za-z0-9_]+\\.(py|lua)`）
- 游戏包内存源码 `register_sources`（.lsc 内，不落盘）
- Lua 走 `make_lua_script_class` → script.dll 内嵌 Lua 5.4 VM

### 1.5 C 批处理分流
`update_scripts` 把 `rotate`/`move` 分流出走 script.dll 批量（SIMD），其余走 Python update。

## 2. 与 Unity 差距对照

| 能力 | Unity | Loom 现状 | 差距等级 |
|---|---|---|---|
| 注册/挂载 | MonoBehaviour | @register + scripts[] | ✅ 对齐 |
| 参数面板 | [SerializeField] | params 自动滑块 | ✅ 对齐 |
| 多组件 | ✅ | ✅ scripts[] | ✅ 对齐 |
| **生命周期** | Awake/OnEnable/Start/Update/**FixedUpdate**/LateUpdate/OnDisable/OnDestroy | on_start/update | 🟡 缺 6 个 |
| **碰撞回调** | Enter/Stay/Exit | start/end | 🟡 缺 Stay |
| **触发器** | OnTriggerEnter/Stay/Exit | 无 | ❌ |
| **协程** | 原生 | 无 | ❌ |
| **脚本间通信** | GetComponent/SendMessage/事件 | 遍历 engine.models | 🟡 |
| **执行顺序** | Script Execution Order | 按注册顺序 | 🟡 |
| **对象查找** | FindObjectOfType/Find | 无 | ❌ |
| **数据资产** | ScriptableObject | 无（仅场景内参数） | ❌ |
| 免编译 | 需编译 | ✅ 立即生效 | ✅ Loom 优 |
| 坏脚本容错 | 编译期发现 | `_script_broken` 运行期不崩 | ✅ Loom 优 |

## 3. 补齐计划（三批）

### 第一批：加钩子/加字段（低耦合，几乎不改热路径）

#### 3.1 生命周期钩子补全

**契约**：
```python
class Script:
    def on_enable(self): ...    # 组件启用 / 进入播放
    def on_disable(self): ...   # 组件禁用 / 退出播放
    def on_destroy(self): ...   # 物体被删除（或退出播放）
    def on_collision_stay(self, other): ...  # 持续接触（每逻辑帧）
```

**接入点**：
- `on_enable`/`on_disable`：`update_scripts` 实例化后调 on_enable；停止播放/禁用时调 on_disable
- `on_destroy`：`remove_model` / `remove_subtree` 时对每个脚本调
- `on_collision_stay`：`_dispatch_collision_events` 在 `current ∩ prev` 上派发（当前只派发 diff）

**验收**：探针 `tests/_tmp/script_lifecycle_check.py` —— 建/启/停/删物体，断言各钩子调用次数。

#### 3.2 脚本执行顺序

**契约**：Script 加类属性 `order = 0`（小者先跑）。
**接入点**：`update_scripts` 收集 generic_items 后按 `(order, 注册序)` 排序。
**验收**：探针断言 order 小的先 update。

#### 3.3 脚本间通信

**契约**：
```python
engine.send_message(obj_or_name, method, *args)   # 向目标物体的脚本发消息
engine.find_by_name(name) -> GameObject | None
engine.find_by_script(script_id) -> list[GameObject]
```
**接入点**：engine 新增查询方法（遍历 models，纯只读）。
**验收**：探针断言查找/发消息命中。

### 第二批：动一点结构

#### 3.4 触发器（Trigger）
**契约**：ColliderComponent 加 `is_trigger: bool`。触发器不阻挡移动，只派发 `on_trigger_enter/stay/exit`。
**接入点**：`move_with_collision` 跳过 trigger；`_dispatch_collision_events` 按 collider 类型分流派发。
**验收**：探针断言穿过触发器不被挡 + 回调触发。

#### 3.5 固定步钩子
**契约**：`on_fixed_update(fixed_dt)`。
**接入点**：`_logic_frame` 物理子步循环内调（语义 = Unity FixedUpdate）。
**验收**：探针断言调用次数 = 子步数。

#### 3.6 轻量协程
**契约**：
```python
engine.start_coroutine(gen)   # gen 为生成器，yield 秒数/None 分帧
engine.stop_coroutine(handle)
```
**接入点**：engine 维护协程表，逻辑帧推进（yield 数字=等待秒数，yield None=等一帧）。
**验收**：探针断言分帧执行顺序与等待时间。

### 第三批：较重

#### 3.7 对象查找增强 + 数据资产（ScriptableObject 式）
- `engine.find_by_tag(tag)`、标签系统
- 数据资产：独立 `.asset.json`，脚本可引用（类似 ScriptableObject）

---

## 4. 实施纪律

1. **每批独立 git 提交**（回退锚点）
2. **每项配探针**（放 `tests/_tmp/`，永久固化）
3. **不改现有热路径**：钩子派发只在事件发生时调，无事件零开销
4. **坏脚本容错**：新钩子全部走 `_call_collision_cb` 同款 try/except + `_script_broken`

---

## 5. 优先级建议

第一批（3.1~3.3）收益最高、风险最低，建议先做。
第二批（3.4~3.6）解锁平台跳跃/机关门类玩法。
第三批按需。
