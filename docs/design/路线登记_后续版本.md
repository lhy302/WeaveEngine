> 4) 取消也必须在表里留痕，不得删除行。

## 3. beta6 末期检查点（Review Gate，写进流程）

在 beta6 收尾、决定是否发版之前，**必须**执行一次：

1. 通读本文件 §1/§2，逐项判断"是否已被 beta6 的改动顺手解决"（解决则标 `已取消（原因）` 或移出）。
2. 从 §1 里挑出**依赖已就绪**的 1-2 项，评估能否在 beta6 剩余容量内提前做（例如 B7-05 若一期 FramePlan 很顺，可顺手做 reads 校验）。
3. 判断 §2 的 N-07（VS2026）是否升级。
4. 把结论回写到本文件与 `版本计划_Loom0.1.0.beta6_*.md`，**不允许只留口头结论**。

**人类裁决（2026-11-16，原文留痕）**

1. 「引擎校验当前安装版本的引擎和服务器上的引擎（例如同样名字都是 beta6）的哈希或者提交节点是否一样，不一样的话 hub 端提示有新补丁包并推荐拉取。」
2. 「发现有补丁包版本的话和 Unity 一样推荐由 Hub 端进行当前同样版本号的老引擎的覆盖安装。」

由此确定的三条口径（与设计 §4.1 的 R1/R2/R3 一一对应）：

| # | 口径 | 落地项 |
|---|---|---|
| 1 | 允许同版本号替换资产，但**必须可对拍、可提示** | H-01 + H-05 |
| 2 | 补丁由 Hub 做**同版本号覆盖安装**（用户不必管两个 beta6） | H-03 |
| 3 | 客户端**不静默替换**：提示 + 推荐拉取，由用户点 | H-04 |

**明确不做**（理由见设计 §5）：单 pack + Range 内容寻址、git 仓库当增量通道、exe 级二进制差分（bsdiff/xdelta）、代码签名（单独立项）。
