# 后续版本路线登记（beta7 及以后）

> **本文件是"延迟项"的唯一落盘处**。规则：
> 1) 任何在本版**不做**、但已想清楚的路线，必须写进这里；**只存在于对话上下文里的计划视为未登记**。
> 2) 每项标注 **预定版本**；凡标 `beta7` 的，均可能在 **beta6 末期检查点**（见 §3）被重新评估后**提前或推迟**。
> 3) 状态只有：`待做` / `可能提前` / `已取消（写明理由）`。
> 4) 取消也必须在表里留痕，不得删除行。

## 3. beta6 末期检查点（Review Gate，写进流程）

在 beta6 收尾、决定是否发版之前，**必须**执行一次：

1. 通读本文件 §1/§2，逐项判断"是否已被 beta6 的改动顺手解决"（解决则标 `已取消（原因）` 或移出）。
2. 从 §1 里挑出**依赖已就绪**的 1-2 项，评估能否在 beta6 剩余容量内提前做（例如 B7-05 若一期 FramePlan 很顺，可顺手做 reads 校验）。
3. 判断 §2 的 N-07（VS2026）是否升级。
4. 把结论回写到本文件与 `版本计划_Loom0.1.0.beta6_*.md`，**不允许只留口头结论**。

## 4. 已明确取消（留痕）

| 编号 | 项目 | 取消理由 |
|---|---|---|
| **X-01** | C → C++ 大规模迁移 | 手写 C 仅 `ckernels/loom_kernels.c` 18KB；无迁移对象。新模块可直接用 C++ 写（保留 `extern "C"` 边界），老文件不动 |
| **X-02** | 渲染 RenderGraph（自动依赖推导/屏障/别名） | 两端执行序已线性；真实成本是"同一语义两种表达"，用 FramePlan 解决；图系统工期翻倍且无第二个需求验证 |
| **X-03** | GLSL → SPIR-V 双编译 | moderngl 5.12 无 SPIR-V；wgpu 只吃 WGSL；无原生工具链 |
| **X-04** | multi-draw indirect（把 38 次 draw 合并） | 实测净收益 ≤0.26ms/帧（~2%）；moderngl 一次只能一个 VAO，`gl_DrawID` 需 GL 4.6 |
| **X-05** | `buffer.write` / `vao.render` 下沉 C | 实测仅 0.103ms / 0.045ms，下沉无意义 |
| **X-06** | 动画时间/播放态落盘 | 会造成"打开就播到某帧"的不可预期行为；改为只写预览 |
| **X-07** | 蒙皮走 UBO 调色板 | GL 地板已抬到 4.3，SSBO 可用，改走 SSBO（B7-01） |
