# T2 差异清单（beta6 · 2026-11-13 建立）

> **这份文件回答一个问题**：GL 与 VK 之间有哪些语义面**没有**共享，为什么不能共享，靠什么门控，以及**用哪条可复跑探针**证明它没坏。
> 目标是计划 §9.31 的 **T2**；清单由人类裁决维护。**探针红 = 清单失效**，必须更新条目而不是改探针。

## 0. 口径（先说清楚，避免再发生「重新分桶」）

- 本清单**不算分、不折算**。§9.28 的 14 项分母与 11.5/9.5 折算已按 §9.29 提案废除；§9.31 里「现 4 项不共享 + 1 项合理差异」是**当时的快照**，不是标准答案。
- 条目只按**证据**增删；§9.31 快照与本清单条数不同（见 §4），差额逐条列明，**不做等价换算**。
- 「不共享」= 同一语义两端各写一份实现，改一处不会自动改另一处。
- 「合理差异」= 受 API/硬件语义限制**无法**共享，且已把差异**关进一层**（宏层 / 描述层），改语义仍只有一处。

## 1. 条目格式

```
| 编号 | 语义面 | 为什么不能共享 | 门控方式（差异关在哪里） | 可复跑探针 | 当前证据 |
```

## 2. 不共享（D 组）

| 编号 | 语义面 | 为什么不能共享 | 门控方式 | 可复跑探针 | 当前证据 |
|---|---|---|---|---|---|
| **D-01** | 主目标的 load/clear | GL 的主目标就是默认帧缓冲，清屏走特例函数 `loom_render.py:396 _clear_main_fbo`；VK 是显式 attachment，走 `clear_value`（`vk_renderer.py:1168/1338/1523`） | 清屏**颜色/深度语义**来自 FramePlan 的 `TargetDecl/PassSpec`，两端只负责各自的 API 写法 | 改 plan 的清屏色/深度清除值 → 两端同向变化（T1 反例矩阵第 7 类，`Loom/tests/test_frame_plan_vk.py`） | 已有受跟踪测试；`§9.28 #4` 判「不共享」 |
| **D-02** | 绘制源的**实现** | `PassSpec` 的 source 名字（`buckets`/`skybox`/`world_canvas`）共享，但每个 source 的执行体两端各一份（GL `loom_render.py` / VK `vk_renderer.py`） | `FramePlan` 决定**存在性与顺序**（T1 已达成）；实现体各自持有 | 删/换 pass source → 两端 MAE 同向（§9.28 #7 的反例） | 已有 `test_frame_plan_vk` 反例；**「实现体不共享」本身无独立探针 → 归入「已接受的存在性差异」** |
| **D-03** | 天空几何与参数注入 | GL 用 6 顶点 TRIANGLES 全屏 quad（`loom_render.py:176-229`）；VK 用 `_SKY_WGSL` 自己的顶点/参数注入路径 | 时机与存在性由 plan 的 sky pass 定；`RasterState.cull` 两端已接线（§9.28 #6 反例 0.24656） | `ab_sky` 三向 MAE + sky.cull 反例 | `ab_sky` 1.2e-5/1.2e-5/0（2026-11-13 实测） |
| **D-04** | 实例桶布局与提交粒度 | GL 每桶一个 VBO 直接 `render(instances=cnt)`（`loom_render.py:1002`）；VK 重排为统一 96B 实例布局 + 每桶一次 submit | 实例字段表 `INSTANCE_LAYOUT`（`loom_shader_bindings.py`）是**单点表**，两端按同一张表写字节 | 改实例字段/桶数 → 两端像素同向（`ab_*` 场景 + `Loom/tests/test_bucket_pack.py`） | §9.28 #13；字段表统一已落盘（T3c-3） |
| **D-05** | UI 光栅化 | GL 走 `loom_ui` 元素树 + moderngl `TRIANGLE_STRIP`（`loom_render.py:369-390`）；VK 在 `vk_ui.py` 里自建三角带 + 自己的管线 | 两端共享的是**元素树与场景数据**，不共享三角化与提交 | `ab_ui_scene` 的 **[UI] 子项** MAE（不是整帧 MAE） | `ab_ui_scene [UI]` 1.10e-4（门限 2e-4），2026-11-13 实测 |
| **D-06** | mip 生成 | GL 侧走 CPU（`loom_cubemap.build_mipmaps()`）；VK 侧走 shader `_MIP_WGSL`（`vk_renderer.py:1285`，14 行） | 无（两条完全不同的算法路径）→ **这是本项目里最该被质疑的一条**，见 §5 | `ab_tex` 三向 MAE（需补：显式带 mip 的贴图场景） | `ab_tex` 0/0/0；**mip 内容本身无独立探针（现状缺口）** |

## 3. 合理差异（R 组：无法共享，但已关进一层）

| 编号 | 语义面 | 为什么无法共享 | 门控方式 | 可复跑探针 | 当前证据 |
|---|---|---|---|---|---|
| **R-01** | 阴影目标编码 | GL 用硬件深度纹理；VK 用 `r32float` + 手工比较（API/硬件语义限制，wgpu 无等价 depth-compare 采样路径） | **比较算法**已统一为 9-tap 显式比较（§9.32），差异只剩**存储格式** | `ab_c_dir_shadow` / `ab_point_shadow` 三向 MAE | 2.9e-5/5.1e-5/2.9e-5 与 5.7e-5/4.6e-5/1.1e-5（2026-11-13） |
| **R-02** | 采样器/绑定模型 | GL 是组合采样器（`sampler2D`），wgpu/naga 只接受**分离采样器**（`texture2D`+`sampler`），比较采样器必须 `samplerShadow` | **`Loom/shaders/loom_shader_compat.glsl` 单层吸收**：`#ifdef LOOM_VK` 只允许出现在这一层，正文只用宏 | `tools/build_shaders.py`（SPIR-V 能建模块）+ 23 场景像素门 | 6 个 shader 已单源化；`#ifdef LOOM_VK` 全仓仅 compat（grep 实证） |

## 4. 与 §9.31 快照的差额（逐条列明，不折算）

§9.31 写「现 4 项不共享 + 1 项合理差异」。T3 完成后重算：

| 变化 | 条目 | 依据 |
|---|---|---|
| **消失（并入共享）** | 原 #11 着色器语言（GLSL vs WGSL） | T3 已单源：一份 GLSL → SPIR-V；剩余差异降级为 **R-02**（采样器写法，关进 compat） |
| **消失（并入共享）** | 原 #12 参数块布局 | T3c-1/2a：Scene UBO / Bucket UBO 由表生成，两端同一份 |
| **新增/拆出** | D-05 UI 光栅化、D-06 mip 生成 | 原表把它们压在「#14 UI」「#12 mip」里；本清单按「改一处是否要改两处」独立成条 |
| **未变** | D-01/D-02/D-03/D-04 | 与 §9.28 #4/#7/#10/#13 一一对应 |

→ 当前 **6 条不共享 + 2 条合理差异**。与快照「4+1」不同是**口径细化**，不是目标退步：T2 的判据是「每条都有原因/门控/探针」，不是条数。

## 5. 需要人类裁决的两点（不擅自决定）

1. **D-06 mip 生成是否允许长期双实现**？GL 是 CPU 逐级降采样，VK 是 shader 降采样，两条算法不可能逐像素相等。选项：**(A)** 接受为「合理差异」并给出容差（当前 `ab_tex` 0/0/0 说明现有场景没暴露差异）；**(B)** 把 GL 也改成同一 shader 路径（工作量：GL 侧增加逐级 FBO 渲染）；**(C)** 把 VK 也改成 CPU（VK 侧失去 GPU mip，可能变慢）。
2. **D-02「绘制源实现体」算不算不共享**？语义面（名字/顺序/存在性）已共享，实现体天然两份。若算，清单里它永远无法消掉；若不算，应降级为「实现细节」。**我倾向不算**（T1 已覆盖其语义），但按纪律不擅自删条目。

## 7. 维护规则

1. 新增任何「两端各写一份」的语义面 → 必须在本表登记，否则视为违规。
2. 条目对应探针变红 → **先判定是清单失效还是产品坏了**；不许改探针阈值了事。
3. 条目删除必须给证据（「已并入共享」要指向哪次提交/哪张表）。
