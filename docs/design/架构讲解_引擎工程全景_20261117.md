# 引擎工程全景 —— 它是怎么被设计和装配起来的（2026-11-17）

> 目的：**讲清工程本身的结构**，而不是列缺陷。读这份东西的人应该能自己判断「某个职责放错了位置」。
> 全部结论带 `file:line`；凡是推断而非读码得到的，正文里注明。
> 规模：`Loom/` 下 93 个生产 `.py`、**52 116 行**（排除 `tests/`、`player_runtime/`、`shaders/`、`ckernels/`、`core_components/`）。

---

## 1 三样产物、五条入口

同一套源码被装配成三种物理形态，各有独立入口文件 —— 这是整个工程的第一个结构事实：

| 产物 | 入口文件 | 形态 | 实测体积 |
|---|---|---|---|
| 源码树（开发） | `Loom/Loom.py` | 直接跑 .py | — |
| 编辑器 dist | `Loom/build_entry.py` → `Loom.exe` | Nuitka onedir | 332 文件 / 150.2 MB，`Loom.exe` **37.1 MB** |
| 构建器 dist | `Loom/build_game.py` → `build_game.exe` | Nuitka onedir | 80.1 MB |
| 运行时 dist | `Loom/game_player.py` → `MyGame.exe` | Nuitka onedir | 278 文件 / 143.4 MB，`MyGame.exe` 33.8 MB |
| 项目管理器 | `LoomHub/LoomHub.py` | Nuitka + NSIS | 25.5 MB 安装包 |

**`Loom.py` 与 `build_entry.py` 是两份平行入口**：`_parse_args`（`Loom.py:31` / `build_entry.py:33`）与 `_make_editor_view`（`Loom.py:70` / `build_entry.py:79`）各写一遍，docstring 完全相同。
编译产物用 `build_entry.py` 是为了「编辑器 exe 里不出现 `Loom.py` 这个模块名」之类的打包约束，代价是 **CLI 面双写**。

## 3 类是怎么拼起来的

### 3.1 `GLEngine` = 14 个 mixin 的多重继承（`engine.py:196-198`）

```
class GLEngine(ShadowMixin, FrameComponentMixin, PhysicsMixin, InputMixin, HudMixin,
               CameraMixin, RenderMixin, ModelGpuMixin, LightingMixin, GlfwWindowMixin,
               TransformMixin, ProfilerMixin, LogicThreadMixin, RaycastMixin)
```

每个 mixin 一个文件（`engine.py:51-97` 的 import 就是这张表）。这种「一个类 + 十四个 mixin」的装配方式的直接后果：
**所有子系统共享同一个 `self` 命名空间**，任何子系统都可以读写别的子系统的私有字段，且没有任何接口约束。
好处是零胶水、调用快；代价是「谁拥有哪个字段」只能靠注释。

### 3.2 三个「引擎门面」并行存在

| 门面 | 位置 | 行数/方法 | 谁用 |
|---|---|---|---|
| `GLEngine` | `engine.py:196` | 1810 行 / 50 方法 | 编辑器、GL 播放器、bench |
| `EditorApp(GLEngine)` | `editor.py:159` | 2906 行 / 6 方法（大量继承） | 编辑器本体 |
| `SceneDriver` | `scene_driver.py` | 1642 行 / **58 方法**（独立类，不吃 GLEngine） | VK 播放器、VK 打包游戏 |

`EditorApp` 继承 `GLEngine` 意味着**编辑器就是引擎加了一层 UI/命令/撤销**；
`SceneDriver` 则是**平行的另一套实现**（不继承），它自带模型/材质/灯光/相机装配函数（`build_models`/`build_materials`/`build_lights`/`build_cameras`，`scene_driver.py:44/202/251/414`）。
GL 侧对应物是 `sceneio._apply_*` 系列。**同一个「场景 dict → 运行对象」的转换因此有两套实现**。

### 3.3 播放器层

| 播放器 | 类 | 渲染器 | 窗口 |
|---|---|---|---|
| GL 播放器 | `runtime.PlayerApp(GLEngine)`（309 行） | moderngl（`GLEngine` 内） | pygame→GLFW（`loom_glfw_window`） |
| VK 播放器 | `SceneDriver` + `VkRenderer`（2107 行） | wgpu | GLFW（`vk_player` 自带） |
| 远程兼容窗口 | `loom_player_window`（313 行） | Qt 离屏 GL + QImage | Qt |

## 5 一帧的旅程（两条后端，标出共享点）

### 5.1 GL 路径

```
RenderMixin.run()                    loom_render.py:1311   while self._running:
  _handle_events()                   输入/窗口事件
  move_camera / rotate_camera        loom_camera
  render(delta_time)                 loom_render → 主 pass
      plan = frame_plan(...)         loom_pass.py:130   ← 共享描述层
      loom_pass_gl.execute(plan)     loom_pass_gl.py:71 按 plan 顺序执行 pass
        每个 pass 的「绘制源」在 RenderMixin/EditorApp 里：
          _prepare_main_pass（相机/VP/uniform）、sky、shadow、post（loom_post_gl）
  限帧 sleep（1/120）
```

### 5.2 VK 路径

```
vk_player.run_vk → GLFW 循环 → VkRenderer.draw_frame()
  plan = frame_plan(include_shadow=..., ...)   vk_renderer.py:1728  ← 同一份共享描述层
  for spec in plan.passes:                      vk_renderer.py:1877
      按 spec.target / depth / raster 选/建 wgpu 管线
  post 目标按 plan.targets 建                    vk_renderer.py:564-576
```

**共享**：`FramePlan` 描述、`loom_post` 的 post 语义、`loom_scene_ubo` 的 UBO 布局、GLSL 源码与 `loom_shader_compat.glsl` 宏。
**不共享**：执行器（`loom_pass_gl` vs `vk_renderer` 内部）、管线对象、绑定号表（`SB_*` 在 compat 里按后端各一份）、窗口/输入。

### 5.3 逻辑帧 / 渲染帧分离

`core_clock.FixedStepClock`（198 行）持逻辑 accumulator；`interp_state.InterpState` 存 prev/curr 双快照做渲染帧插值。
GL 侧由 `LogicThreadMixin`（`loom_logic_thread`）驱动可选异步逻辑线程；VK 侧在 `SceneDriver._logic_frame` 内同步推进。
`frame_buffer`（345 行）是 GL 侧的「逻辑帧预取缓冲」实验，**VK 侧没有对应物**。

## 6 数据模型：从场景文件到运行对象

### 6.1 场景文件（v12，`sceneio.SCENE_VERSION`）

| 顶层键 | 含义 | 谁读 |
|---|---|---|
| `version` / `min_engine_version` | 场景格式版本 / 最低引擎版本 | `sceneio.migrate` / `check_engine_version` |
| `objects[]` | 物体树（id/parent_id/transform/组件/材质引用…） | `scene_from_dict`（GL）/ `build_models`（VK） |
| `materials[]` | **只写引用**（定义在资产库） | `_apply_materials` / `build_materials` |
| `lights[]` / `cameras[]` / `active_camera` | 光源 / 相机实体 | 同上 |
| `camera` | 编辑器导航相机（不是 CameraState） | 编辑器 |
| `skybox` / `ui` / `gravity` | 场景级天空盒 / Canvas 树 / 重力 | 两端 |

### 6.2 资产身份（beta6 B1）

```
<项目根>/Assets/assets.json        资产库：guid -> {kind, 定义/路径, 导入设置}
<项目根>/Assets/…                 贴图/网格/环境图实际文件
场景 materials[]                  只存 guid 引用（+ 内联副本仅供旧场景兼容）
```

`loom_assets.py`（1194 行）是唯一解析入口；`sceneio.asset_context()` 探测不到资产库时返回 `None` = **旧路径模式**（行为回退到 beta5）。

### 6.3 运行对象

| 概念 | 类 | 位置 |
|---|---|---|
| 物体 | `GameObject` | `loom_game_object.py`（M25 组件化容器） |
| 组件 | `TransformComponent` / `MeshRendererComponent` / `AnimatorComponent` / `ColliderComponent` / `RigidBodyComponent` / `ScriptComponent` | `loom_components.py`（10 类） |
| 光源/相机状态 | `LightState` / `CameraState` | `loom_scene_entities.py` |
| 材质/贴图/环境图 | `Material` / `Texture` / `Cubemap` | `loom_material` / `loom_texture` / `loom_cubemap` |
| UI | `UIManager` / `Canvas` / `Element` 家族 | `loom_ui.py`（15 类） |

## 7 双后端的分工（谁写什么）

| 关注点 | GL 侧 | VK 侧 | 是否共享 |
|---|---|---|---|
| 帧描述 | `loom_pass.frame_plan()` | 同一个 `frame_plan()`（`vk_renderer.py:1728`） | ✅ 共享 |
| 场景 UBO 布局 | `loom_scene_ubo.pack_arrays` | `loom_scene_ubo.pack` | ⚠️ 同模块，**两个 packer** |
| 后处理语义 | `loom_post_gl` | `vk_renderer._record_post` | ✅ 语义共享（`loom_post`），实现各自 |
| 着色器源码 | GLSL（`loom_shaders` 拼宏） | 同一份 GLSL → glslang → SPIR-V | ✅ 单源 |
| 后端差异宏 | `compat.glsl` 的 `#else` 分支 | `compat.glsl` 的 `#ifdef LOOM_VK` 分支 | ✅ 单文件内分流 |
| 场景→对象装配 | `sceneio._apply_*` | `scene_driver.build_*` | ❌ 两套 |
| 光照/阴影 VP | `loom_lighting` + `loom_shadow` + `pipeline_glue`(C) | `vk_renderer._pack_light_vps` | ❌ 两套 |
| UI 绘制 | `loom_ui` 数据 + `engine.draw_screen_*` + `loom_render` world Canvas | `vk_ui.py`（屏幕 + world 两条管线） | ❌ 两套 |
| 输入/鼠标锁 | `loom_input` + `loom_glfw_window` | `vk_player` + `vk_ui` 输入桥 | ❌ 两套 |
| 时钟 | `clock_from_settings` | `FixedStepClock()` 默认值 | ❌ 且**不读设置**（见盘点 D2） |

| 面 | 入口 | 机制 | 隔离 |

## 12 有意不统一的地方（不是遗漏，是取舍）

| 差异 | 位置 | 理由（代码里写明的） |
|---|---|---|
| GL 几何**后**画天空 / VK 几何**前**画天空 | `loom_pass.py:10-11` | 同一语义两种实现（LEQUAL 等值通过 vs depth_compare=always） |
