# 开发流程：冒烟 / 回归 / 测量 / 一次性验证 的四层分工

> 2026-11-10 由人类裁定：**冒烟只保留「这个程序能跑」的最基础验证**，其他一切（正确性、异常路径、性能阈值、一次性取证）都必须剥离到各自层。
> 起因：beta6 期间我把「版本闸回退验证」「VK 回退」「后处理开关对照」「资产目录检查」都塞进了每次构建后的手工冒烟，导致冒烟变慢、变吵，且与已存在的受跟踪测试重复。

## 1. 四层分工（一句话）

| 层 | 回答什么问题 | 时长 | 稳定性要求 | 归属 |
|---|---|---|---|---|
| **冒烟** | 这个东西还能不能起来？ | < 60s | 必须稳（红了=构建坏了） | tools/smoke.py（受跟踪） |
| **回归** | 功能是否按契约工作？ | 分钟到十分钟 | 允许慢，必须全绿 | Loom/tests/run_all.py |
| **测量** | 性能是多少、变好还是变坏？ | 分钟 | 只记录不判定（或按明确门禁） | tools/measure_engine.py |
| **一次性验证** | 这次修复到底成不成立？ | 不定 | 验完即处置 | 见第 4 节 |

## 2. 冒烟的四条硬约束

1. **快**：整轮 < 60 秒。任何超过 3 秒的检查都不该进冒烟。
2. **浅**：只走主干路径（启动 -> 打开 -> 播放 -> 有读数 -> 退出）。
3. **稳**：必须稳定通过；一旦红，说明构建/打包已经坏了，与具体功能无关。
4. **只做正向**：不测异常、不测回退、不测降级、不测阈值。

### 冒烟允许的检查（全部）

| # | 检查 | 判据 |
|---|---|---|
| 1 | 编辑器能启动 | 进程存活、无 crash、无 traceback |
| 2 | 能打开示例场景 | models 数量 > 0（证明真加载，不是空场景） |
| 3 | 能播放 | is_playing=true 且持续 > 2s 不崩 |
| 4 | 有性能读数 | fps > 0 且 tps > 0（**不判阈值**） |
| 5 | 打包产物能起（仅编译版） | 双击等价路径能打开并存活 |

### 冒烟明确禁止的内容

- 异常/回退/降级路径（版本闸拒绝、VK 转 GL 回退、auto 降级、缺失 DLL 回退……）
- 性能阈值判断（「FPS >= 某值」属于测量层）
- 资产/配置/文档一致性检查
- 任何 grep 源码字符串的断言
- 任何需要构造反例的验证

> 这些内容要么已经在 Loom/tests/ 里有受跟踪测试，要么属一次性验证。重复放进冒烟 = 噪声。

## 3. 冒烟是构建门：红了就不许打包

顺序固定为：编译 -> 冒烟 -> 打包 -> 包与 HEAD 对拍。
冒烟红 -> 直接停，不进打包（避免「编完就说好了」）。

## 4. 一次性验证怎么处置（重要）

任何为某次修复写的探针/脚本，**验完必须三选一**：

1. **收进回归**：值得长期防回归的 -> 写进 Loom/tests/（例：版本闸验证已收成 test_scene_version_gates）；
2. **收进测量**：属性能对照的 -> 并入 tools/measure_engine.py；
3. **删除**：只对那次改动有意义的 -> 直接删。

**不允许**：留在临时目录里被反复手工执行（这正是本轮清理的对象）。

### 5.2 「上一批全绿」不能当「本批全绿」的证据（2026-11-13，因为有真实事故才写）

**事故**：§9.30 记录的「135 文件全绿」是 2026-11-11 01:55 的状态；`4a66faa`（T3c-1 shader 重构）**12:05** 才落地，此后 T3c-2/3/4 每批只跑 `ab_gl_vk` + 14 套，**再没跑过全量回归**。结果 T3c-1 把 `_WORLD_UI_VERT`/`_LINE_VERT` 的 `u_view_proj` 批量误改成非法 GLSL（`uniform mat4 u.mvp;`），GL 世界 UI / gizmo / 网格 / 选中框**完全画不出来**，5 个测试红着挂了三天，交接文档还写着「全绿」。

**规则**：

1. 任何 `refactor(shader)` / 改动着色器源 / 改绑定表的提交，**四道门必须整套重跑**（编译 → 像素 → 回归 → grep），不许只跑像素门。
2. 交接文档里写「全绿」必须带**时间戳 + HEAD**，并且下一个 Agent 在恢复开发时**先重跑一遍**再引用该结论。
3. `run_all.py` 的失败列表必须贴进报告原文，不许只写「个别失败」或「与本次无关」而不给证据。

### 5.3 回归层不许放「墙钟比值」门限（2026-11-13，又是因为真实假红才写的）

**事故**：`test_bucket_pack.py` 里有一条性能门禁 `C 打包 <= 0.80x Python`（墙钟比值）。同一天里：

| 时刻 | 机器状态 | 实测比值 | 结果 |
|---|---|---|---|
| 上午 / W5 复跑 | 连续跑测试，CPU 热 | ~0.75 | PASS |
| 主审复跑（冷机睿频） | 空闲 | **0.83 / 0.84 / 0.79** | 一次红、两次更接近门限 |

**没有任何代码变化**，`run_all` 却红了。C 路径是内存带宽型、Python 路径是计算型，CPU 睿频/热降频对两者影响不同 → 比值随机器状态漂移，**不适合作回归门限**。

**规则**：

1. **回归层**只挡真实回归：本例改为 `C 不得慢于 Python（ratio <= 1.00）`，仍能挡住「C 路径彻底坏掉」。
2. **测量层**才判 `≤0.80x` 这类目标，且必须遵守 §9.7 的性能测量纪律（空闲 + n=5 + 交替）。
3. 任何「耗时/比值」断言进入 `run_all` 前先问一句：**它在有负载的机器上会不会假红**？会就必须降到回归层能容忍的形式，或移出回归。
4. 判据改动必须留下**改动前后的真实数字**（本例：0.75 → 0.83，无代码变化），否则后人会以为是放宽标准。

## 6. 非交互执行一律抑制弹窗（2026-11-11 补充）

**规则**：回归、冒烟、测量、以及任何**探针/一次性验证**，都必须让被拉起的引擎进程带 `LOOM_NO_DIALOG=1`。

理由：引擎在「VK 不可用 → GL 回退」「场景版本不满足」等路径上会弹阻塞对话框。批量执行时这些框会**弹到用户桌面并卡住管道**——2026-11-10 就发生过：审计代理的探针拉起真实引擎，用户桌面上连续弹 VK 回退对话框。

已内置的位置（无需手工设置）：
- `Loom/tests/run_all.py`：全局 `os.environ.setdefault('LOOM_NO_DIALOG','1')`，所有子测试继承
- `tools/smoke.py` / `tools/measure_engine.py`：给子进程显式设该环境变量

**手工探针的写法**：

```python
env = dict(os.environ, LOOM_NO_DIALOG='1')
subprocess.run([...], env=env)
```

## 7. 子代理不得自造冒烟（2026-11-11 补充）

- 子代理**不允许**自己拼一套「启动+播放+检查」的脚本当作冒烟；冒烟只有 `tools/smoke.py` 一个入口。
- 子代理**不允许**在验收里重跑混装流程（把异常路径、回退验证、性能对照塞进冒烟）；分层见第 1 节。
- 需要验证异常/回退路径时，写**受跟踪测试**（`Loom/tests/`）或**一次性探针并写清 `_tmp` 路径**，验完按第 4 节处置。
