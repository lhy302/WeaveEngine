2. 定位 — 注册表是什么
--------------------------------------------------------------------
- 注册表 = 核心组件槽位的机读清单 (用户构想第 5/6 点的工程化):
  引擎有哪些核心组件、各指向哪个 DLL、提供哪些接口、依赖哪些
  接口、谁官方谁注入 — 一张表说清, 基座据此"组装引擎"。
- 人 + AI 双读 (总纲 §10.2): JSON 本体机器可解析 (Agent 读表即知
  引擎有什么 / 缺什么), 本文人可读 (语义与规则的最终解释)。
- 组装序 = 先核心后插件 (总纲 §3.3): 基座先按本注册表加载校验
  全部在役核心组件, 之后才走 plugin_loader.py 既有机制加载插件层。
  插件层注册表不在 registry.json v1.0 范围 (构想第 6 点同类机制,
  复用 plugin_loader manifest / 信任闸, 后续升格)。

--------------------------------------------------------------------
3. 顶层字段 (registry.json 第一层键)
--------------------------------------------------------------------
_format          必须 == "loom-core-registry/1.0"。
                 不符 = AssemblyError 拒绝组装 (基座报错, 绝不带
                 病运行) — 防旧文件 / 手改文件被误读。
_doc             人读说明指针 (指向本文), 验证器忽略此键。
registry_version 注册表自身版本 "1.0", 语义化增量 (§10)。
components[]     组件条目数组, 每条 = 一个候选 DLL 的声明
                 (字段见 §4, 槽位关系见 §5)。

--------------------------------------------------------------------
4. 组件条目字段 (components[] 每条)
--------------------------------------------------------------------
module_id  槽位主键, 非空, ≤63 字符 (LOOM_NAME_MAX, 对齐
           LOOM_MODULE_INFO.module_id)。槽位模型见 §5。
path       DLL 文件路径, 相对引擎根解析
           (如 "core_components/module_ref.dll")。
official   true=官方组件 (随引擎发行) / false=用户注入。
           必须与 DLL info.official 一致 (§6 校3)。
enabled    true=本条目参与组装; false=本条目不参与组装 (不加载 /
           不校验 / 不占接口)。回退回写改的就是它。
provides[] 本模块提供的接口名, "组件.接口" 点分式
           (如 "module_ref.echo", 对齐 loom_module.h 命名建议)。
depends[]  依赖的接口名, 每项必须被其他在役模块的 provides
           满足, 否则依赖方弹出 (§6 校4)。调用基座 / 系统的接口
           不用声明 (用户构想原话: 调用系统的接口不用写出来)。
sha256     信任闸钉子: DLL 文件指纹 (十六进制)。官方条目可空
           (随引擎发行); 用户注入建议填, 填了即强制比对
           (§6 校0 前置闸; 惯例与 plugin_loader.py 同源)。
note       人读备注 (自由文本, 机读侧忽略)。

5. 槽位模型与顶替规则 (★核心设计)
--------------------------------------------------------------------
槽位 = module_id。同一槽位允许多条目并存 (官方条目 + 用户注入
条目), 组装时每槽位只激活一条:
- 官方条目 (official=true): 常驻 enabled=true, 永远留在表里,
  作为回退靶 — 被顶替时暂不加载, 待命。
- 用户注入条目 (official=false): enabled=true 时遮蔽官方 —
  同槽位官方暂不加载, 本条目顶替上岗; 本条目被弹出或 enabled
  置 false 时, 官方自动顶回。

顶替的定义: 用户注入条目沿用被替换官方组件的同一 module_id
("同槽位换人"), 顶替默认所有接口保持一致 (也可以多提供接口,
写进 provides)。

歧义注入 (≠顶替): 不同 module_id 的模块提供了与在役模块相同的
接口 — 无槽位关系, 纯接口冲突 → 组装时弹出用户注入一方。
冲突消解策略: 保官方, 弃歧义 (双方都官方 = 引擎缺陷 →
AssemblyError, §6 校6)。

候选顺序 (槽位内): 用户注入(enabled) 优先 → 官方(enabled) 兜底。

6. 校验规则表 (module_registry.py 实现, 逐条列)
--------------------------------------------------------------------
"弹出" = 该条目退出本次组装, 引擎继续 (只对用户注入);
"AssemblyError" = 组装拒绝, 基座报错。动作按 §7 矩阵执行。
sha256 闸在 LoadLibrary 之前执行 (见下); 其余规则在加载后、
组装期执行。

校0 sha256 信任闸 (前置, 加载之前): official=false 且 sha256
    非空且与磁盘文件实测不符 → 不加载直接弹出。校验先于
    LoadLibrary — 不给坏文件进进程的机会。
校1 magic: DLL 导出的 LOOM_MODULE_INFO.magic 必须 ==
    0x4D4F4F4C ('LOOM' 内存序, loom_module.h)。不符 = 拒绝加载。
校2 ABI: DLL abi_version 主版本必须与基座相等 (次版本 DLL 高于
    基座 = 允许, DLL 更新, 基座按已知接口调用); loom_module_abi()
    与 info.abi_version 双口一致, 不一致 = 校验失败。
校3 身份一致: DLL info.official 必须与注册表条目 official 一致
    (冒充官方 = 校验失败)。
校4 声明一致: provides/depends 的 JSON 声明必须与 DLL 导出枚举
    (loom_module_provide/depend 逐 index 取全集) 逐集合一致 —
    谎报 (多报 / 漏报 / 改名) = 校验失败。
校5 依赖满足: depends 每项必须被其他在役模块 satisfies; 未满足
    → 依赖方弹出 (用户注入回退官方; 官方 → AssemblyError)。
校6 接口冲突: 同接口双提供 → 弹出用户注入一方 (保官方弃歧义);
    双方都官方 → AssemblyError (引擎缺陷)。
校7 依赖环: 依赖图有环 → AssemblyError (init 拓扑序无解,
    组装拒绝)。
校8 init 拓扑: init 按拓扑序执行 (依赖先行); init 失败按弹出
    规则处理 (§7)。

--------------------------------------------------------------------
7. 回退矩阵 (失败类型 × official=true/false → 动作)
--------------------------------------------------------------------
失败类型: 加载失败 / 校验失败 (§6 校1-校4) / 依赖未满足 (校5) /
  init 失败 (校8) / 运行期崩溃 (§9)。

用户注入坏 (official=false, 任一失败类型):
  ① 弹出 (退出本次组装 / 运行)
  ② registry.json 该条目 enabled=false 自动回写 — 落盘持久化,
     下次启动不再试
  ③ 同槽位官方 DLL 自动顶回
官方坏 (official=true, 理论不可达 — 官方随引擎发行):
  AssemblyError 让基座报错。绝不静默降级, 绝不回退 Python 实现
  — v1.3 铁律: 兜底只对准用户注入, 核心组件无 Python 冗余。

--------------------------------------------------------------------
8. LOOM_NO_DLL 逃生门 (注册表层)
--------------------------------------------------------------------
- LOOM_NO_DLL="ckernels,render_prep": 逗号分隔指名槽位 — 这些
  槽位跳过加载, 基座 get 该槽位抛 ModuleNotAvailable (调用方
  感知缺件, 引擎不死)。
- LOOM_NO_DLL="*": 全部槽位跳过 (整体退回无 DLL 形态)。
- 与既有 LOOM_NO_* 族并存, 分层不重叠:
    LOOM_NO_DLL      = 注册表层门 (槽位根本不进加载器)
    LOOM_NO_CKERNELS = 既有组件内部门 (模块在, 内部功能自关);
      LOOM_NO_PARALLEL / LOOM_NO_CRASHDUMP 同属内部门
- 用途: 排障逐层隔离 — 先关注册表层, 再关组件内部。

--------------------------------------------------------------------
9. 运行期弹出回退 (崩溃自愈)
--------------------------------------------------------------------
组装期闸门之外, 坏 DLL 还可能在运行期崩 (访问违例 0xC0000005,
ctypes 的 SEH 包裹把它转成 OSError 抛给基座)。流程 (对应用户
构想第 5 点"崩溃后基座自动把坏 DLL 从注册表里删掉替换回官方
DLL"):
  ① 基座捕获 ctypes OSError (= DLL 内访问违例)
  ② crash_reporter.write_dump(reason) 落盘 Minidump 留证据
     (限流 / LOOM_NO_CRASHDUMP / 场景备份闭包由 crash_reporter 自管)
  ③ pop_and_fallback: 弹出坏模块 (先 deinit 再 FreeLibrary,
     契约热重载铁律; 状态全在基座)
  ④ 官方顶回 + registry.json 该条目 enabled=false 回写持久化
落地注: "删掉"实现为禁用回写 (enabled=false) 而非物理删文件 —
  可逆 (改回 true 即重试) 且留档 (条目仍在表里可追溯)。

--------------------------------------------------------------------
10. 版本演进
--------------------------------------------------------------------
- registry_version: 语义化增量 (主.次)。读侧遇更高次版本 = 按
  已知字段读 (新增字段透明); 主版本更高 = 拒绝组装 (破坏性,
  提示升级基座)。
- ABI 演进引用 loom_module.h 规则: 主版本变更 = 破坏性 (拒绝
  加载); 次版本追加 = 向后兼容 (允许, 基座按已知接口调用)。
- 字段新增只加不改 (reserved 精神, 对齐 LOOM_MODULE_INFO
  .reserved): 新字段只追加; 已有字段语义不变量、不改名、不复用;
  旧读侧忽略未知键不报错。

11. 示例
--------------------------------------------------------------------
(1) 最小官方条目 (= registry.json 现状 module_ref 条目照抄):
{
  "module_id": "module_ref",
  "path": "core_components/module_ref.dll",
  "official": true,
  "enabled": true,
  "provides": ["module_ref.echo"],
  "depends": [],
  "sha256": "",
  "note": "契约参考实现 (脚手架模板+探针无害靶); 首个真实组件 pipeline.dll 在 M2 落地后追加于此"
}

(2) 用户注入顶替条目 (与 (1) 同槽位并存于 components[]):
{
  "module_id": "module_ref",
  "path": "core_components/user/module_ref_fast.dll",
  "official": false,
  "enabled": true,
  "provides": ["module_ref.echo"],
  "depends": [],
  "sha256": "<实测十六进制指纹>",
  "note": "用户注入加速版"
}
要点: module_id 与官方相同 = 顶替 (非歧义注入); official=false
走信任闸; sha256 填实测值 (填了即强制比对); enabled=true 时
遮蔽官方, 官方作回退靶待命。

(3) 坏条目被弹出回写后的 json 形态 (自动回写, 无人工干预):
"components": [
  { "module_id": "module_ref", "official": true,
    "enabled": true,  ... },   ← 官方条目原样保留, 自动顶回
  { "module_id": "module_ref", "official": false,
    "enabled": false, ... }    ← 注入条目禁用留档 (可逆)
]
下次启动: 坏条目不再参与组装, 官方直接上岗。
