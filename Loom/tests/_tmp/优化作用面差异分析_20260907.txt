## 核心结论
1. **编译版与源码的每逻辑帧账目结构几乎相同** (27.2 vs 25.0ms @TPS20)。
   探针口径下两侧差距只有 ~10%, 远小于用户手测的 90 vs 55。
2. **手测 90 vs 探针源码 60 的缺口来源 (待复测定案)**: A 代理施工污染 +
   探针无头口径偏保守 ~10% (已知) + 用户实测含窗口合成路径。源码侧需在
   A 落地并回归绿后干净复测, 才能下"优化作用面差异"的最终结论。
3. **播放态恒走串行 C 内核 (par=0)**: _AABB_PAR_MIN_MODELS=512 闸门 vs
   混合500 单组 n≈400 卡位 — 并行档从未触发。C 侧 Win32 线程并行空置。
4. **8 线程并发实验 (B 代理)**: numpy B' 路径与 C 内核在 8 线程并发下同样
   退化 (0.57 vs 0.52ms/2行) → 通胀是 GIL/调度级, **非 DLL 内部线程争抢**。
   C 内核 DLL 本身清白; 提升并行度要先解 GIL 侧约束 (C 内核 nogil 调用
   或减并发争抢)。
5. **剩余账目大头 (编译版, 双候选)**: aabbs 混计 17.9ms (C内核5.2+组装+解包)
   + pipe_wait 13.5ms (TPS20 下放大, S1 等待段)。world_matrices/buckets/
   interp 合计 ~12ms 次级。

## 批4 排序建议 (基于编译版有效账目)
1. **4A 闸门 512→384 (第一优先)**: 直接激活 C 内核并行档, 预期 aabbs 内核
   5.2→~2.5ms, 一行改, 风险最低 — 直接回应用户"多核没用起来"。
2. **4C pipe_wait 管线 (第二)**: TPS20 下 13.5ms/逻辑帧, S1 等待期预取
   (frame_buffer.py 记账器可复用) — 与用户 90 帧目标的差距大头。
3. **4B AVX2 (第三)**: C 内核 5.2ms → ~2ms, 但 4A 落地后并行档收益会先吃掉
   一部分, 排后。
4. 4D world_matrices f32 (次级) / 4E buckets+interp (低优先)。
5. 新增候选: 相机位姿入插值 (A 代理在修, 与性能无关但同一批验收)。
