一、取证 (tests/_tmp/shadow_prof.py + shadow_microbench.py, n=501, LOOM_NO_NUMBA=1
   冻结口径 = 编译版等效)
   _scene_light_bounds_par 整体 1052us/调用, 解构:
     - ab/cd 属性链拆包填充循环 (for i,(a,b) in enumerate(aabbs): ab[i]=(a.x,...))
       = 633us  ← 大头, 60% (501 次 × 6 属性链 + namedtuple 解包)
     - corners tile/repeat 展开 = 103us (不是大头, 不动)
     - matmul+minmax = 306us (numpy 批量, 不动)
   numpy 行直填版整体 = 429us (2.45x)。
   buckets: 重填 1101us / 闸命中 13.6us; interp: compute_render_matrices 1226us
   —— 编译版账目 (buckets 1.35 / interp 1.08 ms/帧) 与源码同量级 → 属"两端共有
   的渲染帧成本", 非编译版特异放大; 按任务约束 (候选 c) 只报告不动, 控制爆炸半径。

二、改动 (全部 engine.py, 只加不改另一代理刚落地的组装循环体)
   1. _aabbs_batched(out_rows=None): 新增可选 (N,6) f64 行表回填 —— 组循环内
      rows[k_idx, 0:3]=mn_v / rows[k_idx, 3:6]=mx_v 按 sel 下标散写 (组序与 sel 序
      交错, 不能连续段拷); get_bounding_box 兜底行出口回填; tolist+Point3D 公共
      契约原样保留。out_rows=None 时零新增成本。
   2. _model_aabbs_par: 仅 visible_only=False (全量对齐 = 播放态路径) 分发行表并
      发布 _aabb_shadow_rows + 配对守卫 _aabb_shadow_gen=(id(out), n);
      visible_only=True 不发布 (sel 子集行序与 models 下标错位风险 → 消费方自动
      走旧属性链回退)。dirty 行级复用路径: 上帧表形状匹配即复用 (静止行沿用),
      脏行段重算增量更新; 池 worker 各写 rows_full 连续切片视图 (互斥段, 不碰
      实例字段); dirty 连续段行表走位置切片 (fancy-index 副本坑已防, 跨段块回退
      + 按需回填)。池分块块序=parallel._split_bounds 连续 range, 切片视图与 out
      拼接同构。
   3. _scene_light_bounds_par(row_input=None): 新增参数; (n,6) f64 时 ab/cd = 零
      拷贝列视图 (rows[:, 0:3] / rows[:, 3:6]), 消 633us 属性链; 形状/dtype 不符
      或 None 走旧路径 (逐位)。
   4. _compute_light_vps: 行表与 aabbs id 配对时, 可见过滤处同步花式拷 vis_rows
      (~39us), 随 vis_aabbs 传 _dir_light_vp(新 rows 参数); 配对守卫 (id+len) 挡
      过时表/行序错位; _dir_light_vp 自算路径同样受守卫保护。
