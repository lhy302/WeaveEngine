aabb 组装段去重优化报告 (2026-09-07)
====================================================================

任务: 消除 _aabbs_batched 组装段重复拷贝 (每逻辑帧逐行 Python 拷贝 vhN/m3N,
混合500 口径 ~9ms 组装段账; 编译版 16.4→25.9FPS 后的剩余堵点定基)。

--------------------------------------------------------------------
一、方案对比 (微基准 tests/_tmp/aabb_assembly_bench.py, 纯源码口径)
--------------------------------------------------------------------
场景形态复刻 压测500混合.json 实测分布: 460 球 (30 组参数) + 40 cube (4 size)
+ 1 plane = 501 物体; 分组结果 = 7 组 (V=3015/2501/2035/1617/1247/8/4),
501 行仅 35 个唯一 vh (同网格样本共享 _homogeneous_vertices 缓存对象)。
预装 numba+C 内核 DLL 在位 (LOOM_NO_NUMBA=1 口径), 60 轮均值, 多次独立运行
数字稳定。

组装段隔离计时 (只 vh+m3 拷贝, 不含分组/内核/tolist):
  0 现状 逐行写                 2.52~3.07 ms/帧  (分配 0.00MB)
  A 身份命中 + take(clip,out=)  0.25~0.31 ms/帧  (分配 0.02MB)  ★10.0x
  B 每帧 gather 无命中缓存      2.34~3.06 ms/帧  (分配 0.01MB)  无收益 (1.0x)
  C fancy index 临时 (uniq[inv]) 11.18~12.46 ms/帧 (分配 9.65MB)  大倒退
整机口径 (分组+组装+内核+tolist, 旧实现复刻 vs 新引擎整方法):
  旧 15.76~16.58 ms/call -> 新 7.56~7.88 ms/call (2.0~2.2x)
内核参照 (C 串行, 最大组 n=100 V=3015): 1.43~1.69 ms (非本批对象, 未动)

★关键发现 1 (任务书未预见的坑):
  np.take 默认 mode='raise' 时 out= 被 numpy 强制走内部临时缓冲
  (官方文档: "out is always buffered if mode='raise'") —— 首跑实测
  17.7ms + 9.65MB/帧, 与第 11 版 np.stack 32MB 每帧分配倒退同源。
  换 mode='clip' (inv 值域 [0,nu) 受控, 语义等价) 后真零临时, 收益兑现。

★关键发现 2 (端到端 A/B 揪出的形态坑):
  播放态稳态组装账其实很小: 行数探针 (aabb_rows_probe.py) 实测每渲染帧
  仅 ~25 行 (100 脏行/逻辑帧经 8-worker 池分块 = 4 调用 x 6-7 行小分组)。
  纯 (gi,V) 键在"同 V 不同内容"的分块组间碰撞 -> work-stealing 换块即
  恒 miss, 小分组 miss 固定开销反比 6 行逐行写贵 -> 交替 A/B 端到端
  实测 -3.6% (OLD 97.9 / NEW 94.4, 4 轮方向一致)。
  修复: 缓存键升级 = (gi, V, 完整行身份序列 tuple(id(vh))) —— 键即命中
  判定 (全等才命中, 数学上无假命中可能: 条目持 vh_refs 活引用, 活对象
  id 唯一); miss 且组内无重复 (nu==n) 时直接旧行为逐行写 (精确旧成本)。

三方案取舍逻辑:
  - C (fancy 临时) 淘汰: 每帧 n*V*4 f64 临时分配, 印证零分配铁律。
  - B (每帧 gather) 淘汰: 序列构建+inv 重算成本吃掉 gather 收益。
  - A (身份命中) 胜出: 命中帧 vh 段整段跳写 (vh 按 id(mesh) 缓存 + 网格
    不可变契约 => 同 id 同值); miss 帧唯一行写 (35 行) + take(clip) C 级
    gather。源码整组口径 10x; 端到端播放态 (小块形态) 不倒退 (+2%)。

二、改动清单 (全部在工作区源码, 编译版未动)
--------------------------------------------------------------------
1. engine.py _aabbs_batched (仅此一处, 组装段):
   - staging 缓冲项扩为 7 元组: (vhN, m3N, mn, mx) + (uniq, inv, fresh)。
     uniq = 唯一行表 (n,V,4) f64, 惰性按唯一数 grow-only (混合500 仅
     ~6 行/组, 不随行数 cap 翻倍, 免 vhN 之外再压 32MB);
     inv = 行→唯一行索引 intp, grow-only (首建 max(n,64));
     fresh = miss 哨兵 (键命中即 True, 跳写 vh 段)。
   - 缓存键 = (gi, V, tuple(id(vh) per row)): 键即命中判定; 池分块"同 V
     不同内容"组间不互踩 (纯 (gi,V) 键分块碰撞教训见上); 条目持 vh_refs
     (唯一 vh 引用表, 存于 uniq_rows) 使同键必同内容。
   - miss 帧: 建唯一行表 (uniq_rows) -> nu==n 时旧行为逐行写; 有重复时
     唯一行写 uniq + np.take(uniq_v, inv[:n], axis=0, out=vhN_v,
     mode='clip') 一次 C 级 gather 展开回 n 行。
   - 命中帧: vhN 前 n 行整段跳写; m3 段恒逐行原地写不动 (96B/行小缓冲,
     矩阵每帧变无命中空间)。
   - buf_cache 64 键护栏: 分块组合漂移累积超限整体清空 (代价=下帧一轮
     miss 重建, 稳态键集远低于阈值不触发)。
   - group 分组逻辑/内核调用/tolist 解包零改动; docstring 补注记。
2. 新增 tests/_tmp/aabb_assembly_check.py (对拍闸门, 18 项)。
3. 新增 tests/_tmp/aabb_assembly_bench.py (三方案微基准 + 整机口径)。
4. 新增 tests/_tmp/aabb_ab_e2e.py (播放态交替 A/B 端到端, OLD=改前复刻
   猴子补丁 / NEW=现行引擎, 4 轮配对)。
5. 新增 tests/_tmp/aabb_rows_probe.py (播放态组装行数形态探针)。
禁碰清单遵守: 稳定区/编译版/开源版/fastpath.py/core_clock.py/C 源码
均未动; 台账未改 (主线程登记)。

--------------------------------------------------------------------
四、风险与边界 (已设防)
--------------------------------------------------------------------
- 假命中: 键=完整身份序列 + 条目持 vh_refs 活引用 (缓存存活期旧数组不被
  GC -> 活对象 id 唯一), 同键必同内容; R3 用例 (每帧 GC 后换对象换值)
  实证 6 轮全对。
- 池分块碰撞: 键含完整序列, "同 V 不同内容"分块组天然分键; nu==n 回退
  精确旧行为, miss 固定开销不再放大。
- 最坏退化: vh 集合每帧全变恒 miss = 旧逐行 +id 构建 (~+5% 组装段内,
  端到端 A/B 稳态不现形), 可接受。
- thread-local 安全: 缓存仍挂 self._aabb_staging thread-local, 各线程
  独立缓存互不干扰; 64 键护栏防膨胀。
- 内存增量: uniq ~6 行/组 + inv n*8B/组 + vh_refs, 相对 vhN 32MB 可忽略。
- m3N 段语义: 仍逐行写, 数值口径零变化。
