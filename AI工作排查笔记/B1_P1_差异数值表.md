## B. 设计 vs 实测冲突 (记录差异, 未改设计; 均需 P2 前拍板)

### B-① 设计 §1.2/§1.1#16: "penetration_slop=0.005 追踪贴边, 漂移随 slop 线性" —— **实测不成立**
- `settings={'penetration_slop': 0.02/0.005/0.001}` 三档, 全部场景落点**逐位相同** (probe7 复刻 -0.5190, 软落 0.48000, 硬落 0.50000)。
- 实测静止穿透量由**落地撞击速度**决定: 10m 硬落 → 0mm (精确触碰); 1.5m 软落 → 20mm; probe7 零厚盒 → 19mm。
- 对 P2 影响: (1) R2 的 0.005 默认值保留无害但**无效**; (2) 所有落点 \|Δ\| ≤ 0.02 **全部满足**设计 §5 用例 1/16 的 0.03 容差 (`test_physics` 语义测试走 legacy 路径, 不受影响); (3) 视觉微沉 2cm 待 P5 人工看 (0.02 大沉) —— 若在意, 可尝试 `max_contact_constraints`/`temp_allocator` 无关参数, 或改为不依赖库文档承诺的实现: 桥在 post_step 对"落定未睡"体做位置微修 (不建议, 引入抖动风险)。**结论: 接受 0-2cm 沉入, 靠容差 0.03 兜住。**

### B-② 睡眠体残速 = 上次累加重力写速 (-0.1633), 契约 \|v\|<0.01 破坏 —— **已修并锁定**
- 机制: 每帧写 v.y=-9.8/60, Jolt 接触解算归 0, 但入睡时刻 Jolt 保留存留速度; post_step 回读到 -0.1633 写回 rb.velocity → 引擎契约 (碰就停, |v|=0) 破坏, **first_person 用 `abs(rb.velocity.y)<0.01` 检测接地会失效**。
- 修复: post_step 对 `is_active=False` 的体把回读速度**归 0** 写回 (睡眠=不动, 定义上合法); 单测锁定: 用例 2 = 0.000000。
- 对 P2 影响: **必须带上这个零化分支**, 否则玩家脚下恒有 -0.163 速度。

### B-③ 设计 §1.4: "culverin euler_to_quat = 列 Rz@Ry@Rx, 同角差 0.154 (probe10)" —— **实测不成立**
- 桥转换器 (引擎行 Rx@Ry@Rz → Shepperd) 与 `culverin.MathService.euler_to_quat` 在 (0.3,0.5,-0.2)/(30,45,60)/y90 三组角上输出**逐位一致** (max 差 3.4e-08, f32)。probe10 的 0.154 差源自其参考四元数算法缺陷 (与本次发现的 Frobenius 归一化 bug 同源: 旋转矩阵 Frobenius 范数 = √3 而非 1)。
- 桥自带转换器**保留** (设计已定, 且它现与本库自身一致), 但需更正设计报告 §1.4 说法; P2 无需额外 euler 依赖。附:R4 单测 20°单轴、90°单轴、复合+往返全过 (0.00e+00 / 2.22e-16)。

### B-④ 表亲同树 (设计已列收窄项, 实测确认发生) —— 需人工裁决
- 根下两分支各一球相向 2m/s: 世界中心距 0.000, 完全穿过。引擎 `_related`(仅祖先) 会互撞; 桥"同树位"方案不互撞。
- 组合方案备选: (a) 接受 (真实场景表亲很少占据"会相撞"位置); (b) 每棵子树按"祖先排除"给 pair 加例外 =需要 Jolt 滤波增强 (无 API, 只能每对建体时设置额外位/或动态改 filter, 成本高); (c) 与用户讨论长期语义。
- **已进入 P5 人工实测清单 (低风险)。**

### B-⑤ 睡眠红利 (设计 §6 风险 4 担心"每帧写速度会防睡") —— **实测不成立, 利好**
- 尽管策略 R 对清醒体每帧写重力速度, 落定后仍于 ~1.03s 入睡 (9e), 50 球 1600 步后 active=0/50 (9c)。Jolt 睡眠计时以**步进后低速**计, 不受 set_linear_velocity 唤醒影响 (实测证据: 落体+逐帧写速仍睡)。策略 R 直接可用, 无需改设计。

## C. 新 API 事实 (P2 工程直接引用)

1. **查询必须冲刷**: `is_active/get_motion_type/get_velocity` 等查询在 create_body 后未 `step(0.0)` 抛 `RuntimeError: Cannot query ... until it has been flushed`。桥必须在 build/ensure_models 末尾 `w.step(0.0)` (设计 §3.2 已有, 现实证必需)。
2. **create_bodies_batch 类别/掩码缺失 + 默认=幽灵**: pyi 仅有 positions/sizes/shape_type/motion_type; 不补贴价时两动态球**完全不互撞** (比设计推测的 0xFFFF 陷阱更差: 默认连互撞都不给)。补贴 200 次 set_collision_filter 后语义正确, 但总耗时与逐体 create_body (505.5 vs 501.3 ms) **持平**。
3. **set_collision_filter 也要先冲刷** (batch 后直接调报 RuntimeError)。
4. `MathService.euler_to_quat`/`quat_to_euler`/`quat_rotate_vec3(q, v)` (两参元组) 均为实例方法; 与桥转换器一致 (见 B-③)。
5. `create_body` 显式传 `category/mask` 全程可用; 掩码 0xFFFFFFFF & ~bit 与树位位 >=16 均验证过穿透/碰撞语义正确 (bridge_api_check 部分 6 + 全量用例)。

## 性能总结表 (50 球+地面, 落定后, 单快照)

| 路径 | 实测 | 说明 |
|---|---|---|
| raw `w.step(dt)` | 2.0-3.6 µs/帧 | Jolt 睡眠态; P0 基线 2.4µs 一致 |
| 桥整帧 (pre+step+post) | **650.5 µs/帧** (第一版 4994 µs) | 已批量向量化; 相位拆解: pre=115.7 / step=2.1 / post=504.2 |
| 每帧写速度 (防睡破坏版) | 770.0 µs/帧 | 睡眠红利 = 18% |
| 双世界双线程 (100 球拆分) | 单 1504.7 vs 双 1309.2 µs/帧 → 1.15x | Python 回写段 (GIL) 摊薄; 纯 step 是 1.59x |
| 50 球一次性建体 (桥 build) | ~37ms 量级 (P0 数据, 逐体含显式滤波) | 播放开始一次性, 可接受 |
| 200 体建体对照 | 逐体 505.5ms / batch+补贴 501.3ms | 不用 batch |

**对 P2 的性能影响结论**: 桥 Python 段 ~650µs/帧 (占 60fps 预算 4%) << legacy 引擎物理 (毫秒级, 且为 D8 标的主堵点)。引擎版接入后: (1) post_step 的逐体循环可再优化 (合并 is_active 查询、减少 Vector3 分配、按"有变化才写"快筛 —— 预期可压到 250-350µs/帧); (2) `num_threads` 建议 max(1, 逻辑核-2)=16 与设计一致, 直接可用; (3) 双世界收益 1.15x 表明多解释器/双物理世界没必要 (收益 < Python 摊薄损失)。
