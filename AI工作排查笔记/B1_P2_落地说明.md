## 2. 逐文件改动说明

### 2.1 physics_bridge.py (新, ~870 行, 零 GL)

结构 (自 P1 `_perfprobe\bridge_headless.py` 改进移植, 对象模型为引擎 GameObject/驱动
共用模型的鸭子类型):

1. **库探测**: `import culverin` try/except → `cv_available` (False → 桥 enabled=False,
   引擎/驱动自动回退 legacy, 不 import engine/pygame)。
2. **几何静态助手** (与 engine.GLEngine 对应方法公式逐位一致, 供 SceneDriver/测试复用):
   - `model_world_matrix` (S@R@T 行主序 @ 父链, 帧内记忆化缓存)
   - `collider_bounds` (box=世界 AABB (mn,mx); sphere=中心+最大半长)
   - `pair_overlap` / `push_out` / `resolve_collisions` / `move_with_collision` /
     `get_collisions` / `collider_hit` / `related` (严格< 贴边等契约逐位保留)
   - 网格顶点缓存按 id(mesh)+列表身份 (同 engine._homogeneous_vertices)。
3. **R4 转换器**: `euler_to_quat_batch` / `quat_to_euler_batch` (Shepperd, 引擎行
   Rx@Ry@Rz ⟷ culverin 列四元数; P1 已与 MathService 逐位一致)。
4. **PhysicsWorldBridge**:
   - settings: gravity=(0,0,0) (R1 世界无重力) / penetration_slop=0.005 (P1-B-①: 无效
     无害) / num_threads=max(1, 逻辑核-2)。
   - `build(models)` → 逐体 `create_body` (显式 category/mask + friction/restitution +
     mass; **不用 create_bodies_batch** — P1-10c: batch 无滤波参数且默认幽灵, 补贴价
     无净收益) → `step(0.0)` 冲刷 (P1-C①: 建体后不冲刷, 查询抛 RuntimeError)。
   - `ensure_models(models)` 差量 (新增/移除/形态签名变→rebuild; 桥已 destroy → 幂等 no-op)。
   - `pre_step(dt, gravity=None)`: ① 脏检测 (pos/rot 变化 + 祖先链脏传播) → 世界位姿
     `set_position/set_rotation`; ② 策略 R: 仅 (rb.velocity 脏 或 is_active 清醒且
     use_gravity) → `set_linear_velocity` + 手动累加 `v.y += gravity*dt` (gravity 由
     引擎实例传入, 缺省 -9.8); ③ 睡眠体跳过写 (性能红利, P1-B-⑤ 写速度不防睡实证)。
   - `step(dt)` → 单次 C 步进 (GIL 释放, Jolt 内线程池)。
   - `post_step()`: positions(f64)/rotations(f32)/vel(f32) np.asarray 零拷批量回读;
     按 user_data 登记号 argsort 映射行; 批量 quat→euler; **is_active=False 体回读
     速度归 0 (P1-B-② 必修项)**; 有父体世界→局部换算 (与 engine 同公式)。
   - **建体时把模型当前速度推入 Jolt** (`set_linear_velocity` in _build_one) —— P2 实测
     修复: 若脚本在建体帧前已设 velocity, 脏检测 (v==sync) 永不触发, 新体将静止
     (设计缺口, 已补)。
   - 树位: `_tree_bit_for` 每根根树 1 位 category (mask=ALL_MASK&~bit, >31 轮转+警告);
     全程显式传。

关键摘录 (策略 R + 睡眠体归零):

```python
# pre_step (速度策略 R + R1 手动重力):
if vel_dirty:
    w.set_linear_velocity(ent['handle'], v[0], v[1], v[2])   # 脚本改速 (唤醒)
    sync[2] = v
elif getattr(rb, 'use_gravity', False):
    if self._active_ok(ent['handle']):
        av = v[1] + g * dt                                  # R1: 手动累加 (引擎重力)
        rb.velocity = Point3D(v[0], av, v[2])
        w.set_linear_velocity(ent['handle'], v[0], av, v[2])
        sync[2] = (v[0], av, v[2])
# post_step (P1-B-② 必修):
wv = np.where(ws[..., None], wv, 0.0)      # 睡眠体: 回读速度归 0 (Jolt 残速不外泄)
```

### 2.3 ※P2 重大发现: culverin set_motion_type 卸载崩溃 (已规避)

- 现象: 播放期静态体被脚本/动画移动 → 桥一次性升级 `MOTION_STATIC→KINEMATIC`
  (设计 §1.1#4) → 下次 `w.step(dt)` **原生崩溃 0xC0000005** (cuJolt/release 0.14.0;
  faulthandler 栈顶 = physics_bridge.step)。
- 交叉验证 (最小直调): `create_body(STATIC)+set_motion_type(KINEMATIC)+step` 崩溃;
  `step(0.0)` 冲刷后再 step 也崩溃; build 即 KINEMATIC + set_position/set_rotation +
  step 正常; destroy+rebuild 为 KINEMATIC 正常。
- **处置: 升级路径改为"destroy + 以 KINEMATIC 重建"** (`_build_one(m, motion_override)`),
  行为等价 (升级一次性, 之后每帧脏同步仅 set_position/set_rotation, P1 probe7 已证
  kinematic 平台支撑语义)。
- 备注: 该崩溃发生在 **integration 全量真实窗口渲染路径** 才暴露 (无头桩不建体/
  不跑脚本旋转静态体), 故 P2 实测链 (test_integration + PlayerApp 冒烟) 必须保留。

## 4. 未决问题 / 已知差异 (P3/P5 清单)

1. **表亲同树不再互撞** (树位方案收窄项, P1-FACT): 同根非祖先两球相向对穿
   (min 中心距 0.000)。引擎 `_related`=祖先语义互撞。**待用户人工裁决**。
2. **推箱/滚箱/翻箱 = 表现升级**: 旧"谁动谁被挡死" → Jolt 真实冲量 (测试 #9: 被撞球
   被推走 6.13m)。新玩法, **用户实测重点**; 若觉得太滑可调摩擦系数 (新检查器字段)。
3. **静态体被移动时升级 KINEMATIC = 销毁重建**: 语义与设计一致 (唤醒压着的动态体),
   但重建有句柄切换 (桥内不可见); set_motion_type 原生崩溃已规避 (见 §2.3)。
4. **R3 形状冻结**: 缩放/旋转动画中 box 不重建 (出生尺寸 OBB); 动画 scale/rot 的
   碰撞表现与引擎"逐帧 AABB"有视觉差异, P5 人工看录制/滚动动画。
5. **>31 根树**: 轮转位+警告 (相邻桶树间额外"不互撞"); 现实场景根数 10-30, 低风险。
6. **Vk 播放器缺口残留**: (a) SceneDriver 未加载 animator/audio_source 组件字段
   (B1 范围外, 记录) (b) 后端口喂输入 (driver.key_state) 未接 — 输入桥接相邻小缺口
   (c) _DriverUI 为 no-op 空壳 (运行时 UI 在 Vk 未实现) (d) 驱动层 move_with_collision
   走几何 (与引擎同语义), 与 Jolt 双写交互的抖动待 P3 对齐。
7. **collider.enabled=False / shape='none' 的刚体物体桥不建体** (设计 §1.1#7) →
   桥路径下该物体不再有重力/速度运动 (legacy 仍会); 已知差异, 极致边缘用法。
8. **Nuitka 打包 (P6)**: `--include-data-dir=<venv>\...\culverin.libs=culverin.libs`
   (delvewheel 改名 MSVC 运行时, 缺 → 0xC0000135); 编译只等用户指令。
9. **发布链**: 无 culverin 的 MyGame.exe 会静默回退 legacy (设计建议 Up-Info 提示
   "需 culverin 0.14.0"; 保留为 P6 决策点)。
10. **测试护栏**: 现有契约测试全走 legacy (引擎桩 __new__ 无 _phys_bridge_auto;
    桥用例独立文件, 无库 SKIP); 若未来让桥默认接管, test_physics 的数值期望需按

## 5. 环境与 FIX 备注

- culverin 0.14.0 (gil-enabled, double-precision) 实测关键事实 (P2 补充):
  - `set_motion_type(STATIC→KINEMATIC)` + `step()` = **0xC0000005 崩溃** (设计缺口,
    修复已上, 勿回退 set_motion_type 用法)。
  - 建体/重建后**立刻** set_linear_velocity/set_position/set_rotation 均安全
    (V8/V9/V10 交叉验证), 步进前无需额外冲刷。
