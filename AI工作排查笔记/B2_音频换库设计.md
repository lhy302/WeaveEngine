## 0. 结论 (TL;DR)

- **选型: game-audio 2.1.0 (miniaudio C++20), 已实机探测并验证; Synthizer 0.12.6 出局**:
  无 cp312-win 轮子 (`--only-binary :all:` → No matching distribution), 源码构建被其
  CMake 检查硬拒 (MSVC 1944 does not pass this check), 本机双路 (裸 pip / vcvars shell)
  均装不上 → 无法用于现引擎 (py3.12 + Windows + Nuitka)。
- **game-audio 实测**: 单文件 pybind11 pyd (948KB, miniaudio 静态链入, 零额外 DLL);
  `load_sound`/`play_sound`/`set_sound_looping`/`set_sound_volume`/`stop_sound`/3D 全部可用;
  调用延迟 play_sound 0.027ms、set_volume 0.004ms、load ~0.2-0.3ms (毫秒级薄绑定, 非热点);
  **格式实测 = wav / mp3 / flac 可用, ogg(vorbis)/opus 加载失败 (-10 MA_INVALID_FILE)** —
  句柄级 OGG 不支持是硬伤, 设计以"per-file 回退 pygame.mixer"兜底 (pygame 保证 wav/ogg)。
- **Nuitka 打包: 默认参数即可**。实测 standalone 试打包 (py3.12 + nuitka 2.7.1),
  `dist\game_audio\game_audio.pyd` 被自动复制, exe 内 import/initialize/加载/循环播放/
  shutdown 全通过, EXIT=0。**唯一必须遵守: 退出前必须调 AudioManager.shutdown()**,
  否则 miniaudio 设备线程挂住进程 (首轮无 shutdown 的 exe 实测超时挂死)。
- 实施方式: 新增 `Loom/audio_backend.py` 双后端适配层 (game-audio 主 + pygame.mixer 兜底,
  自动降级+按文件回退), `AudioSystem` 公开 API 不变; 3D 声像做可选特性 (默认关闭零行为变更)。

### 1.2 推荐 + 理由

**推荐 game-audio 2.1.0**:
1. 唯一"装机即用"选项 (wheel 现成, 零依赖, 单 pyd 无 DLL 链)。
2. API 与 AudioSystem 需求天然对应 (文件→句柄→音量/循环/位置→播放/停止),
   桥接层薄 (~60 行), 符合"最小改动+稳定优先"。
3. 性能判据早已明确: 音频=Case1 (非热点), 换库=特性向 (多格式/3D/低延迟/组音量),
   game-audio 这些特性全部有且可关。
4. Nuitka 兼容实测通过 (本次试打包为唯一未知项, 已消)。
5. Synthizer 唯一溢价 (高优先级线程防 GIL/GC 卡顿) 与 game-audio 的
   miniaudio 设备回调线程在"音频流不经过 GIL"这一实质点上等价 (都 C++ 侧), 溢价不成立。

**Synthizer 弃用并留档**: pip 无 Windows 轮子 + CMake 编译器检查冻结在本机 VS2022 版本之前,
装不上 = 一切特性免谈。若未来用户明确要"合成器级"(实时生成音效/效果器), 再作第二方案评审。

## 2. API 桥映射表 (引擎 AudioSystem ↔ game-audio)

### 2.1 映射 (AudioSystem 公开 API 完全不变)

| 引擎/AudioSystem | pygame.mixer (现状) | game-audio (新主后端) |
|---|---|---|
| `_ensure()` 惰性初始化 | `pygame.mixer.get_init()`/`init()` try/except | ga 后端: `AudioManager.get_instance().initialize()` try/except (首次 True, 二次 False, 实测 0.08ms); 失败→回退 pygame 路径(现有代码); 双双失败→置不可用, 一切操作静默 no-op (与现状无设备时 mixer 挂掉全静默同语义) |
| `load(path)` | `pygame.mixer.Sound(path)` 缓存 | `ga.load_sound(path)` → 缓存 `(path, owner) -> LightBackendHandle`; **FileLoadException → 按文件回退 pygame.mixer.Sound** (ogg/opus 自动兜底); 兜底也失败→缓存 None (与现状"None 永久缓存"一致) |
| `play(path, loop, volume, owner=None)` | `Sound.set_volume(clamp(v))` + `Sound.play(loops=-1 if loop else 0)` | ga 句柄: `set_sound_looping(h, loop)` → `set_sound_volume(h, clamp(v))` → `play_sound(h)`; 若该句柄已 playing → 追加播放实例 (实测支持) |
| `stop(path, owner=None)` | `Sound.stop()` (停该 Sound 全部通道) | 「按 owner 逐个 stop_sound(h)」; 二次 stop 幂等 (实测无异常) |
| `play_sound(path, volume)` | `play(path, False, volume)` | 同左, owner 默认 None (脚本一次音效共享句柄) |
| 退出 | pygame.quit() 隐式 | **必须 `AudioManager.shutdown()`** (否则进程挂死, 实测); 挂在引擎退出链 + atexit 兜底 |

### 2.2 关键设计决策 (均基于实测)

1. **句柄按 (path, owner) 缓存, owner=组件身份**:
   - 实测 `load_sound()` 每次返回**新句柄** (绑定层无路径级缓存: 二次 load ≠ 同一句柄) →
     由我们层缓存, 句柄数可控。
   - `set_sound_volume/looping` 是**句柄级**状态 (无 get_sound_volume/get_sound_looping),
     同一路径被多个组件共享时句柄级音量会互相踩 → **每个 AudioSourceComponent 各自持有一份
     句柄 (owner=id(component))** 即与 pygame"每 Channel 独立音量"语义等价且更强。
   - `update_audio` 改传 `owner=id(a)` (engine.py 两行 + MockAudio 契约方法加 kwarg)。
   - 记忆换行为: 同文件每组件解码一份 (实测 load 0.2ms/88KB, 大文件需人工留意; 若未来资源大,
     可退 path-keyed 共享句柄模式 = 现状语义, 留开关)。
2. **音量**: 引擎侧维持 `max(0, min(1, v))` 前裁; ga 对越界值实测不报错 (0.7/-0.5 均接受), 双保险。
3. **loop**: 引擎只在"播放状态变化"时 play, 每次 play 前设 loop → 实测前置设置稳定生效
   (0.5s 文件 1.3s 后仍在播)。**播放中 set_sound_looping(False) 实测并不终止** —— 引擎本就不在
   播放中改 loop (改 loop 只影响下一次 play), 无行为影响; 文档注明该限制即可。
4. **is_sound_playing 仅作调试/测试辅助**: 循环中"改旗标后即刻状态"实测不可靠 (真听感为准),
   引擎逻辑不依赖它 (update_audio 用 _key 自查), 测试断言只用早期 True / 结束 False 极性。
5. **多实例**: 同句柄重复 play_sound 实测共存 (2 次 play → playing=True; stop 全停) —
   与 pygame Sound.stop"停全部通道"语义一致。
6. **失败静默**: 缺失文件必须**捕获 FileLoadException 返回 None** (P1 实测: missing → FileLoadException;
   destroyed → InvalidHandleException; shutdown 后 → NotInitializedException —— 三种全捕获, 边界全覆盖)。
7. **异常类型分层** (引擎统一 `except Exception: pass` 兜底即可, 但按类型给出日志):
   - `FileLoadException` = 文件缺失/无法解码 (回退 pygame 后仍失败 → None 缓存)
   - `InvalidHandleException` = 句柄已被销毁 (destroy_sound 后误用; 引擎正常路径不触发)
   - `NotInitializedException` = shutdown 后调用 (引擎在 shutdown 后不再播放, 不该触发)

### 2.3 双后端结构 (audio_backend.py)

```
AudioSystem (公开 API 不变: load/play/stop/play_sound/_ensure)
 └─ AudioBackend  (audio_backend.py):
     ├─ _Backends.GAME_AUDIO (主):  cap
     │    - import game_audio; AudioManager.get_instance()
     │    - _ensure(): initialize() → ready
     │    - load(path, owner)  -> (GAHandle | pygameSound | None)
     │    - per-file fallback: FileLoadException → pygame.mixer.Sound(path)
     ├─ _Backends.PYGAME (兜底): 现状 AudioSystem 逻辑原样搬入 (零回归)
     └─ 选择: 环境变量 LOOM_AUDIO_BACKEND = auto(默认) | game_audio | pygame
          auto = ga import+init 成功即 ga, 否则 pygame; 二者皆不成功 → 静默降级 (同现状无设备)
```

- pygame 兜底播放 e.g. ogg 文件时, 其 play/stop/volume 走原来的 pygame.mixer 代码路径
  (AudioSystem 内部对每缓存项记 `backend_type`, 派发到对应实现)。
- 两组后端可并存 (ga 引擎 + pygame mixer 同时 init), 互不干扰 (SDL 与 miniaudio 不同设备会话)。

## 3. 3D 声像设计 (可选特性, 默认关闭)

- **默认关闭 = 零行为变更**。开关: `AudioSystem.spatial_enabled = False` (engine/编辑器设置,
  引擎类常量或场景级 flag; 文档明确默认关)。
- 开启后:
  - `AudioSourceComponent` 加字段 `position = None | (x, y, z)` (世界坐标列存储为元组,
    不设=非空间化, 与默认行为一致; 序列化加 `"position": None|(x,y,z)`, sceneio 双向兼容旧文件)。
  - `load` 时若组件 position!=None: `set_sound_spatialization_enabled(h, True)` +
    `set_sound_min_distance(h, 1.0)` / `set_sound_max_distance(h, 100.0)` /
    `set_sound_rolloff(h, 1.0)` (类常量可调, 默认项不设也 OK, miniaudio 有默认)。
  - `update_audio` 扩展: spatial 模式下每帧 `set_listener_position/direction/up`。
    帧约定策略: **源位置与 listener 全部用引擎同一世界帧 (Point3D → Vec3 直接平移) + 
    listener direction = 引擎相机 forward / up=(0,1,0)** —— 自洽即可, 不需要硬凑
    ga 文档中"OpenGL -Z 前"的宣称 (ga 的 direction 是显式方向向量, P3 实测 set/get 原样往返;
    引擎 forward 公式 engine.py:952-954: yaw=0 时 = +Z, 与 mat4_view_yaw_pitch 同约定)。
    换算函数单点 `_engine_to_ga_vec3(p)` 便于日后若需改帧。
  - 每帧对 position!=None 的组件: `set_sound_position(h, Vec3(x, y, z))`
    (实测句柄级 set/get 数值往返一致; 每帧调用 0.004ms/次, 可忽略)。
  - 已发布的场景默认 position=None → 不开 3D 也用不了 3D, 兼容无忧。

## 6. 风险

| # | 风险 | 等级 | 对策 |
|---|---|---|---|
| 1 | **无输出设备时 initialize() 抛 AudioException** (文档声明; 本机为成功路径, 未实测失败形态) | 高 | `_ensure()` 全 try/except → 自动降级 pygame → 再失败全静默 (与现状 mixer.init 异常吞掉同语义); 无头测试环境 (-1) 不初始化、无崩溃由该路径保证 |
| 2 | **不 shutdown 则进程挂死** (miniaudio 设备线程) | 高 | 引擎退出链调用 + atexit 兜底; 试打包实证 shutdown 后 EXIT=0 |
