## P1 滚动摩擦没生效 (球滚起来停不下来)

**根因 (实测确认)**: culverin 0.14.0 **没有原生滚动摩擦/角阻尼**:
- `create_body` 合法关键字实测 (TypeError 列出可取集): pos/rot/size/shape/motion/
  user_data/is_sensor/mass/category/mask/**friction**/**restitution**/material_id/ccd
  —— 无 linear/angular_damping/rolling_friction。
- `_culverin_c.pyi` 321 行: `linear_damping` 只属于 `create_soft_body`;
  496-497 行: `set_linear_damping`/`set_angular_damping` 被**注释禁用**。
- Jolt 摩擦模型对纯滚动球不做功 (接触点无滑动 → 库仑摩擦无效应) —— 实测
  `rolling=0(关闭)` 时球滚 8s 仅 3.0→1.4 m/s, 几乎永不停 → 用户"停不下来"成立。

**修复 (桥内实现, physics_bridge.py)**:
1. 新字段 `rolling_friction` (默认 0.1, 范围 0-3, 0=关闭): ColliderComponent/
   RigidbodyComponent (engine.py 396-409 / 423-434 / add_rigidbody 766-773)。
2. 检查器新行 "滚动摩擦" (与摩擦系数/弹性同控制组): loom_gui.py 1770-1791。
3. 序列化/快照: sceneio.py `collider`/`rigidbody` dict 加 `rolling_friction` 键
   (105-118 / 191-199 / 215-223; 旧文件缺键 → 缺省 0.1, 兼容); undo.py 快照
   第 5 槽 (collider) / 第 6 槽 (rigidbody), apply_snapshot 旧 2/3/4/5 元兼容
   (42-52 / 86-100)。
4. **衰减公式** (post_step 878-951): 对清醒 (is_active) DYNAMIC 体:
   ```
   f  = max(0, 1 - mu * rolling * K * dt)      # K = 23.0 (标定)
   ω *= f   (全分量);   vx/vz *= f   (仅水平, vy 不碰——不影响下落/弹跳)
   ```
   - `mu` = 物体自身摩擦系数 (动态体=rb.friction) —— 与用户"滚动摩擦与 μ 相关"
     需求对应: 摩擦越大滚筒停得越快 (衰减率 = rolling × μ × 23)。
   - Jolt 接触侧继续用 pair 组合 (sqrt(μ1·μ2)) 管滑动/推挤, 桥只补"滚动阻力"。
   - **不防睡眠**: 仅 `|ω| > 0.06 rad/s` 才写回; 阈值以下停写 → Jolt 自然入睡 →
     post_step 睡眠体速度归零兜底 (active 计数红利保留)。
5. 附带修: `_entry_signature` 数值字段 bool() 改 float() (626-641) —— 原 bool()
   使 0.5 vs 0.2 摩擦改动画等签名 → 播放中改摩擦不重建体 (真 bug, 同函数内顺手修)。

**标定数值 (roll_calib_probe.py, r=0.5 球 / μ=0.5 / 平地面, 60fps)**:
| 场景 | 实测停止时间 | 说明 |
|---|---|---|
| rolling=0.1, μ=0.5, v0=3 m/s | **3.98 s** | 目标 2-4s ✓ (K=23) |
| rolling=0.1, μ=1.0, v0=3 m/s | 1.98 s | μ↑ → 更快 ✓ |
| rolling=0.5, μ=0.5, v0=3 m/s | 1.37 s | rolling↑ → 更快 ✓ |
| rolling=0 (关闭) | 不停 (0.75s 后仍 2.06 m/s) | 关闭语义 ✓ |
| rolling=0.1, μ=0.5, v0=1 m/s | 2.50 s | 慢速也停 ✓ |
| 停后 | active=0 | 睡眠红利保留 ✓ |

## P2 碰撞器开了物体浮空完全不动

**复现调查 (实测反证, 坦白记录)**: 三途径均**未复现"浮空不动"** ——
- bridge 直测 (p2_float_probe.py): 新动态体 (场景同型: 地面顶 -2 + 玩家盒 y=0)
  帧 0 即 active=True, 正常下落落定。
- EditorApp 真 GL + 跳台试炼播放 (p2_editor_probe.py, 含 first_person/count_touch
  脚本): 玩家 y=0→-1.619 落定, active 1→0, 播放结束快照还原 y=0.000。
- Qt 真窗口 10 轮播放: 每轮 玩家 y→-1.34~-1.37 (下落中) ✓。
- 推断: "新体初始即入眠" 只是**假设** (任务书重点假设), 本环境 culverin 将新体
  直接入活跃集; 用户现象可能由 (a) 其当时场景的其它组件组合, (b) 其它环境因素
  触发。**仍需保留本修复**: 机制廉价、零回归, 且覆盖"以睡眠态入世"的边缘
  (culverin 文档明确 is_active 对 PENDING 体返回 False / 重力=0 时 Jolt 可在建体后
  立刻入眠的版本差异)。

**修复 (防御性, physics_bridge.py)**:
1. `_build_one` (675-698): DYNAMIC + use_gravity 体建后立即 `w.activate(h)`
   (culverin 文档: 对 PENDING_CREATE 兼容, 命令排队到下次 step 生效)。
2. `pre_step` (783-845) 激活保底: 每帧 `guard_left -= 1`; 建体后 **90 帧 (1.5s @60fps)**
   内、且体睡眠 (`is_active=False`)、且**从未被脚本/碰撞碰过** (`|v|<1e-3`, 无活动
   速度) → `w.activate(h)` + **当帧手动累加重力一次**。一旦该体被观测到清醒过一次
   (或脚本写过速度) → guard 清零, 此后**永不触碰** → 目标"落定后仍能自然入眠"
   不受影响 (防抖设计: 不是"永远醒着", 而是 90 帧保底窗口)。
3. use_gravity=False 动态体不激活 (悬浮体由脚本/碰撞天然唤醒, 不耗 CPU)。

**验证**: 用例 11 (test_physics_bridge.py): 球 5m 下落 6s 后 active=0 + 位形稳定
(保底不防眠断言); EditorApp 复测前后数值**逐位一致** (-1.619 / active=0) —— 零回归。
GUI 10 轮每轮下落正常 (p4_smoke_out.txt)。

## P3 摩擦选项有两个

**根因**: P2 把"摩擦系数/弹性"同时放进 碰撞体区 (静态/运动学体用) 与 刚体区
(动态体用); 同一物体两侧各显示一组 → 用户困惑"到底哪组生效"。

**修复 (loom_gui.py 1765-1791)**: **单组显示** switch:
- 物体有 rigidbody → 只显示刚体组 (摩擦系数/弹性/滚动摩擦, 写 rb.*);
- 无 → 只显示碰撞组 (写 col.*)。
- 数据仍双通道 (桥 `_build_one`: 动态体用 rb 值, 否则 col 值), 序列化保持两键
  (实际三键) 缺省兼容 —— 旧文件不变。
- `_sync_inspector_values` 补 col.roll/rb.roll 回读键 (2156/2162)。
- 撤销/即时写回走既有 _spin → edit_model 协议, 无新路径。

**验证 (p3_inspector_probe.py, 真 Qt 窗口, ALL PASS)**: 刚体对象只显示 rb 组三键
(无 col 组); 非刚体只显示 col 组三键 (无 rb 组); **真实 DragBlock 拖拽路径**:
聚焦"滚动摩擦"行 → 拖拽块按住拖动 45px (步长 0.05) → 0.1→2.35 即时写回 →
撤销回 0.1 → 重做回 2.35 (undo/redo 完整协议)。
