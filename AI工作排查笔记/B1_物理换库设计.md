## 0. 结论速览 (TL;DR)

1. **Culverin 0.14.0 可用, 关键未知全部落定**:
   - 接触事件**没有隐藏开关** —— `WorldSettings`(typing-only, 运行时以 dict 传入)无 events 字段; 此前探针报告 0 事件 = 时序伪象: 事件是**每步一次性消费 + 只产生于清醒(Jolt 未睡眠)实体** (probe6 决定性复现: 落体第 33 步精确出现 ADDED, 落定睡眠后归 0, 强制速度唤醒后恢复 PERSISTED)。
   - 类别/掩码 = 文档所述**双向 AND** 语义, 已用 9 组隔离微世界实证 (probe9); 探针 8 号的"异常"是动态-动态推挤被误读为穿透, 实际掩码正确 (动态球会互相推走, 静态目标在 x=3.00 精确挡停)。
   - `save_state/load_state` 可用 (位置/计数恢复), 但 **user_data 不随快照恢复** (probe8: 存 777 读回 0) → 编辑-播放快照方案用**世界重建**而不是 load_state。
   - **零厚度盒 (create_plane 碰撞体) 直接可用** (probe7: 球落定 y=-0.519, slop 0.019); `create_mesh_body` 地板可用 (y=0.486); kinematic 平台 `set_position` 同步每帧 = 有效支撑 (y=0.730, 期望 0.75)。
   - **欧拉约定不匹配**: culverin `MathService.euler_to_quat` = 列向量 Rz@Ry@Rx; 引擎 = 行向量 Rx@Ry@Rz, 同欧拉角差 0.154 范数 (probe10) → 桥必须自带转换器 (设计见 §4)。
   - `USE_DOUBLE_PRECISION=1`: positions 是 f64!(N,4) [x,y,z,0]; rotations/velocities/angular 都是 f32 (N,4); user_data u64 (N,) (probe8)。
   - `WorldSettings` **运行时不可导入** (`.pyi` 有、`__init__` 没有) —— 构造只吃 dict: `PhysicsWorld(settings={'gravity':(0,-9.81,0), ...})`; 合法键 = `validate_settings(_culverin.py:334)`: gravity / penetration_slop(0.02) / max_bodies(10240) / max_pairs / max_contact_constraints / temp_allocator_size(32MB) / max_physics_jobs(≤2048) / max_physics_barriers(≤8) / num_threads(4)。
   - Python >=3.12 无其他依赖 (METADATA); Nuitka 打包 = `_culverin_c.pyd` (3.3MB) + `culverin.libs\msvcp140-<hash>.dll` (delvewheel 改名版 MSVC 运行时, 由 `__init__.py` 的 `os.add_dll_directory` 装载) —— 打包需把 .libs 当数据带进 dist (风险项, 见 §7)。
   - 性能基线 (前探针/2-4 号): 50 球+地面落定后 **2.4µs/步**; 一次性创建 50 体 37ms; 双线程两世界 **1.59x** 加速 (步进释放 GIL ✓)。

2. **关键架构决策 = "混合"**: Jolt 只接管**刚体动力学** (velocity+重力驱动运动、碰撞响应/摩擦/滚动/角速度), 引擎**几何碰撞管线全部保留** (move_with_collision / get_collisions / collider_hit / on_collision_start/end / 同树不互撞 / 编辑-播放快照)。理由: 行为契约测试 (test_collision / test_collision_edges / test_physics / test_scripts_collision / test_playmode_edges) 是语义的机器化定义, 而它们依赖的语义 (静止物重叠也触发事件、静态-静态、严格<贴边、同树仅祖先-后代排除) 与 Jolt 接触事件语义 (仅清醒实体、睡眠静默) **不兼容**; 保留几何路径 = 契约逐位不变 + 现有测试天然兼容 + 风险最小。Jolt 的价值恰好落在自研最弱处 (D8 子步循环纯 Python GIL 内、无摩擦/滚动/角速度/连续检测)。

3. **换库后表现变化 (预期内升级, 须人工验收)**: 动态物体落地/撞墙从"撞停归零"变为 Jolt 接触解算 (法向反弹=restitution 0 默认停住, 切向保留 → 会滑/滚; 盒子会被撞翻、滚动)。这正是 B1 卡标的"表现偏差消除", 但用户可见 → 列入人工实测清单。

4. **分阶段**: P0 调研(已完成本报告前全部) → P1 _perfprobe 沙盒桥原型 → P2 引擎接入(工作区, 单堵点) → P3 行为对齐 → P4 全绿 → P5 用户人工实测 → P6 Nuitka 打包+Vk 冒烟(compile-on-request)。

### 1.2 重力/速度方案 R1 (世界 gravity=0 + 手动累加)
- 为什么要 0: culverin 无 `set_gravity_factor` (pyi 注释掉) → `use_gravity=False` 无法按体关重力。把世界重力设 0, 桥**复刻引擎 update_physics 的累加次序** (use_gravity 才 `v.y += G*dt`), 与引擎逐步行为一致, 且 use_gravity=False 天然精确 (不累加即可)。
- 唤醒策略 R (防 Jolt 睡眠被每帧写速度打碎): 每帧写入速度仅当 (a) 脚本显式改过 rb.velocity (脏检测 vs 上次写出值), 或 (b) Jolt `is_active(handle)` 为真 (清醒中: 累加重力后写回)。睡眠中的体**跳过写** → 保持睡眠 = 性能红利 (2.4µs/步场景成立), 下次被唤醒 (邻居碰撞/位置触碰/脚本写速度) 后自动恢复步进。
- 回读速度直接写 `rb.velocity` (真实解算后速度): 玩家跳跃 (first_person 检查 `abs(rb.velocity.y)<0.01` 再起跳) 语义保持; fall 脚本 (脚本自持 `_vy`, 不走 rb) 不变 ✓。

### 1.3 形状尺寸换算 R3
- 建体时取值 = 引擎 `collider_bounds` 的当帧值: box=(世界 AABB 半长, identity rot); sphere=(世界 AABB 中心, 最大半长)。父链移动自动由 set_position 跟随; **缩放/旋转动画** (animator/脚本连续改 scale/rot) 不会重建形状 → 盒保持出生尺寸 (转/缩后仍挡在该尺寸 OBB 上) —— 级 1 限制, 记录为已知差异 (引擎会逐帧重算 AABB)。若后续需要: 形状变更体 = destroy+rebuild (有句柄抖动, 且仅当 缩放/宽高比变化过阈值)。
- 零厚度平面盒: 直接用 (probe7 ✓); create_mesh_body 备用 (未来 obj/OBB 精确碰撞或碰撞体扩展)。

### 1.4 欧拉/四元数转换 R4 (桥自带, 不用 culverin 的 euler 助手)
- 引擎: 行向量 `v @ (Rx_row @ Ry_row @ Rz_row)`, Rx_row=[[1,0,0],[0,c,s],[0,-s,c]] (engine.py:2204-2218)。
- culverin MathService: 列向量 `Rz@Ry@Rx` (probe10 实证差 0.154)。
- 桥实现 (numpy, 可批量): `euler→矩阵(引擎行主) → 转置为列 → quat` (Shepperd, probe10 已对照 ✓); 回读同理 `quat → 列矩阵 → 行矩阵 → euler(rx,ry,rz) atan2 分解`, 用"单位四元数→引擎矩阵→点旋转与 engine.mat4_rotation 一致"单测锁住。f32/f64 混合: 回读用 f64 计算。
- 性能: 每动态体每帧 ~12 次 sin/cos/atan2 —— 批量 numpy 化 (回读矩阵化向量化), 动态体几十个时 µs 级。

## 2. 事件映射方案

### 2.1 Culverin 事件事实 (probe6, 决定性)
- 无开关。`get_contact_events`(简化 4 元组 h1,h2,impulse,slide) / `_ex`(dict 含 bodies/position/normal/impulse/slide_speed/materials/**type**) / `_raw`(128B 记录, f64 布局因 USE_DOUBLE_PRECISION=1; flags 在偏移 60)。
- **一次性消费**: 三个 getter 任意一个被调, 内部计数即清零 (每个 getter 一次 = 同一批; 调两次第二次为空)。
- **只在 Jolt 实体清醒时产生**: 落体首触 = type 0 (ADDED); 接触续 = 1 (PERSISTED); 分离 = 2 (REMOVED); **睡眠后静默** (落定 240 步后 0 条; 手动赋速唤醒后恢复 PERSISTED)。
- `step(dt)` 才出事件; dt=0 冲刷无事件。

### 2.2 推荐方案 = **混合 A (Jolt 只做模拟, 事件保持引擎几何差分)**
- 保留 `_update_collision_events` 及其内联/并行实现 (A1 已 numpy 化, 费用 ~10-100µs/帧; A3 缓存后不再是热点), 事件语义逐位不变:
  * start=本帧进入重叠 (严格<), end=离开; 与帧序无关节拍 → 静态-静态/睡眠/无刚体重叠/贴边判定全部原样;
  * 只对带脚本物体派发 (改状态串行主线程) 不变;
  * 事件在 `_frame_world` 计算后、矩阵/阴影并列时执行 —— 顺序天然正确 (物理回读发生在 world matrices 之前)。
- 差异审计表 (放弃 Jolt 事件的原因, 若未来切换 pure-Jolt 需解决):

| 语义点 | 引擎几何 | Jolt 接触事件 | 差异 |
|---|---|---|---|
| 静态-静态重叠 (test_physics #4 就是这个场景!) | 触发 | 永不 (无接触对) | 硬不兼容 → hybrid 必需 |
| 无刚体重叠 (纯碰撞体脚本触发) | 触发 | 不触发 (都睡眠) | 硬不兼容 |
| 睡眠临界 (球静置在地) | 保持"还在碰撞" | 静默 (无法区分"还在碰"/"已飞走") | 引擎正确性要求几何 |
| 严格< 贴边判碰撞 | 精确 | 接触有 slop (0.49 也算接触) | 事件帧序漂移 |
| 表亲同树 | 可碰撞 | (滤波后) 不产接触 | 已由 1.1#8 收窄项承担 |
| 提供 impulse/slide_speed (未来 on_collision 附带) | 无 | 有 → 增强点 | 保留 Jolt 事件**只读**通道: 每帧 step 后 `get_contact_events_ex()` 一次性消费, 仅当某脚本订阅了增强字段时才读 (现阶段不读, 防止消费语义干扰未来改造) |

### 2.3 未来可选 pure-Jolt 事件启动条件 (不属本卡)
- 当 N 碰撞体 > 4000 (几何 O(N²) 真瓶颈) 或需要 impulse 数据时; 迁移需先把 test_physics #4 类测例改为"仅动态对"并将 slop/睡眠语义注入引擎契约 —— 单独卡点, 本卡不做。

## 3. 每帧同步设计

### 3.1 帧序 (GL 引擎 render, engine.py:3482-3503)

```
_run_scripts(dt)            # 脚本动 transform / rb.velocity / move_with_collision(几何)
  → bridge.pre_step(dt)     # ① 脏检测: transform 变化的体 → set_position/set_rotation
                            # ② 速度: 策略 R (脚本改过 或 清醒) → set_linear_velocity
                            # ③ 重力: 用 R 且 use_gravity 清醒体: v.y += -9.8*dt
  → bridge.step(dt)         # 一次 C 调用 (命令缓冲冲刷 + 模拟; GIL 释放, 与脚本线程并行)
  → bridge.post_step()      # ④ 批式回读: positions(f64)/rotations(f32)/velocities(f32)
                            #    → numpy reshape → 写 m.position / R4 转换写 m.rotation /
                            #    rb.velocity = 回读线性速度 (真实解算值)
update_audio / update_animations     # 动画在物理后写 transform (下一帧 sync 捕获)
_frame_world = compute_world_matrices
_parallel_shadow_and_collision(with_events=True)   # 几何碰撞事件 = 最终位形 (不变)
_prepare_bucket_frame → 阴影 → 主 pass
```

- 编辑期 (is_playing=False): 桥不活跃 (零开销) —— 现状不变。
- Vk/驱动路径 (scene_driver.step): `_update_scripts → bridge.…→ _update_animations → VP`, 同序 (补物理即可; 驱动无 `_frame_world` 概念, 驱动层几何查询用桥的静态 AABB 助手)。

### 3.2 批式接口 (桥内一个 `np.asarray` 即可, 均零拷贝)
- 回读: `pos = np.asarray(w.positions)` f64 (N*4); `rot = np.asarray(w.rotations)` f32 (N*4) [x,y,z,w]; `vel` f32 (N*4); `angv` f32 (N*4)。按**体在桥内登记顺序**直接映射到模型 (桥持有 `handle→(model-idx)` 表; user_data 也回写登记 id 备用)。
- 写回: 每模型一条 `last_sync (pos,rot,vel)` 缓存, 比较做脏检测 (向量化: 站全局数组 diff, 一次 np 比较; 只对变化体调 set_position)。
- `step(dt=0)` 冲刷: 播放开始/编辑期同步用 (建体后先 step(0) 使宽相位就位, "0 步不模拟"语义正好用于快照边界)。

### 3.3 与 `compute_world_matrices` / `_frame_world` 衔接触点
- `_frame_world` 在物理回读之后计算 → 渲染/阴影/几何事件全部用 Jolt 解算后的位形 (与现状"update_physics 改完 position 再算矩阵"同构) ✓。
- 多核重叠 (8 核均摊, A4=A1 路径): 物理阶段在 `_run_scripts` 后、`_frame_world` 前 → 阴影与碰撞事件并行结构不动 ✓。桥自身不引入线程 (step 内部 Jolt 线程池; `num_threads` 设置见 §7)。

## 6. 风险与开放问题

1. **事件开关=无开关 (已解)**: 但"睡眠即静默"语义 = pure-Jolt 事件不可用于契约 → hybrid (方案已定)。未来若启用 Jolt 事件数据 (impulse 增强), 注意一次性消费 (读一次即清) + 只允许桥单一调用方。
2. **Nuitka 打包 (中风险, 已定位)**: 缺 `culverin.libs\msvcp140-<hash>.dll` (delvewheel 改名运行时) → `add_dll_directory` 指向不存在的目录 (无害) 但 pyd 的改名导入会失败 → `ImportError 0xC0000135`。处置: `--include-package=culverin --include-data-dir=...\culverin.libs=culverin.libs`; P6 打包探针 (nuistka standalone + 启动冒烟) 必做; 备用: 把 DLL 重命名回 msvcp140.dll 放 dist 根 (Nuitka 自带 MSVC 运行时时可撞名)。另: `_verify_cpu_requirements` 检查 AVX2/FMA (Windows 分支跳过, 仅 Linux) —— 不拦。免费线程 (3.13t) 无涉。
3. **Python 3.12 兼容**: ✓ (cp312 轮子, Requires-Python>=3.12, 3.12-3.15 分类器; 引擎/Nuitka 链均 3.12)。
4. **性能索债项**: ① 唤醒策略 R 需实测 (每帧写速度会防睡 → `is_active` 门控后应在几十-几百 µs/帧); ② `num_threads` 默认 4 → Jolt 自线程池 + 渲染主核占用, 建议 bridge 设置 `num_threads = max(1, 逻辑核-2)` (8 核 → 6) 并复测 (注意 E 核调度: Jolt 线程未 pin, 交给 OS; 性能验收按真实压测场景)。③ 创建成本 37ms/50 体 (播放开始一次性, 可接受; 超 300 体时用 `create_bodies_batch` 快建? —— batch 无 category/mask 参数, 桥内后补 `set_collision_filter`, P1 测)。
5. **欧拉约定 (已解)**: 桥自带 R4 转换; 单测锁约定 (与 engine.mat4_rotation 对齐), 防"球转了但盒子轴错位"。
6. **shape 尺寸冻结 (R3) 级 1 限制**: 缩放/旋转动画中 box 不重建 = 静止尺寸 OBB 会与"当帧 AABB"偏差 (视觉角: 长条旋转 90° 时实体宽高交换感); 处置: 已知差异 + "严重时才重建"开关; 属表现性, 人工验收时特别看录制/滚动动画场景。
7. **>31 根树**: 收窄/回退方案 (轮转+警告); 真实场景根数 < 31 概率高; 若 P5 实测有场景超限 → 提供"全默认 (全互撞)"降级选项或树合并器。
8. **动态-动态推挤语义变更**: 旧版"谁动谁被挡死", Jolt "互相推/滚"。这是能力升级但会改变已有玩法 (推箱子=新玩法; 压球罩=都塌)。**人工实测重点**。
9. **用户数据/句柄**: save/load 不恢复 user_data (实测) → 若未来主存档用 load_state: 需按回读 pos 顺序重映模型 (或把映射存在快照外); 本卡用"重建"规避。
10. **默认 category/mask=0xFFFF 陷阱**: 树位 ≥16 时默认掩码不与之碰撞 → 桥内所有体显式传 category/mask (设计已强制); 编辑器探针/外部脚本若直接用 cv 建体不受引擎管理, 不保证 (文档化)。
11. **游戏包/玩家运行时**: 打包后的 MyGame.exe 玩家链 (game_player) 走 PlayerApp → 若 exe 无 culverin → 静默回退 legacy (物理=旧表现) 或启动报错提示 → 建议: 无库时 Up-Info 提示"需 culverin 0.14.0", 不静默 (防"发布链偷偷降级")。
