--------------------------------------------------------------------
【测试规则 · 测前必读】(后续测试人员照此执行, AI 改本文件也照此约束)
--------------------------------------------------------------------
规则 A —— 无法自动化 (需人工实测的功能), 标记写【a,b】
  a = 人工实测: 0 = 还没人工测过 / 1 = 人工测过, 没发现问题或问题已修好。
      ★只能人改。AI 禁止动 a。
  b = 代码改动: 0 = 测完后代码没动过 / 1 = 代码有改动, 需要重新测。
      AI 改过相关代码后, 必须把 b 从 0 改成 1 (提醒重测)。
      ★AI 禁止把 b 改回 0; 只有人重测确认没问题后, 才手动把 b 改回 0。

规则 B —— 可自动化 (能自动化测试的功能), 标记写【a,b】
  a = 自动化测试: 0 = 没自动测 / 1 = 自动测过并通过。
      ★AI 全权管理: AI 跑自动测试通过后设 1, 代码改动后重跑, 不通过设回 0。
      人一般不用管 a。
  b = 人工实测: 0 = 还没人工实测 / 1 = 人工实测过, 没问题或已修好。
      AI 改过相关代码后, 必须把 b 改成 0 (代码动了, 之前的人工实测作废, 需重测)。
      ★AI 禁止把 b 改成 1; 只有人实测确认没问题后, 才手动把 b 改成 1。

一句话记: 无法自动化"人工"在前、代码改动 AI 只能 0→1;
          可自动化"自动化"AI 全管,"人工"AI 只能 1→0。
规则一致: 任何标记的"1"里含"人工确认没问题"含义的, 都由人最终确认。
规则 C (2026-08-30 用户定): **涉及动态过程的画面显示测试全部人工进行** ——
  物理运动 (落体/弹跳/滑墙/滚动/角色移动手感)、动画播放、异步过程画面/音频
  播放类, 一律列入"无法自动化"人工实测项【a=人工,b=代码改动】; 自动化探针
  只允许测数值/接口 (如落定高度、碰撞事件次数、音量 API), 不得用自动截图
  判定"画面显示是否正常"。
